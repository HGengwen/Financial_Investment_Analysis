## 1. 背景与问题

第一阶段（代码列表缓存）完成后，三市场的**财务与筛选类工具仍每次裸调 API**：

| 工具 | 重复调用 | 数据特性 | 限流风险 |
|---|---|---|---|
| `tools/hk_stock/stock_screen.py` | **一次筛选调 4 个接口**：`ak.stock_financial_hk_analysis_indicator_em`（财务指标）+ `ak.stock_financial_hk_report_em`（利润表/资产负债表/现金流量表） | 年度/季度慢变，一年最多更新 4 次 | **最高** |
| `tools/hk_stock/stock_financial.py` | `ak.stock_financial_hk_analysis_indicator_em(symbol, indicator)` | 同上 | 高 |
| `tools/us_stock/stock_financial.py` | `yf.Ticker` 三大报表（income_stmt/balance_sheet/cashflow）、分红拆股历史 | 季度慢变；分红历史几乎不变 | 高（yfinance 429） |
| `tools/a_share/stock_screen.py` | **一次筛选调 3 个接口**：`ak.stock_ipo_info`（112 行，IPO 信息）+ `ak.stock_financial_report_sina`（388 行，利润表）+ `ak.stock_financial_abstract`（594 行，财务摘要） | IPO 信息**永不变**；利润表历史年度永不变；摘要季度慢变 | **最高** |
| `tools/a_share/stock_financial.py` | `ak.stock_financial_abstract(symbol)`（83 行，与 screen 重复调用同一接口） | 季度慢变 | 高 |

**典型受害场景**：投资团队技能（4 Agent 并行研究同一只股票）各跑一次 `stock_screen`：
- 港股：4 × 4 = 16 次重复 API 调用，其中 12 次纯浪费；
- A 股：4 × 3 = 12 次重复 API 调用，其中 9 次纯浪费；
财务数据季度才更新，同日多 Agent 重复拉取全为浪费。

## 2. 目标

1. 港股财务指标与三大报表、美股三大报表与分红拆股历史、A 股 IPO 信息/财务摘要/利润表实现本地缓存；
2. 港股/A 股 `stock_screen` 第二次调用起分别从 4/3 次 API 降为 **0 次**；
3. yfinance 限流（HTTP 429）时美股报表从缓存降级返回，不中断研究流程；
4. 沿用已验证的缓存模式（TTL + miss 双触发、原子写、stale 降级），零新模式引入。

## 3. 设计原则（沿用第一阶段已验证模式）

- **扩展现有模块，不新建文件**：港股财务缓存并入 `hk_stock_cache.py`，美股财务缓存并入 `us_stock_cache.py`，A 股财务缓存并入 `a_stock_cache.py`；
- **按股票分文件**：避免大文件全量读写，单股 upsert 简单，天然支持并行 Agent 各查各股；
- **TTL + miss 双触发刷新**：缓存新鲜直接读本地（hit）；过期/缺失拉取并原子覆写（refresh）；刷新失败返回旧缓存（stale），无缓存才抛错；
- **格式适配数据形态**：港股财务（akshare 返回 DataFrame）→ CSV（utf-8-sig）；美股报表（嵌套 dict：年报+季报）→ JSON（保留原始键名）；
- **不缓存的数据**：机构持仓、分析师评级（随时变化）、K线/指数（用户确认排除）。

## 4. 港股财务缓存设计（hk_stock_cache.py 扩展）

### 4.1 新增公开函数

```python
get_financial_indicators(code: str, indicator: str = "年度") -> pd.DataFrame
    # 封装 ak.stock_financial_hk_analysis_indicator_em(symbol, indicator)
    # ROE、毛利率、净利率等财务分析指标

get_financial_report(code: str, report_type: str, indicator: str) -> pd.DataFrame
    # 封装 ak.stock_financial_hk_report_em(stock, symbol=report_type, indicator)
    # report_type: "利润表" / "资产负债表" / "现金流量表"
```

### 4.2 缓存文件布局

```
data/hk_stock/financial/
    00700_年度_indicators.csv      # 财务指标
    00700_利润表_年度.csv           # 三大报表（各一文件）
    00700_资产负债表_年度.csv
    00700_现金流量表_年度.csv
    00700_年度_indicators.meta     # 元数据：拉取时间、状态（用于 TTL 判定与 stale 标注）
```

> TTL 判定沿用 mtime 方案（与代码列表缓存一致），**不引入 .meta 文件**，仅以 mtime 判断新鲜度，保持零额外状态文件。上表 .meta 行仅示意，实施时省略。

### 4.3 TTL 配置

- `.env` 新增 `HK_FINANCIAL_TTL_DAYS`，默认 **7 天**；
- 依据：财报一年最多披露 4 次，7 天保证披露后最迟一周自愈，且同周内多 Agent 复用；
- 刷新失败（东财接口断连）→ 返回旧缓存（`stale`），东财港股接口不稳定是已知问题（项目记忆），降级路径必须有测试覆盖。

### 4.4 内部实现要点

- 拉取 → `_atomic_write_csv`（.tmp + os.replace）→ 返回 DataFrame；
- 读取：`pd.read_csv` 失败视为缓存损坏 → 触发刷新并覆写（自愈）；
- 返回值附带状态查询函数 `get_financial_status() -> str`（hit/refresh/stale），供调用方写入 `meta.cache`。

## 5. 美股财务缓存设计（us_stock_cache.py 扩展）

```python
    # 返回结构（沿用 stock_financial.py 现有输出结构，含年报+季报）

    # 封装 stock.dividends / stock.splits
```

### 5.2 缓存文件布局

```
data/us_stock/financial/
    AAPL_statements.json    # 三大报表（嵌套 dict，JSON 保留原始结构）
    AAPL_dividends.json     # 分红拆股历史
```

### 5.3 TTL 配置

| 数据 | 环境变量 | 默认 TTL | 依据 |
|---|---|---|---|
| 三大报表 | `US_FINANCIAL_TTL_DAYS` | 7 天 | 季报披露节奏 |
| 分红拆股历史 | `US_DIVIDENDS_TTL_DAYS` | 30 天 | 历史数据几乎不变 |

- yfinance 429/断连时返回旧缓存（stale），与 `--realtime` 慢变字段降级同模式；
- JSON 读写均为原子写（.tmp + os.replace）；解析失败视为损坏 → 刷新自愈。

### 5.4 不纳入缓存

- 机构持仓（`institutional_holders`）：季度 13F 披露但调用频次低、体积小，缓存收益低，暂不缓存；
- 分析师评级：随时变化，不缓存；
- K线/指数（stock_quote.py）：用户确认排除，保持实时。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 东财港股接口不稳定导致缓存刷新失败 | stale 降级返回旧缓存（有测试覆盖），接口恢复后下次查询自愈 |
| akshare `RemoteDisconnected`（A 股封禁信号） | 立即放弃重试 + stale 降级（项目记忆约束），避免加剧封禁 |
| 港股/A 股财报披露后缓存最长 7 天滞后 | 可接受：筛选场景关注年度趋势；紧急时人工删缓存文件或等 TTL |
| yfinance 429 高发时段报表不可拉取 | 报表缓存 stale 降级，研究流程不中断 |
| 并行 Agent 同时触发同一股票缓存刷新 | 原子写保证缓存文件不损坏；最坏情况重复拉取一次，无数据风险 |
| 美股 JSON 缓存与 yfinance 输出结构漂移 | 读取时按键容错（缺键置 None），不做严格 schema 校验 |
