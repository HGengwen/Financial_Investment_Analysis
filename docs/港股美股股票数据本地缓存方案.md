# 港股/美股股票数据本地缓存方案

> 状态：待确认（2026-08-15）
> 目标文件：`tools/common/hk_stock_cache.py`（新建）、`tools/common/us_stock_cache.py`（新建）、`tools/hk_stock/stock_info.py`、`tools/us_stock/stock_info.py`
> 参考实现：`tools/common/a_stock_cache.py`（A股，已实施，见《A股股票数据本地缓存方案》）

---

## 1. 背景与问题

A股工具已实施本地缓存（`data/a_share/` CSV + `tools/common/a_stock_cache.py`），
消除了每次查询全量拉取 akshare 的低效与限流风险。本方案将类似优化推广至
港股与美股工具，但**两个市场的问题性质完全不同**。

### 1.1 港股 `tools/hk_stock/stock_info.py` — 问题比 A 股更严重

| # | 发现 | 严重度 |
|---|---|---|
| 1 | **N+1 调用灾难**：`cmd_search` 先调 `get_all_hk_stocks()` 拉一次全量 spot（约 2600 只），然后**每个匹配结果**再调 `get_hk_stock_info(code)`，每次又拉一次全量 spot。搜"中国"匹配 40+ 条 → **40+ 次全量拉取** | 极高 |
| 2 | `--code` 查单只股票也是拉全市场 spot 再筛选一行 | 高 |
| 3 | spot 数据混合性：每行既有代码/名称（慢变，适合长期缓存）又有行情价格（快变，不可长期缓存） | 设计难点 |
| 4 | 兜底硬编码列表（43 只）数据质量差：`00241` 标注"阿里巴巴-SW"错误（09988 才是）、`00688` 标注"中国海外发展"错误（00688 为中兴通讯）、`06690` 标注"海尔智家"错误 | 中 |
| 5 | `--hot` 热度榜为实时人气数据，不适合长 TTL 缓存 | 低 |

### 1.2 美股 `tools/us_stock/stock_info.py` — 痛点与 A 股完全不同

| # | 发现 | 影响 |
|---|---|---|
| 1 | 无 `--list`/`--search` 功能，仅 `--realtime` 单只查询，"名称查代码"场景不存在 | 与港股无可比性 |
| 2 | `yf.Ticker(symbol).info` 为单只查询，**不存在全量拉取浪费** | 缓存收益性质不同 |
| 3 | Yahoo/yfinance 限流比 akshare 更凶（HTTP 429 封禁常见）；info 中慢变字段（PE/PB/ROE/Beta/52周高低/市值/股息率）与快变字段（价格/成交量）混在同一响应 | 缓存需拆分 |
| 4 | yfinance 无全市场列表接口 | 通过 **NASDAQ Trader 官方文件**（nasdaqlisted.txt + otherlisted.txt，约 11000 只）获取列表，官网优先、镜像回退 |

**关键约束**：`yf.Ticker.info` 是单次请求返回全部字段，无法只取价格不取估值。
因此美股缓存**无法降低 info 调用频率**（实时价格仍需每次调用 info），其核心
价值是 **429/断连时的降级兜底** —— 限流发生时估值指标仍可从本地缓存返回。

## 2. 已确认的设计决策

| 决策项 | 结论 |
|---|---|
| 港股 N+1 修复 | **一并修复**：搜索改为一次 spot 拉取提取全部匹配行情 |
| 港股缓存拆分 | **列表缓存 7 天 + 行情单次拉取**（保持行情实时性） |
| 美股改造方向 | **列表获取 + 慢变字段缓存**：通过 NASDAQ Trader 官方文件（nasdaqlisted.txt + otherlisted.txt，官网优先、镜像回退）建立本地代码/名称列表；慢变字段缓存 1 天防 429 降级兜底 |
| 模块组织 | **独立缓存模块**：hk_stock_cache.py / us_stock_cache.py，缓存放 data/hk_stock/、data/us_stock/ |

### 3.1 新建 `tools/common/hk_stock_cache.py`

**数据源设计（双源回退，与美股三级回退对齐）**：

| 3（兜底） | 硬编码列表 | 内置 43 只主要港股 | 最后兜底（顺带修正 3 处代码/名称错误） |

```python
get_hk_spot_dataframe() -> pd.DataFrame
```

### 3.2 stock_info.py 流程重写

| 命令 | 现状 | 改造后 |
|---|---|---|
| `--list` | 每次拉全量 spot | 读缓存（7 天 TTL），miss/过期才刷新 |
| `--search 关键词` | 1 + N 次全量 spot（N=匹配数） | 缓存列表**中英文名称双匹配**关键词 → **一次** spot 拉取 → 提取全部匹配股票的行情（1 次或 0 次 API） |
| `--code 00700` | 拉全量 spot 筛一行 | 名称从缓存列表取，行情一次 spot 提取（保持 1 次，消除冗余字段处理） |
| `--hot` | 实时拉取 | 不缓存，保持现状 |

- **兜底顺序**：本地缓存 > akshare API > 硬编码列表（最后兜底，顺带修正
  硬编码列表中的 3 处代码/名称错误）。
- meta 增加 `cache` 字段（hit / refresh / stale），与 A 股一致。
- 新增 `--refresh` 参数：强制刷新港股列表缓存。

### 3.3 修复收益量化

搜"中国"（约 40 条匹配）：从 **41 次全量 spot** → **1 次**；
列表命中时（缓存 7 天内）：→ **1 次**（仅行情）。

## 4. 美股方案

### 4.1 数据源：NASDAQ Trader 官方文件（双模式：官网优先、镜像回退）

| 优先级 | 数据源 | 文件/接口 | 说明 |
|---|---|---|---|
| 1（主源） | NASDAQ Trader 官网 | `https://www.nasdaqtrader.com/dynamic/SymDir/nasdaqlisted.txt`<br>`https://www.nasdaqtrader.com/dynamic/SymDir/otherlisted.txt` | 管道分隔文本，合计约 11000 只；国内直连不稳定 |
| 2（备源） | NASDAQ 官方 screener API | `https://api.nasdaq.com/api/screener/stocks?tableonly=true&limit=25&download=true` | JSON 格式（symbol/name/lastsale/sector 等），官方域名不同，可达性与主源互补 |
| 3（自定义镜像） | `.env` 配置 | `US_TICKER_MIRROR_URLS`（逗号分隔） | 用户可按自身网络环境配置镜像 URL（如自建反代、GitHub raw 镜像仓库等），逐个尝试 |

下载策略：按优先级逐源尝试（`requests.get(timeout=15)`），任一源成功即停止；
全部失败时降级返回旧缓存（stale），无缓存抛 `RuntimeError`。

**解析规则**（管道文件）：
- 表头为第一行（`Symbol|Security Name|...`），末行为文件创建时间戳行
  （`File Creation Time: ...`），按"列数与表头不符"过滤，不依赖 `-1` 下标；
- **过滤测试股**：`Test Issue == "Y"` 的行丢弃；
- **保留 ETF 标志**：`ETF` 列原样保留（不过滤，查询端自行判断）；
- **交易所映射**：nasdaqlisted 固定 `NASDAQ`；otherlisted 按 `Exchange` 列映射
  （`N`=NYSE, `A`=NYSE American, `P`=NYSE Arca, `Z`=BATS, `V`=IEXG）；
- **yfinance 符号兼容**：原始 ACT Symbol 中特殊股类含点号（如 `BRK.B`），另生成
  `yf_symbol` 列（点号替换为连字符 `BRK-B`，yfinance 格式），原始符号保留。

### 4.2 新建 `tools/common/us_stock_cache.py`

```python
get_us_code_name_list(force_refresh: bool = False) -> list[dict]
```

`requests` 依赖处理：与 `fx_rate.py` 相同的顶层 `try-except` 优雅降级模式。

### 4.3 stock_info.py 新增命令

| 命令 | 行为 | API 调用 |
|---|---|---|
| `--list` | 列出全部美股代码/名称/交易所 | 缓存命中零 API；过期拉一次列表文件 |
| `--search 关键词` | 按名称关键词搜索（不区分大小写） | 同上（列表纯本地匹配） |
| `--code AAPL` | 查询单只代码→名称/交易所 | 同上；miss 时强制刷新一次再查 |
| `--realtime AAPL` | 实时行情与估值指标（原有功能） | 每次实时调用 info（见 4.4） |
| `--refresh` | 强制刷新列表缓存 | 拉一次列表文件 |

meta 增加 `cache` 字段（hit / refresh / stale），与 A 股/港股一致。

### 4.4 字段拆分与 `--realtime` 降级

| 类别 | 字段 | 处理 |
|---|---|---|
| 慢变（缓存 1 天） | 公司名称、市值、流通股本、总股本、PE(TTM)、PB、股息率、Beta、ROE、ROA、52周最高/最低 | `data/us_stock/symbol_info.csv`（多 symbol 单文件，按 symbol 列索引） |
| 快变（实时） | 当前价格、开盘价、最高价、最低价、昨收、成交量 | 每次实时拉取 info |

```
正常路径：调 yf.Ticker(symbol).info（实时全量）→ 输出 → 顺带刷新慢变字段缓存
降级路径：info 调用失败（429/断连，重试 3 次后）→ 从缓存取慢变字段拼装输出
          → 价格字段为 null → meta.cache = "stale" + 附降级提示
```

- **诚实声明**：`yf.Ticker.info` 为单次请求返回全部字段，无法只取价格不取估值，
  因此慢变缓存**不减少 info 调用次数**，价值是限流时估值查询仍可用。

## 6. 风险与权衡

- **港股行情不缓存** —— `--code`/`--search` 仍每次拉一次 spot 换取行情实时性
  （spot 单次约 2600 行，但一天内多次查询仍各拉一次；如后续需要可加短 TTL，
  本次按决策不做）；
- **美股慢变缓存不省 API 调用** —— 仅提供 429 降级；若未来要零 API 估值查询，
  需新增"容忍陈旧价格"模式（本次不做，避免过度设计）；
- **nasdaqtrader.com 国内可达性不稳定** —— 已按"官网 → 备源 → 自定义镜像"
  三级回退设计；镜像 URL 的实际可用性需在实施时真实验证，默认给 api.nasdaq.com
  备源 + `.env` 自定义入口，用户可按网络环境自行替换；
- **列表文件尾部时间戳行** —— 解析按列数校验过滤，不依赖文件恰好以时间戳行
  结尾（比参考代码 `lines[1:-1]` 更稳）；
- **美股列表不含退市股** —— NASDAQ Trader 文件仅含当前上市标的（与 A 股列表
  接口行为一致）；
- **港股缓存 7 天内退市/改名不自愈** —— 与 A 股方案一致的已确认权衡；
- **东方财富港股接口（stock_hk_spot_em）当前不可用** —— 2026-08-15 实测
  `RemoteDisconnected`（服务端拒绝连接），印证项目记忆记载；方案将其定位为
  备源而非主源（新浪主源实测稳定，2797 只），网络恢复时自动互补；
- **spot 列与列名变动风险** —— `get_hk_stock_info` 已有多字段名动态适配逻辑，
  迁移时保留。
