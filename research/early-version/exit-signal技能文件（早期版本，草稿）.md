## 技能元数据

```yaml
name: exit-signal
version: 1.0.0
description: >
  卖出信号触发系统——P0~P5 六级优先级检查。
  将理念文档"决策优先级金字塔"映射为硬编码检查顺序，
  输出"持有/减仓/清仓"的明确决策信号。
  不允许 AI 自由裁量绕过或降级高优先级信号。
triggers:
  - 卖出信号
  - 止损检查
  - 持仓风控
  - 退出信号
  - exit-signal
disable-model-invocation: true
```

## 一、设计理念

在1~3年的中长期投资中，**卖出纪律比买入决策更重要**。本技能融合四位大师的卖出思想，建立强制优先级检查机制。

### 1.1 四位大师在卖出层面的贡献

| 大师 | 卖出层面的贡献 | 在本技能中的体现 |
|------|---------------|-----------------|
| **李进** | 管理层诚信一票否决 | **P0**：治理一票否决，立即清仓 |
| **欧奈尔** | 8%~10%硬止损，绝不等"反弹" | **P1**：硬止损，无条件执行 |
| **林奇+郑希** | 增速放缓/逻辑改变即卖出；满4季度未兑现即替换 | **P2**：逻辑止损（含时间止损） |
| **李进+郑希** | 渗透率减速/ROE拐头即减仓 | **P3**：产业景气拐点 |
| **林奇** | PEG>1.5减机动仓，PEG>2清机动仓 | **P4**：估值透支 |
| **机会成本** | 发现更优标的可替换 | **P5**：性价比替换 |

### 1.2 决策优先级金字塔（P0~P5 六级，对齐开发方案 v3.3 第 2.5 节 + 第 6.6 节）

| 级别 | 触发条件 | 决策 | 思想来源 |
|------|----------|------|----------|
| **P0 治理一票否决** | 管理层失信、财务造假实锤、监管立案 | **立即清仓**，不看估值趋势 | 李进（治理评估） |
| **P1 硬止损** | 单笔亏损8%~10%，且无基本面反转信号 | **无条件止损** | 欧奈尔 |
| **P2 逻辑止损** | 连续2季业绩低于预期且产业景气未改善；**或持有满4季度逻辑未兑现（时间止损）** | **减仓或清仓** | 林奇+郑希 |
| **P3 产业景气拐点** | 渗透率减速（二阶导转负）/ ROE拐头向下 | **减机动仓** | 李进+郑希 |
| **P4 估值透支** | PEG>1.5（减机动仓）；PEG>2.0（加速清机动仓） | **减/清机动仓** | 林奇 |
| **P5 性价比替换** | 其他标的PEG显著更低且产业趋势更强 | **调仓**（每季度最多1次） | 机会成本 |

**执行逻辑**：从 P0 到 P5 依次检查，**高优先级触发即停止后续检查**，直接输出对应信号。

### 1.3 核心原则

> **先保命（止损/防造假），再谈收益（景气/估值）。**
> 欧奈尔的底线规则优先于林奇的乐观逆向，郑希/李进的产业判断优先于短期的估值噪音。

### 1.4 四大矛盾在本技能中的化解要点

| 矛盾 | 化解方案 | 在本技能中的体现 |
|------|----------|-----------------|
| **止损 vs 越跌越买** | 引入"仓位状态"：建仓初期（<最终仓位50%）止损优先；底仓已立且三维度（产业/管理层/财务）均未恶化时，才在估值下限加仓；逻辑证伪立即清仓 | P1 止损比例按仓位状态区分（8%/10%） |
| **单季噪音 vs 趋势拐点** | 以**连续3个季度数据趋势**区分波动与拐点 | P2 要求"连续2季"低于预期，而非单季 |
| **长期持有 vs 中期兑现** | 满4季度逻辑未兑现触发时间止损 | P2 包含时间止损子项 |
| **买点哲学对立（左侧 vs 右侧）** | 左侧布局仅适用于"杀估值"而非"杀逻辑"。杀估值可逆向，杀逻辑必须止损 | P1 的10%临界点处理规则 |

## 二、输入参数

### 2.1 参数定义

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `{标的}` | 字符串 | 是 | 无 | 公司名称或股票代码（支持A股/港股/美股） |
| `--buy-date` | 日期 | 条件 | 无 | 买入日期（YYYY-MM-DD），用于计算持有期。若未提供，尝试从 `thesis-tracker --horizon mid` 论文读取 |
| `--buy-price` | 浮点数 | 条件 | 无 | 买入价格，用于计算欧奈尔止损。若未提供，尝试从论文读取 |
| `--hold-quarters` | 整数 | 否 | 4 | 时间止损触发阈值（持有季度数），默认4个季度（1年） |
| `--horizon` | 字符串 | 否 | mid | 投资周期：`mid`（1~3年，当前技能唯一支持模式） |
| `--check-mode` | 字符串 | 否 | daily | 检查模式：`daily`（每日，监控P0/P1/P3）/ `quarterly`（季度，完整P0~P5检查） |
| `--export` | 标志 | 否 | false | 是否导出Markdown报告 |
| `--export-path` | 字符串 | 否 | reports/exit-signals/ | 报告输出路径 |
| `--json` | 标志 | 否 | false | 是否以JSON格式输出 |

**批量模式**：支持逗号分隔多个标的，如 `exit-signal 中际旭创,新易盛,天孚通信`

### 2.2 参数依赖说明

| 场景 | 参数提供方式 |
|------|-------------|
| 有 `thesis-tracker --horizon mid` 论文 | 自动从 `reports/{公司名}/{公司名}-mid-thesis.md` 中解析买入日期、买入价格、买入逻辑、建仓时PEG |
| 无论文或论文不完整 | 必须通过 `--buy-date` 和 `--buy-price` 手动提供 |
| 两者均无法提供 | 跳过 P1（止损）、P2（时间止损子项）和 P5（逻辑漂移），输出"数据不足"标记 |

## 三、执行流程

### 第一步：获取持仓上下文信息

#### 1.1 尝试从 thesis-tracker 论文读取买入信息

**读取路径**：`reports/{公司名}/{公司名}-mid-thesis.md`

**解析目标**：
- 买入日期（`buy_date`）
- 买入价格（`buy_price`）
- 买入逻辑摘要（用于 P2/P5 逻辑漂移对比基准）
- 建仓时PEG（用于 P4 估值透支对比基准）
- 目标仓位比例（用于 P1 判断"仓位状态"）

#### 1.2 手动参数覆盖

若 `--buy-date` 或 `--buy-price` 在命令行提供，**优先使用命令行参数**（覆盖论文读取值）。

#### 1.3 获取当前行情与财务数据

| 数据项 | 用途 | 工具/技能 |
|--------|------|----------|
| 当前价 | P1硬止损、P3技术面辅助 | `stock_quote.py --code {code} --momentum --auto-peers` |
| MA50/MA200 | P3技术面辅助判断 | `stock_quote.py`（从日线序列计算） |
| 近期成交量 | P3辅助判断（放量破位） | `stock_quote.py` |
| TTM EPS / 当前PE | P4估值透支（计算PEG） | `stock_financial.py --indicator ROE,毛利率,营业总收入,归母净利润` |
| 合同负债/存货/研发费用 | P2业绩验证、P5逻辑漂移 | `stock_financial.py --advanced` |
| 当前PEG / PE分位 | P4估值透支 | `valuation-thermometer`（内置调用） |
| 市值隐含业绩 | P4交叉验证 | `financial_rigor.py implied-growth` |

---

### 第二步：P0 优先级检查——治理一票否决（管理层失信/财务造假）

**检查内容**（对齐理念文档 V2.0 第二部分"管理层评估清单"维度A）：

| 检查项 | 数据来源 | 触发条件 | 信号 |
|--------|----------|----------|------|
| 监管记录 | `anysearch.py --tag legal`、`doubao_search.py --finance` | 近3年有违规、问询函、警示函记录（财务造假相关为一票否决） | **立即清仓** |
| 财务造假 | `stock_financial.py` 交叉验证 | 营收与经营性现金流严重背离（现金流/营收<0.5连续2季）；利润与行业趋势严重不符 | **立即清仓** |
| 业绩预告 | 近5次预告与实际偏差 | 频繁大幅修正（偏差>20%）且方向向下 | **立即清仓** |
| 归因习惯 | 年报"经营情况讨论"文本分析 | 习惯性将未达目标归咎于宏观/政策/疫情，从不自省 | **立即清仓** |
| 大股东质押率 | 公告/交易所数据 | 大股东质押比例>50%且持续攀升 | **一票否决预警** |

**执行方式**：

```bash
# 1. 查询监管记录与负面新闻
python tools/common/anysearch.py "{公司名} 监管 警示函 问询函" --tag legal
python tools/common/doubao_search.py "{公司名} 财务造假 违规" --finance

# 2. 获取最新财报验证营收与现金流匹配度
python tools/a_share/stock_financial.py --code {code} --indicator 营业收入,经营活动现金流净额

# 3. 若任何一项触发，立即输出"清仓"信号，停止后续所有检查
```

**P0 触发输出格式**：

```json
{
  "priority": "P0",
  "signal": "清仓",
  "reason": "治理一票否决——管理层诚信问题暴露/财务造假实锤/监管立案",
  "detail": "具体检查项和证据",
  "action": "无论当前盈亏，立即清仓，不考虑估值和趋势"
}
```

> **硬编码规则**：P0 触发后，**禁止**输出"再观察一个季度""估值便宜可继续持有"等弱化建议。必须输出"立即清仓"。

### 第三步：P1 优先级检查——欧奈尔8%~10%硬止损

#### 3.1 触发条件

```
当前价 ≤ 买入价 × (1 - 止损比例)
```

#### 3.2 止损比例取值规则（融合"矛盾三：止损 vs 越跌越买"化解方案）

| 仓位状态 | 止损比例 | 说明 |
|----------|----------|------|
| 建仓初期（持仓 < 目标仓位的50%） | **8%** | 严格执行，保护本金 |
| 底仓已建立且逻辑已验证（持仓 ≥ 目标仓位的50%） | **10%** | 给予更多容忍空间 |
| 波动性大的标的（如科技成长股） | **10%** | 避免噪音触发 |

#### 3.3 执行规则

| 条件 | 决策 | 备注 |
|------|------|------|
| 触发止损 + 无明确基本面反转信号 | **无条件清仓** | 忘掉买入成本，不以"已经跌了这么多"为借口 |
| 触发止损 + 有明确基本面反转信号（产业景气/管理层/财务三维度均未恶化） | **暂不清仓，降级至观察仓** | 需在报告中详细说明反转信号证据 |
| 未触发止损 | 继续下一优先级检查 | — |

#### 3.4 10%临界点处理（融合理念文档矛盾三化解方案）

10%同时落在硬止损上限与"越跌越买"加仓区间下沿。触及该点时先做止损复核——仅当**产业逻辑、管理层、财务**三维度均未恶化、且属已建立的底仓逻辑仓位时，才允许在合理估值下限附近加仓；否则一律退出，不得"越跌越买"。

> **核心原则**：**欧奈尔的规则优先于林奇的乐观。** 先活下来，再谈收益。底仓未建立前，止损是第一位的；底仓建立后且逻辑充分验证，才考虑逆向加仓。

**P1 触发输出格式**：

```json
{
  "priority": "P1",
  "signal": "清仓",
  "reason": "欧奈尔硬止损触发（亏损 {loss_pct}%）",
  "buy_price": 85.20,
  "current_price": 78.00,
  "stop_loss_threshold": 78.38,
  "position_status": "建仓初期",
  "action": "无条件清仓，不考虑估值和基本面"
}
```

> **硬编码规则**：P1 触发后，**禁止**输出"考虑到估值便宜，暂不止损"等弱化建议。必须输出"无条件清仓"。

---

### 第四步：P2 优先级检查——逻辑止损（基本面逻辑破坏 / 时间止损）

> **修订说明**：草稿 V0.0.1 将"技术面破位"定义为 P2、"时间止损"定义为 P3。开发方案 v3.3（第 6.6 节 F-5）明确要求将"连续2季低于预期"与"时间止损（满4季度未兑现）"**合并为 P2**，技术面信息降为 P3 的辅助判断指标。

#### 4.1 子项A：连续2个季度业绩低于预期

**检查维度**：

| 维度 | 判断标准 | 数据来源 |
|------|----------|----------|
| 营收增速 | 连续2个季度低于买入时预期增速的50% | `stock_financial.py` 单季度营收 |
| 扣非净利润 | 连续2个季度增速放缓或为负 | `stock_financial.py` 单季度扣非净利润 |
| 合同负债/订单 | 合同负债环比连续2季下降>10% | `stock_financial.py --advanced` |
| 产业景气交叉 | 所在行业景气度同步下行 | `mid-industry-research` 输出 |

**连续3季度趋势判定**（融合"矛盾二"化解方案）：

| 趋势 | 判定 | 操作 |
|------|------|------|
| 连续3个季度加速 | 景气向上 | 不触发 |
| 单季度放缓 + 全年预期不变 + 产业渗透率仍<40% | 短期波动 | 不触发，仅调整机动仓 |
| 连续2~3个季度减速 + 订单增速同步放缓 + 行业竞争加剧 | 趋势性拐点 | **触发 P2** |

#### 4.2 子项B：时间止损（持有满4个季度逻辑未兑现）

**"买入逻辑未兑现"的判断标准**：

| 维度 | 判断标准 | 数据来源 |
|------|----------|----------|
| 订单 | 合同负债/在手订单未显著增长 | `stock_financial.py --advanced` |
| 收入 | 季度营收增速 < 买入时预期增速的50% | `stock_financial.py` 单季度营收 |
| 利润 | 扣非净利润未增长或为负 | `stock_financial.py` 单季度扣非净利润 |

**执行规则**：

| 条件 | 决策 | 备注 |
|------|------|------|
| 满4季度 + 完全未兑现（订单/收入/利润均无实质改善） | **减仓至观察仓（原仓位的30%~50%）** | 替换为性价比更高的标的 |
| 满4季度 + 部分兑现（部分指标改善但未达预期） | **给予"缓刑"1个季度** | 下季度再未兑现则执行减仓 |
| 满4季度 + 逻辑已兑现 | 继续持有，重置时间止损计数器 | 论文更新 |
| 连续2季业绩低于预期 + 产业景气未改善 | **减仓或清仓** | 不等时间止损 |

**持有季度数计算**：

```python
持有季度数 = (当前年份 - 买入年份) * 4 + (当前季度 - 买入季度)
```

**P2 触发输出格式**：

```json
{
  "priority": "P2",
  "signal": "减仓或清仓",
  "sub_type": "logic_stop | time_stop",
  "reason": "逻辑止损——连续2季业绩低于预期 / 时间止损——持有满4季度逻辑未兑现",
  "hold_quarters": 5,
  "expected_growth": 30,
  "actual_growth": 8,
  "trend_direction": "连续减速",
  "action": "减仓至观察仓或清仓，替换为性价比更高的标的"
}
```

> **硬编码规则**：以"连续3个季度数据趋势"而非"单季数据"来区分短期波动与趋势性拐点，避免被噪音干扰。禁止因单季度数据波动而触发 P2。

---

### 第五步：P3 优先级检查——产业景气拐点

#### 5.1 检查维度

| 检查项 | 触发条件 | 数据来源 |
|--------|----------|----------|
| 渗透率减速（二阶导转负） | 行业渗透率增速放缓，接近或超过50% | `mid-industry-research` 输出 |
| ROE拐头向下 | 公司ROE从上行转为走平或下行 | `qoq-accelerator` 输出 |
| 行业供需逆转 | 从供不应求转为供过于求 | `mid-industry-research` 输出 |
| 技术面辅助 | 当前价 < MA200 + 放量破位 | `stock_quote.py --momentum --auto-peers` |

#### 5.2 执行规则

| 条件 | 决策 | 备注 |
|------|------|------|
| 渗透率>50%且增速放缓（二阶导转负） | **减机动仓** | 估值中枢必然下移（李进"二阶导思维"） |
| ROE从上行转为走平或下行 | **减机动仓** | 景气周期见顶信号（郑希"ROE拐点"逻辑） |
| 技术面破位（<MA200 + 放量）+ 产业景气走弱 | **加速减机动仓** | 技术面作为辅助确认信号 |
| 仅技术面破位但产业景气完好 | **机动仓小幅减持，底仓保留** | 技术面单独触发不构成本级充分条件 |

> **说明**：技术面信息（MA50/MA200/RSI/SMR）在本技能中作为 P3 的**辅助确认指标**，不单独构成一个优先级层级。如需对持仓做纯技术面深度体检，应调用 `trend-momentum-scan` 技能。

**P3 触发输出格式**：

```json
{
  "priority": "P3",
  "signal": "减机动仓",
  "reason": "产业景气拐点——渗透率减速/ROE拐头向下",
  "penetration_rate": 52,
```

### 第六步：P4 优先级检查——估值透支

#### 6.1 检查维度（对齐 `valuation-thermometer` 五档阈值 + 开发方案 F-9）

| 档位 | PEG区间 | 操作建议 | 与 exit-signal 联动 |
|------|---------|----------|-------------------|
| 显著低估 | < 0.8 | 绝佳买点，底仓可加 | 不触发 |
| 合理 | 0.8 ~ 1.2 | 合理买入区间，先建1/3底仓 | 不触发 |
| 偏贵 | 1.2 ~ 1.5 | 机动仓观望 | 温和预警（报告中标注，不强制操作） |
| 高估 | > 1.5 | 机动仓减持 | **触发 P4（减机动仓）** |
| 严重透支 | > 2.0 | 加速清机动仓 | **触发 P4（清机动仓）** |

> **阈值口径说明**：本表与 `valuation-thermometer` V1.0.0 的 PEG 五档阈值完全一致。理念文档 V2.0 对 PEG 阈值有三处表述（第一部分 PEG<1 低估、第三部分 0.8~1.2 合理区间、备忘卡 PEG<1.2 买入），本表以第三部分"0.8~1.2 合理区间"为主锚，"1.2~1.5 偏贵"为衔接过渡档。

#### 6.2 执行规则

| 条件 | 决策 | 备注 |
|------|------|------|
| PEG>1.5 且 PE历史分位>80% | **减持机动仓（30%~50%）** | 进入高估区 |
| PEG>2.0 | **加速清空机动仓，仅保留底仓** | 严重透支 |
| PEG>2.5 且 产业渗透率>50% | **底仓也考虑减仓** | 极端透支叠加景气见顶 |

#### 6.3 数据获取（零开发，直接调用已内置命令）

```bash

python tools/common/financial_rigor.py peg --pe {current_pe} --growth {forward_growth}

# PE 历史分位

# 估值交叉验证

```

#### 6.4 隐含业绩倒推（implied-growth）联动

在 P4 检查中，除了 PEG/PE 分位外，还需执行市值隐含业绩倒推：

| 判定 | 条件 | 操作 |
|------|------|------|
| 红灯 | 隐含增速 > 管理层指引增速 × 1.5 | 强化 P4 信号，加速减持 |
| 黄灯 | 隐含增速 在管理层指引增速 × 1.0~1.5 之间 | 温和预警，减持机动仓 |
| 绿灯 | 隐含增速 ≤ 管理层指引增速 | 估值可消化，不触发 |

**注意**：
- P4 触发仅影响**机动仓**，不影响底仓（除非 PEG>2.5 且渗透率>50%）
- 若 P4 与 P1/P2 同时触发，以**高优先级**为准

## 六、注意要点

### 6.1 数据缺失处理

| 缺失数据 | 处理方式 |
|----------|----------|
| 买入日期（且无 `--buy-date`） | 跳过 P2 时间止损子项，标记"数据不足" |
| 买入价格（且无 `--buy-price`） | 跳过 P1（欧奈尔止损），标记"数据不足" |
| 无 thesis 论文 | 仅执行 P0、P3、P4 检查，P1/P2/P5 跳过 |
| MA200 数据不足（上市<200天） | P3 技术面辅助跳过，标记"数据不足" |
| 一致预期增速缺失 | P4 PEG 使用历史3年复合增速替代 |

### 6.2 风控硬编码（不可被 AI 自由裁量）

以下规则为**硬编码**，写入 Prompt 后不允许 AI 自由裁量绕过或降级：

| 规则 | 硬编码值 | 说明 |
|------|----------|------|
| PEG > 1.5 | P4 减机动仓 | 不可输出"估值仍可接受"等弱化建议 |
| PEG > 2.0 | P4 加速清机动仓 | 不可输出"长期持有可消化估值"等弱化建议 |
| PE 分位 > 90% | 强制预警 | 无论其他指标如何，必须在报告中明确标注 |
| P0/P1 触发 | 禁止降级 | 不可输出"再观察""暂不操作"等弱化建议 |
| 时间止损（满4季度未兑现） | 必须执行减仓 | 不可因"产业前景好"而无限延期 |
| 调仓频率 | 每季度最多1次 | 防止过度交易 |
| 修正因子幅度 | 最大 ±1 档 | 估值修正因子上调或下调不得超过 1 档 |

### 6.3 禁止 LLM 心算

所有数值计算**必须**通过工具完成，禁止 LLM 心算：

```bash
# 正确用法
python tools/common/financial_rigor.py peg --pe 32.5 --growth 38.5

# 错误用法
# "PEG = 32.5 / 38.5 = 0.84"  <-- 禁止手动计算
```

| 市场 | 止损比例 | MA计算 | 特殊考虑 |

| 港股 | 8%~10% | 250个交易日 | 流动性折价，止损可放宽至10%；关注南向资金动向 |
| 美股 | 8%~10% | 250个交易日 | 无涨跌停，严格执行；关注SEC监管动态 |

### 6.5 检查频率建议

| 模式 | 触发时机 | 覆盖优先级 |

| `daily` | 每日收盘后（建议每周一开盘前运行） | P0（监管突发）、P1（止损）、P3（技术面辅助） |

| `mid-thesis-drift` | **内置调用** | 提供 P5 逻辑漂移数据 |
| `qoq-accelerator` | **前置** | 提供 P2/P3 季度加速度与景气数据 |
| `trend-momentum-scan` | **辅助** | 提供 P3 技术面深度体检参考 |
| `mid-industry-research` | **前置** | 提供 P3 产业渗透率/景气度数据 |
| `portfolio-review --horizon mid` | **后置** | exit-signal 输出作为组合调整依据 |

**典型使用流程**：

```
建仓时：
  thesis-tracker {公司名} --horizon mid    <-- 建立买入论文
        |
每日监控（每周一）：
  exit-signal {公司名} --check-mode daily  <-- 检查 P0/P1/P3（快速）
        |
季报发布后：
  qoq-accelerator {公司名}                 <-- 季度加速度分析
        |
  mid-thesis-drift {公司名}               <-- 逻辑漂移检测
        |
  exit-signal {公司名} --check-mode quarterly  <-- 完整 P0~P5 检查
        |
  （若触发卖出信号）
  portfolio-review {持仓清单} --horizon mid    <-- 组合层面评估调仓影响
```

## 八、局限性

1. **论文依赖**：P1/P2/P5 检查依赖 `thesis-tracker --horizon mid` 建立的买入论文，若未建立论文，这三项检查无法完整执行
2. **MA200 数据**：上市不足200个交易日的标的无法计算 MA200，P3 技术面辅助跳过
3. **一致预期数据**：若无法获取一致预期，P4 的 PEG 计算可能依赖历史增速，精度下降
4. **监管记录覆盖**：搜索工具可能无法覆盖所有监管信息，建议用户自行在证监会/交易所官网确认
5. **地缘政治量化**：地缘政治风险的量化评估超出本技能范围，需结合理念文档 V2.0 第一部分"支柱四"进行人工判断
6. **不构成投资建议**：本技能仅为风控工具，最终决策需用户独立判断
