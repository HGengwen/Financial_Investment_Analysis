## 一、设计理念

在1~3年的中长期投资中，**增速的加速度（二阶导）比增速本身更重要**。李进明确指出："即使行业仍在增长，若增速放缓，估值中枢必然下移。"

本技能是理念文档"矛盾二：持有逻辑的时间维度冲突"的**量化化解工具**，通过连续3个季度的数据趋势来区分短期波动与趋势性拐点。

### 1.1 四位大师在加速度分析中的贡献

| 大师 | 在加速度分析中的贡献 | 在本技能中的体现 |
|------|---------------------|-----------------|
| **李进** | "二阶导思维"——增速放缓即估值中枢下移信号 | 加速度（二阶导）是核心输出指标；连续3季减速直接映射 exit-signal P3 |
| **郑希** | 每季度用景气数据做"体检"，不持有信仰 | 强制每季度检查，连续3季判定；implied-growth 验证市场隐含增速 |
| **林奇** | 区分"快速增长型增速放缓"与"正常波动" | 连续趋势判定法区分噪音与拐点；利润增速匹配度分析 |
| **欧奈尔** | 信号驱动，拒绝主观臆断 | 硬性规则判定，不依赖主观判断；禁止 LLM 心算 |

**核心理念**：以"连续3个季度的数据趋势"而非"单季数据"来区分短期波动与趋势性拐点，避免被噪音干扰。

### 1.2 四大矛盾在本技能中的化解要点

| 矛盾 | 化解方案 | 在本技能中的体现 |
|------|----------|-----------------|
| **单季噪音 vs 趋势拐点** | 以连续3个季度数据趋势区分波动与拐点 | 第四步"连续3季度趋势判定"：连续加速=景气向上；连续减速=拐点预警；单季异动=噪音不判拐点 |
| **长期持有 vs 中期兑现** | 满4季度逻辑未兑现触发时间止损 | 加速度连续4季度为负时，在报告中标注"可能触发 P2 时间止损"预警 |
| **止损 vs 越跌越买** | 左侧布局仅适用于"杀估值"而非"杀逻辑" | 加速度持续为负（杀逻辑信号）时，报告中明确标注"不建议逆向加仓" |
| **分散 vs 集中** | 行业分散、个股集中 | 批量模式下输出行业加速度均值，辅助判断行业整体景气方向 |

### 1.3 与其他技能的联动关系

| 联动方向 | 技能 | 联动方式 |
|----------|------|----------|
| **→ valuation-thermometer** | 估值温度计 | 加速度方向作为估值修正因子：连续正加速 +0.3 档，连续负加速 -0.5 档 |
| **→ exit-signal P3** | 卖出信号 | 加速度连续3季为负 → P3（产业景气拐点）核心触发条件之一 |
| **→ exit-signal P2** | 卖出信号 | 加速度连续4季为负 + 业绩低于预期 → 辅助触发 P2（逻辑止损） |
| **→ mid-thesis-drift** | 逻辑漂移检测 | 加速度数据是漂移检测的核心证据 |
| **← mid-industry-research** | 行业景气研究 | 行业渗透率数据辅助判断加速度方向的产业背景 |

## 二、输入参数

### 2.1 参数定义

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `{标的}` | 字符串 | 是 | 无 | 公司名称或股票代码（支持A股/港股/美股） |
| `--quarters` | 整数 | 否 | 8 | 回溯季度数（至少4个季度，建议8个季度） |
| `--seasonal-adjust` | 标志 | 否 | false | 是否启用季节性调整（强季节性行业建议开启） |
| `--horizon` | 字符串 | 否 | mid | 投资周期：`mid`（1~3年，当前技能唯一支持模式） |
| `--export` | 标志 | 否 | false | 是否导出Markdown报告 |
| `--export-path` | 字符串 | 否 | reports/ | 报告输出路径 |
| `--json` | 标志 | 否 | false | 是否以JSON格式输出 |

**批量模式**：支持逗号分隔多个标的，如 `qoq-accelerator 中际旭创,新易盛,天孚通信`

### 2.2 参数说明

- `--quarters`：最少4个季度（可计算加速度但样本不足以做连续3季趋势判定），建议8个季度以获得完整的趋势视图
- `--seasonal-adjust`：开启后，QoQ 增速将与去年同期 QoQ 做对比，消除季节性干扰（详见"季节性调整"步骤）
- `--horizon`：统一为 `mid`（与 `thesis-tracker`、`portfolio-review` 保持一致，F-4 修正）

### 第二步：计算季度环比增速（QoQ Growth）与同比增速（YoY Growth）

#### 2.1 QoQ 增速计算

**计算公式**：

```
QoQ增速(%) = (本季度值 - 上季度值) / |上季度值| × 100%
```

**计算示例**：

| 季度 | 营收（亿） | QoQ增速 | 利润（亿） | QoQ增速 |
|------|-----------|---------|-----------|---------|
| 2026Q1 | 32.5 | +15.2% | 4.8 | +17.1% |
| 2025Q4 | 28.3 | +12.7% | 4.1 | +13.9% |
| 2025Q3 | 25.1 | +10.1% | 3.6 | +12.5% |
| 2025Q2 | 22.8 | +12.9% | 3.2 | +14.3% |
| 2025Q1 | 20.2 | +9.2% | 2.8 | +7.7% |
| 2024Q4 | 18.5 | +10.1% | 2.6 | +8.3% |
| 2024Q3 | 16.8 | +10.5% | 2.4 | +9.1% |
| 2024Q2 | 15.2 | — | 2.2 | — |

#### 2.2 YoY 增速计算（双口径，开发方案 6.3 要求）

**计算公式**：

```
YoY增速(%) = (本季度值 - 去年同季度值) / |去年同季度值| × 100%
```

**为什么需要双口径**：QoQ 受季节性影响较大（如零售行业 Q4 旺季环比大增、Q1 淡季环比下滑），YoY 可消除季节性干扰。当 QoQ 与 YoY 方向一致时，结论更可信。

| 场景 | QoQ | YoY | 判定 |
|------|-----|-----|------|
| 方向一致 | 加速 | 加速 | 高置信度加速 |
| 方向一致 | 减速 | 减速 | 高置信度减速 |
| 方向不一致 | 减速 | 加速 | 季节性干扰，以 YoY 为主 |
| 方向不一致 | 加速 | 减速 | 季节性干扰，以 YoY 为主 |

#### 2.3 数据质量检查

| 检查项 | 判定 | 处理 |
|--------|------|------|
| 连续2个季度数据缺失 | 数据严重不足 | 输出"无法计算加速度"，建议不依赖本技能结论 |
| 单个季度数据缺失 | 数据缺口 | 用相邻季度平均值估算，并标注"估算值" |
| 营收或利润为负值 | 负值影响QoQ计算 | 使用同比（YoY）作为替代，标注"因负值改用同比" |

### 第三步：计算加速度（二阶导）

**加速度 = 本季度QoQ增速 - 上季度QoQ增速**

**加速度的含义**：

| 加速度符号 | 含义 | 景气状态 |
|-----------|------|----------|
| 加速度 > 0（正值扩大） | 增速在加快 | 景气加速 🟢 |
| 加速度 = 0 | 增速持平 | 景气平稳 🟡 |
| 加速度 < 0（正值缩小或转负） | 增速在放缓 | 景气减速 🔴 |

**计算示例**（接上表）：

| 季度 | 营收QoQ | 加速度（营收） | 利润QoQ | 加速度（利润） |
|------|---------|---------------|---------|---------------|
| 2026Q1 | +15.2% | +2.5%（15.2-12.7） | +17.1% | +3.2% |
| 2025Q4 | +12.7% | +2.6% | +13.9% | +1.4% |
| 2025Q3 | +10.1% | -2.8%（10.1-12.9） | +12.5% | -1.8% |
| 2025Q2 | +12.9% | +3.7% | +14.3% | +6.6% |
| 2025Q1 | +9.2% | -0.9% | +7.7% | -0.6% |
| 2024Q4 | +10.1% | -0.4% | +8.3% | -0.8% |
| 2024Q3 | +10.5% | — | +9.1% | — |

### 第四步：连续3个季度趋势判定

**判定规则**（基于理念文档"矛盾二"的化解方案 + 开发方案 10.2 Q-1/Q-2/Q-3 验收用例）：

| 趋势模式 | 判定结果 | 颜色 | 含义 |
|----------|----------|------|------|
| 加速度连续3个季度为正 | **景气加速** | 🟢 | 增长势头在增强，是积极信号 |
| 加速度正负交替（无连续方向） | **景气平稳/波动** | 🟡 | 无明确趋势，需继续观察 |
| 加速度连续3个季度为负 | **景气减速/拐点预警** | 🔴 | 增长势头在减弱，估值中枢可能下移 |

**判定流程**：

```
取最近3个季度的加速度值：
  第1个加速度（最早）：a₁
  第2个加速度（中间）：a₂
  第3个加速度（最新）：a₃

IF a₁ > 0 AND a₂ > 0 AND a₃ > 0:
    → 景气加速 🟢
ELIF a₁ < 0 AND a₂ < 0 AND a₃ < 0:
    → 景气减速/拐点预警 🔴
ELSE:
    → 景气平稳/波动 🟡
```

**连续3季趋势判定示例**：

| 场景 | a₁ | a₂ | a₃ | 判定 | 说明 |
|------|----|----|----|----|------|
| A（对齐 Q-1） | +2.5% | +2.6% | +2.5% | 🟢 加速 | 连续3季正加速，景气向上 |
| B（对齐 Q-2） | -2.8% | -1.5% | -0.8% | 🔴 减速 | 连续3季负加速，拐点预警 |
| C（对齐 Q-3） | +2.6% | -1.8% | +2.5% | 🟡 波动 | 正负交替，无明确趋势，**不判拐点** |
| D | +2.5% | +3.2% | -0.5% | 🟡 波动 | 最新季转负，需关注下季 |

> **硬编码规则**：仅当加速度**连续3个季度为负**时才判定为"景气减速/拐点预警"。单季度或连续2个季度的负加速**不得**判定为拐点，仅标注"需关注下季数据确认"。此规则防止将短期噪音误判为趋势拐点（对齐开发方案 10.2 Q-3 验收用例：单季波动不判拐点）。

### 第五步：营收与利润匹配度分析

**核心问题**：利润增速是否跟上营收增速？（理念文档 V2.0 第一部分"支柱二"）

| 场景 | 判定 | 含义 |
|------|------|------|
| 利润增速 ≥ 营收增速 | ✅ 匹配 | 费用控制良好，盈利质量高 |
| 利润增速 < 营收增速 但 > 0 | ⚠️ 弱匹配 | 费用增长快于收入，需关注费用结构 |
| 利润增速为负 但 营收增速为正 | 🔴 不匹配 | 费用失控或毛利率大幅下滑，警惕 |

**匹配度计算**：

```
利润增速匹配度 = 近4季度利润累计增速 - 近4季度营收累计增速

若 > 5%: ✅ 利润跑赢营收
若 -5% ~ 5%: ⚠️ 基本匹配
若 < -5%: 🔴 利润跑输营收（警惕费用失控）
```

**毛利率趋势辅助判断**：

```bash
python tools/a_share/stock_financial.py --code {code} --indicator 毛利率
```

| 毛利率趋势 | 对匹配度的影响 |
|-----------|---------------|
| 毛利率稳定或提升 | 弱匹配可能是阶段性的，容忍度可提高 |
| 毛利率连续下降 | 不匹配是结构性的，需警惕护城河侵蚀 |

### 第六步：先行指标验证（前瞻性判断）

通过先行指标验证"加速度"方向是否具有持续性：

| 先行指标 | 数据来源 | 加速信号 | 减速信号 |
|----------|----------|----------|----------|
| **合同负债** | `stock_financial.py --advanced 合同负债` | 环比增长 > 营收增速 | 环比下降 |
| **存货** | `stock_financial.py --advanced 存货` | 存货周转率提升（存货增速 < 营收增速） | 存货增速 > 营收增速（积压风险） |
| **研发费用** | `stock_financial.py --advanced 研发费用` | 研发费用率提升（未来增长储备） | 研发费用率下降（短期化倾向） |

**综合判断**：

| 先行指标方向 | 与加速度方向一致性 | 结论置信度 |
|-------------|-------------------|----------|
| 一致（合同负债增 + 存货周转快） | 高度一致 | 加速度方向可信度高 ✅ |
| 中性 | 部分一致 | 加速度方向需谨慎对待 ⚠️ |
| 相反 | 不一致 | 加速度方向可能被证伪 🔴 |

### 第七步：implied-growth 加速度方向验证（V1.0.0 新增）

**目的**：验证当前加速度方向是否与市场隐含增速一致。若加速度为正但市场隐含增速已远超管理层指引，说明市场可能过度乐观，加速度方向的可持续性存疑。

**调用工具（禁止 LLM 心算）**：

```bash
python tools/common/financial_rigor.py implied-growth \
  --market-cap {当前市值} \
  --target-pe {合理PE} \
  --net-margin {净利率} \
  --ttm-revenue {TTM营收} \
  --guidance-growth {管理层指引增速}
```

**加速度方向与 implied-growth 交叉验证规则**：

| 加速度方向 | implied-growth 信号 | 综合判定 | 含义 |
|-----------|-------------------|----------|------|
| 🟢 加速 | 绿灯 | ✅ 加速可信 | 业绩加速且估值可被消化，最理想状态 |
| 🟢 加速 | 黄灯 | ⚠️ 加速但需验证 | 业绩在加速，但市场已隐含较高预期，需确认增速能否持续超预期 |
| 🟢 加速 | 红灯 | 🔴 加速但估值透支 | 业绩虽在加速，但市场已透支更多，估值风险大 |
| 🔴 减速 | 绿灯 | ⚠️ 减速但估值低 | 业绩减速但估值已有安全边际，可能是短期波动 |
| 🔴 减速 | 黄灯/红灯 | 🔴 减速且估值高 | 双重风险，拐点预警加强 |

> **阈值口径说明**：implied-growth 的"合理PE"取值与 `valuation-thermometer` V1.0.0 保持一致：`合理PE = 未来2年EPS复合增速 × 1.2`，上限40x，下限8x。

### 第八步：季节性调整处理（V1.0.0 新增）

**问题**：部分行业（零售、旅游、农业、消费电子）存在强季节性，Q1 环比 Q4 通常大幅下滑，导致 QoQ 加速度在每年 Q1 均呈负值，产生系统性"假减速"信号。

**启用条件**：`--seasonal-adjust` 参数开启时执行；或当行业被识别为强季节性行业时自动提示。

**调整方法**：

#### 8.1 YoY 辅助验证

当 QoQ 加速度发出"减速"信号时，检查 YoY 增速是否同步减速：

| QoQ 加速度 | YoY 增速趋势 | 调整后判定 |
|-----------|-------------|-----------|
| 连续为负 | YoY 仍在加速或稳定 | **季节性干扰**，维持"景气平稳 🟡" |
| 连续为负 | YoY 同步减速 | **真实减速**，维持"景气减速 🔴" |
| 连续为正 | YoY 同步加速 | **真实加速**，维持"景气加速 🟢" |

#### 8.2 季节性 QoQ 基准比较

将本季度 QoQ 与**去年同季度的 QoQ** 做比较，消除季节性基准差异：

```
季节性调整后QoQ = 本季度QoQ - 去年同季度QoQ

若调整后QoQ > 0：说明增速优于去年同期（排除季节性后的真实改善）
若调整后QoQ < 0：说明增速弱于去年同期（排除季节性后的真实走弱）
```

**示例**：

| 季度 | 营收QoQ | 去年同季QoQ | 调整后QoQ | 判定 |
|------|---------|------------|-----------|------|
| 2026Q1 | -5% | -8% | +3% | 优于去年同期，非真实减速 |
| 2025Q1 | -8% | -5% | -3% | 弱于去年同期，需警惕 |

#### 8.3 季节性调整对综合评级的影响

| 场景 | 调整前评级 | 调整后评级 | 说明 |
|------|-----------|-----------|------|
| QoQ 减速但 YoY 稳定 | 🔴 减速 | 🟡 平稳 | 季节性干扰，降级处理 |
| QoQ 减速且 YoY 也减速 | 🔴 减速 | 🔴 减速 | 真实减速，不调整 |
| QoQ 加速且 YoY 也加速 | 🟢 加速 | 🟢 加速 | 真实加速，不调整 |

> **注意**：季节性调整为辅助手段，不替代核心的"连续3季趋势判定"。最终报告中需同时展示"调整前"和"调整后"结论，让用户自行判断。

### 第十步：综合评分与输出

#### 10.1 综合评分维度

| 维度 | 权重 | 评分标准 |
|------|------|----------|
| 营收加速度趋势 | 35% | 连续3季正=100分，正负交替=50分，连续3季负=0分 |
| 利润加速度趋势 | 35% | 同上 |
| 营收与利润匹配度 | 15% | 匹配=100分，弱匹配=50分，不匹配=0分 |
| 先行指标一致性 | 10% | 一致=100分，中性=50分，相反=0分 |
| implied-growth 验证 | 5% | 绿灯=100分，黄灯=50分，红灯=0分 |

#### 10.2 综合评级

| 综合得分 | 评级 | 含义 | 操作参考 |
|----------|------|------|----------|
| ≥ 80 | 🟢 加速向好 | 景气度明确上行，业绩持续改善 | 积极关注，可考虑加仓 |
| 50 ~ 79 | 🟡 平稳/待确认 | 无明确方向，需继续观察 | 维持当前仓位，等待下季确认 |
| < 50 | 🔴 减速/拐点 | 景气度下行，存在拐点风险 | 提高警惕，机动仓应考虑减仓 |

#### 10.3 加速度-估值二维矩阵（V1.0.0 新增）

将加速度评级与 `valuation-thermometer` 的估值温度联合决策，生成更精确的操作建议：

| 加速度 \ 估值 | 显著低估（PEG<0.8） | 合理（0.8~1.2） | 偏贵（1.2~1.5） | 高估（>1.5） | 严重透支（>2.0） |
|-------------|-------------------|----------------|----------------|-------------|----------------|
| 🟢 加速向好 | **积极加仓** | **建仓/加仓** | 机动仓观望 | 机动仓不加仓 | 不加仓，等估值回落 |
| 🟡 平稳 | 分批建仓 | 持有/小仓位建 | 持有观望 | 机动仓减持 | 减机动仓 |
| 🔴 减速/拐点 | 轻仓试探 | 持有不动 | **机动仓减持** | **减机动仓** | **加速清机动仓** |

**核心逻辑**：
- 加速度为正且估值合理 → 最佳买点（戴维斯双击条件具备）
- 加速度为负且估值偏高 → 双重风险，必须减仓
- 加速度为负但估值极低 → 可能是短期波动，轻仓试探

> **与 exit-signal 联动**：当加速度为 🔴 减速 且估值为 高估/严重透支 时，同时触发 exit-signal P3（产业景气拐点）和 P4（估值透支），以 P3 优先（优先级更高）。

## 四、与 exit-signal 联动（V1.0.0 新增）

本技能输出的加速度评级直接映射到 `exit-signal` 的 P3（产业景气拐点）级别：

| 本技能输出 | exit-signal 映射 | 触发条件 |
|-----------|-----------------|----------|
| 🔴 景气减速（营收+利润加速度连续3季为负） | **P3 产业景气拐点** | 核心触发条件之一 |
| 🔴 景气减速 + 先行指标方向相反 | **P3 强化信号** | 加速度+先行指标双重确认 |
| 🔴 景气减速持续4个季度以上 | **P2 逻辑止损预警** | 辅助触发 P2（需叠加业绩低于预期） |
| 🟡 平稳/待确认 | 不触发 | 继续观察 |
| 🟢 加速向好 | 不触发 | 积极信号 |

**P3 触发条件补充说明**：

加速度数据是 P3 的**核心输入之一**，但 P3 的完整触发还需结合：
- 渗透率位置（>50%且增速放缓）→ 由 `mid-industry-research` 提供
- ROE 趋势（拐头向下）→ 由 `stock_financial.py --indicator ROE` 提供
- 技术面辅助（MA200 下方+放量破位）→ 由 `trend-momentum-scan` 提供

> **硬编码规则**：加速度连续3季为负 → 必须在报告中标注"P3 产业景气拐点预警"，不可因"产业前景长期向好"而弱化该预警。

## 五、与 valuation-thermometer 联动（V1.0.0 新增）

本技能输出的加速度方向作为 `valuation-thermometer` 的修正因子：

| 加速度评级 | 修正值 | 说明 |
|-----------|--------|------|
| 🟢 连续2个季度以上正加速 | **+0.3 档** | 景气加速可适度容忍更高估值 |
| 🟡 平稳/波动 | **无修正** | 不改变估值评级 |
| 🔴 连续负加速 | **-0.5 档** | 景气减速应降低估值容忍度 |

**修正幅度上限**：±1 档（防止过度修正）。例如，即使加速度连续正加速且先行指标一致，估值评级最多上调1档（如"偏贵"→"合理"），不可跳2档。

以下规则为硬性规则，写入 Prompt 后不允许 AI 自由裁量绕过或降级：

| 硬性规则 | 内容 | 不可做的事 |

| 禁止 LLM 心算 | 所有数值必须走工具 | 不可手动计算 QoQ、YoY、加速度等数值 |

## 十、注意要点

### 1. 数据口径一致性

- **必须使用单季度数据**，不得使用累计数据（TTM或年初至今累计）
- A股东方财富的 `营业总收入` 在季报中返回的是**单季数据**，可直接使用
- 若数据源返回的是累计数据，需自行计算单季值（本季累计 - 上季累计）

### 2. 数据不足处理

| 场景 | 处理方式 |
|------|----------|
| 上市不足8个季度 | 使用全部可用数据，报告标注"数据不足8季，趋势判定置信度降低" |
| 只有4个季度数据 | 可计算加速度，但**不执行"连续3季趋势判定"**（样本不足），仅展示数据 |
| 只有3个季度数据 | 仅展示QoQ增速，不计算加速度（至少需要2个QoQ值才能算加速度） |

### 3. 负值处理

当季度营收或利润为负值时，QoQ计算会产生误导。处理规则：

| 场景 | 处理方式 |
|------|----------|
| 利润为负 | 改用**同比增速（YoY）** 替代环比，标注"因利润为负，改用同比" |
| 营收为负（极罕见） | 放弃该季度数据，标注"异常值" |

### 4. 禁止LLM心算（硬性规则）

所有数值计算（QoQ增速、YoY增速、加速度、匹配度）**必须**通过工具计算或程序化处理，禁止LLM心算。

```bash
# 正确用法：使用 --json 输出后由程序解析计算
python tools/a_share/stock_financial.py --code 300502 --indicator 营业总收入,归母净利润 --json

# 错误用法
# "营收从28.3亿增长到32.5亿，增速15.2%" ← 禁止手动计算
```

### 5. 跨市场差异

| 市场 | 数据粒度 | 季报披露要求 | 特殊考虑 |
|------|----------|-------------|----------|
| A股 | 单季数据 | 强制披露季报 | 数据最完整，优先使用 |
| 港股 | 单季/半年数据 | 半年报强制，季报自愿 | 部分公司无季报，数据可能不足；开启 `--seasonal-adjust` |
| 美股 | 单季数据（10-Q） | 每季度强制披露 | Q1/Q3为10-Q（未经审计），Q2/Q4为10-K（经审计） |

### 6. 命名一致性

| 错误写法（草稿） | 正确写法（V1.0.0） | 依据 |
|----------------|-------------------|------|
| `exit-signal --mode quarterly` | `exit-signal --horizon mid` | F-4 参数统一 |
| `trend-tech-screen` | `mid-trend-tech-screen` | F-7 命名统一 |
| `thesis-drift-mid` | `mid-thesis-drift` | F-7 命名统一 |
| `portfolio-review --mode mid` | `portfolio-review --horizon mid` | F-4 参数统一 |

## 十一、局限性

1. **数据可得性**：部分港股/美股公司季报数据可能不完整
2. **行业季节性**：部分行业（零售、旅游）存在强季节性，QoQ分析需开启 `--seasonal-adjust` 进行季节性调整
3. **会计变更**：企业会计政策变更可能导致前后数据不可比
4. **极端值干扰**：单季极端值（如资产出售一次性收益）会影响加速度判断
5. **QoQ 的固有缺陷**：环比增速天然受季节效应、节假日分布影响，需与 YoY 双口径交叉验证
6. **不构成投资建议**：本技能仅为基本面分析工具，需结合其他技能综合决策
