# 中期逻辑漂移检测：景气假设验证 + 漂移等级判定 + 多技能联动

对 $ARGUMENTS 持仓标的，对比**建仓时投资论文中的景气假设**与**最新季度财报数据**，逐条验证假设是否仍成立，输出"漂移等级 + 证据链"及行动建议。

---

## 设计理念

在1~3年的中期投资中，郑希强调"长期判断由无数短期客观判断拼接而成"，李进强调"二阶导思维"——即使行业仍在增长，若增速放缓，估值中枢必然下移。**持仓不是"买入并遗忘"，而是每季度用景气数据做一次"体检"**。

### 本技能与长期 `thesis-drift` 的本质区别

| 维度 | 长期 `thesis-drift` | **中期 `mid-thesis-drift`** |
|------|-------------------|---------------------------|
| **检测对象** | 护城河永续性、商业模式 | **景气假设（渗透率/订单/ROE/毛利率/加速度/地缘政治）** |
| **核心追问** | "公司还是不是好公司？" | **"当初的景气逻辑还在吗？"** |
| **判断依据** | 竞争格局、管理层诚信 | **季度数据趋势（连续3季）** |
| **检测频率** | 年度/半年度 | **季度** |
| **时间止损** | 可容忍数年业绩平淡 | **满4季度逻辑未兑现即触发P2** |
| **输出** | 论文漂移/未漂移 | **四级漂移等级 + 证据链 + exit-signal P级别映射** |

### 四位大师在逻辑漂移检测中的角色

| 大师 | 核心贡献 | 本技能体现 |
|------|---------|----------|
| **郑希** | "景气下行果断调仓，不被长期叙事绑架" | 漂移即触发调仓逻辑 |
| **李进** | "二阶导思维——增速放缓即估值中枢下移" | 加速度是核心检测维度 |
| **林奇** | "增速放缓即考虑卖出" | 连续3季度趋势判定 |
| **欧奈尔** | "信号驱动，拒绝主观臆断" | 硬性指标判定漂移 + 风控硬编码 |

### 核心理念

**基于证据而非信仰。** 用最新季度数据逐条验证当初的景气假设，若假设被证伪（≥3项漂移），无论股价涨跌，均应考虑卖出或减仓。

## 输入参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `{标的}` | 字符串 | ✅ | 无 | 公司名称或股票代码（支持A股/港股/美股） |
| `--thesis-date` | 日期 | ❌ | 最新 | 建仓论文日期（YYYY-MM-DD），默认取最新论文 |
| `--since` | 日期 | ❌ | — | 买入日期（用于时间止损判断，可自动从论文读取） |
| `--export` | 标志 | ❌ | false | 是否导出Markdown报告 |
| `--export-path` | 字符串 | ❌ | reports/ | 报告输出路径 |
| `--json` | 标志 | ❌ | false | 是否以JSON格式输出 |

> **参数命名统一**：本技能不使用 `--mode` 参数，所有涉及持有周期的参数统一使用 `--horizon`（与 `thesis-tracker`、`portfolio-review` 保持一致，对齐开发方案 F-4）。

**数据依赖**：

- **强依赖**：必须已存在 `thesis-tracker --horizon mid` 建立的投资论文（`reports/{公司名}/{公司名}-mid-thesis.md`）
- **弱依赖**：`qoq-accelerator` 输出（提供加速度数据）、`trend-momentum-scan` 输出（提供技术面确认）
- 若无中期论文，系统应提示"请先运行 `/thesis-tracker {标的} --horizon mid` 建立中期投资论文"

## 执行流程

### 第一步：提取基准假设清单

**读取路径**：`reports/{公司名}/{公司名}-mid-thesis.md`

从论文中精确提取全部景气假设，构建基准假设清单。**必须从论文中明确提取，禁止AI"脑补"。**

**提取六大景气假设**：

| 假设编号 | 假设类型 | 论文中必须包含的内容 | 提取方式 | 权重 |
|----------|----------|---------------------|----------|------|
| H1 | **渗透率假设** | 建仓时渗透率位置、预期渗透率提升路径 | 从论文"景气假设"章节提取 | 20% |
| H2 | **订单/合同负债假设** | 建仓时合同负债水平、预期订单增长 | 从论文"关键验证指标"提取 | 20% |
| H3 | **ROE趋势假设** | 建仓时ROE水平、预期ROE方向 | 从论文"财务验证"章节提取 | 20% |
| H4 | **毛利率假设** | 建仓时毛利率水平、预期毛利率趋势 | 从论文"竞争格局"章节提取 | 15% |
| H5 | **增速加速度假设** | 建仓时增速加速度方向、预期加速度持续 | 从论文"景气判断"章节提取 | 15% |
| H6 | **地缘政治假设** | 建仓时地缘风险评估、关税/制裁/供应链预期 | 从论文"地缘风险"章节提取 | 10% |

> **H6 新增说明**：理念文档 V2.0 第一部分第3步"深度研究"将"地缘政治与外部环境"列为四大支柱之一。草稿版仅含5个维度，本版新增H6地缘政治维度，对齐理念文档。

**假设完整性检查**：

| 场景 | 处理方式 |
|------|----------|
| 无中期论文文件 | 输出"❌ 未找到中期论文，请先运行 `/thesis-tracker {标的} --horizon mid`" |
| 论文内容不完整（缺少某假设） | 标注"⚠️ 论文中未找到 {假设名} 假设，该项无法验证，不纳入漂移计数" |
| 论文文件损坏 | 输出"❌ 论文文件损坏，建议重新建立论文" |
| H6地缘假设缺失 | 标注"⚠️ 论文中未包含地缘政治假设"，该项不纳入计数，但在风险提示中标注"地缘风险未设基线" |

### 第二步：假设分类与权重分配

将提取的假设按四大类别归组，便于分类验证与分类内聚合：

| 类别 | 包含假设 | 权重总和 | 说明 |
|------|---------|---------|------|
| **景气类** | H1（渗透率）、H2（订单）、H5（加速度） | 55% | 产业景气核心维度 |
| **估值类** | H3（ROE）、H4（毛利率） | 35% | 财务健康与定价权 |
| **地缘政治类** | H6（地缘政治） | 10% | 外部系统性风险 |
| **管理治理类** | （由 exit-signal P0 覆盖，本技能不重复检测） | — | 治理问题走一票否决 |

> **管理治理类说明**：管理层诚信、财务造假等治理问题由 `exit-signal` P0（治理一票否决）独立覆盖，本技能聚焦景气假设验证，不重复评估治理维度。若在验证过程中发现治理异常线索（如管理层频繁变更业绩指引、审计报告非标意见），应在报告中显式标注"⚠️ 发现治理异常线索，建议同步运行 exit-signal 检查P0"。

### 第三步：数据收集与交叉验证

基于理念文档 V2.0 第三部分"深度研究"的框架，获取验证所需的六大维度最新数据。

**数据获取命令**：

```bash
# 获取营收、利润、ROE、毛利率
python tools/a_share/stock_financial.py --code {code} --indicator 营业总收入,归母净利润,ROE,毛利率

# 获取合同负债（订单能见度）
python tools/a_share/stock_financial.py --code {code} --advanced 合同负债

# 获取动量数据（技术面确认）
python tools/a_share/stock_quote.py --code {code} --momentum --auto-peers

# 获取估值数据（implied-growth 交叉验证）
python tools/common/financial_rigor.py peg --pe {PE} --growth {growth}
python tools/common/financial_rigor.py implied-growth --market-cap {市值} --target-pe {目标PE} --net-margin {净利率} --ttm-revenue {TTM营收} --guidance-growth {指引增速}

# 搜索行业最新渗透率数据
python tools/common/anysearch.py "{行业名} 渗透率 最新" --tag finance
python tools/common/doubao_search.py "{行业名} 渗透率 {当前年份}" --finance --need-content

# 搜索地缘政治最新动态
python tools/common/anysearch.py "{公司名} 关税 制裁 出口管制" --tag finance
python tools/common/doubao_search.py "{公司名} {行业名} 地缘风险 {当前年份}" --finance --need-content
```

**最新季度数据提取要点**：

| 检测维度 | 所需数据 | 数据来源 | 统计周期 |
|----------|----------|----------|----------|
| H1 渗透率验证 | 行业最新渗透率 | 搜索工具（第三方数据） | 最新季度 |
| H2 订单验证 | 合同负债（最新 vs 建仓时） | `stock_financial.py --advanced 合同负债` | 最新季度 vs 建仓季度 |
| H3 ROE验证 | ROE（最新季度 vs 建仓时） | `stock_financial.py --indicator ROE` | 最新季度 vs 建仓季度 |
| H4 毛利率验证 | 毛利率（最新季度 vs 建仓时） | `stock_financial.py --indicator 毛利率` | 最新季度 vs 建仓季度 |
| H5 加速度验证 | 连续3个季度的营收增速 | `stock_financial.py --indicator 营业总收入` | 最近3个季度 |
| H6 地缘验证 | 最新关税/制裁/供应链动态 | 搜索工具 | 最新动态 |

**多源交叉验证**：关键财务数据至少两个独立来源，误差 >1% 显式标记（遵循报告质量门禁 G-2）。

### 第四步：逐条假设验证

对每条假设给出"成立 / 部分漂移 / 完全漂移"三档判定，并附完整证据链。

#### H1：渗透率假设验证

**验证逻辑**：

| 比较结果 | 判定 | 说明 |
|----------|------|------|
| 最新渗透率 ≥ 论文中预期渗透率 | ✅ 成立 | 渗透率提升速度符合或快于预期 |
| 最新渗透率略低于预期（偏差 < 20%） | ⚠️ 部分漂移 | 略低于预期，但仍在合理偏差范围 |
| 最新渗透率明显低于预期（偏差 ≥ 20%） | 🔴 完全漂移 | 渗透率提升速度显著慢于预期 |
| 渗透率已超过50% | 🔴 完全漂移 | 李进框架：渗透率>50%后增速放缓，考虑兑现 |

**二阶导验证（新增）**：不仅看渗透率绝对值，还需验证渗透率的**增速是否在加速**（李进"15%临界点"理论）：

| 渗透率增速趋势 | 判定 | 说明 |
|---------------|------|------|
| 渗透率增速在加速 | ✅ 二阶导为正 | 行业仍在加速上行期 |
| 渗透率增速持平 | ⚠️ 二阶导为零 | 行业可能进入稳态，需关注 |
| 渗透率增速在减速 | 🔴 二阶导为负 | 行业可能接近景气顶点 |

**数据获取**：

```bash
python tools/common/anysearch.py "{行业名} 渗透率 最新" --tag finance
python tools/common/doubao_search.py "{行业名} 渗透率 {当前年份}" --finance --need-content
```

**输出格式**：

```json
{
  "dimension": "H1_渗透率",
  "thesis_assumption": "建仓时渗透率=18%，预期12个月内达25%",
  "latest_data": "当前渗透率=22%（已过6个月）",
  "expected": "25%",
  "actual": "22%",
  "deviation": "-12%",
  "second_derivative": "渗透率增速仍在加速（Q1:+2%, Q2:+3%）",
  "judgment": "✅ 成立",
  "evidence": "LightCounting 2026Q2数据"
}
```

#### H3：ROE趋势假设验证

**验证逻辑**（基于郑希框架）：

| ROE趋势 | 判定 | 说明 |
|---------|------|------|
| 最新ROE ≥ 建仓时ROE + 预期增幅 | ✅ 成立 | ROE向上斜率符合或快于预期 |
| 最新ROE > 建仓时ROE | ✅ 趋势向上 | ROE仍在上升通道 |
| 最新ROE ≈ 建仓时ROE（±5%） | ⚠️ 部分漂移 | ROE持平，需关注 |
| 最新ROE < 建仓时ROE（下降<10%） | ⚠️ 部分漂移 | 小幅下降，需确认是否为临时因素 |
| 最新ROE < 建仓时ROE（下降≥10%） | 🔴 完全漂移 | ROE明显下降，景气可能见顶 |
| ROE连续3季下降 | 🔴 完全漂移 | **郑希"ROE向上是重力加速度"被证伪** |

#### H5：增速加速度假设验证

**验证逻辑**（基于李进二阶导思维 + 理念文档矛盾二化解方案）：

以**连续3个季度的营收增速趋势**判定加速度方向：

| 连续3季趋势 | 加速度方向 | 判定 |
|-------------|-----------|------|
| 连续3季增速上升 | 🟢 正加速 | ✅ 成立 |
| 增速先升后平 | 🟡 平缓 | ⚠️ 部分漂移 |
| 连续3季增速下降 | 🔴 负加速 | **完全漂移**（增速放缓即估值中枢下移） |
| 正负交替 | 🟡 波动 | ⚠️ 部分漂移（标记为噪音） |

**QoQ/YoY 双口径（对齐开发方案 6.3）**：

- **QoQ（环比增速）**：反映最新季度动能，敏感度高但噪音大
- **YoY（同比增速）**：消除季节性，趋势更清晰

### 第六步：implied-growth 交叉验证（新增）

**目的**：将市值隐含的业绩增速与实际景气增速交叉验证，判断市场定价是否合理。

**计算方法**：

```bash
python tools/common/financial_rigor.py implied-growth \
  --market-cap {当前市值} \
  --target-pe {合理PE} \
  --net-margin {净利率} \
  --ttm-revenue {TTM营收} \
  --guidance-growth {管理层指引增速上限}
```

**红/黄/绿灯判定**：

| 灯色 | 判定条件 | 含义 |
|------|---------|------|
| 🟢 绿灯 | 隐含增速 ≤ 实际景气增速 | 市场定价合理或偏低 |
| 🟡 黄灯 | 隐含增速 > 实际景气增速（差距<10%） | 市场定价略偏高，但在可接受范围 |
| 🔴 红灯 | 隐含增速 > 实际景气增速（差距≥10%） | 市场定价透支，估值泡沫风险 |

**与漂移等级的交叉矩阵**：

| | 🟢 绿灯 | 🟡 黄灯 | 🔴 红灯 |
|---|---------|---------|---------|
| **🟢 未漂移** | 最佳持有状态 | 持有但关注估值 | 减机动仓（估值偏高但逻辑完好） |
| **🟡 轻微漂移** | 持有观察 | 减机动仓 | 大幅减机动仓 |
| **🟠 显著漂移** | 减机动仓+底仓设止损 | 大幅减仓 | 触发 exit-signal |
| **🔴 严重漂移** | 触发 exit-signal | 触发 exit-signal | **立即触发 exit-signal** |

### 第八步：与 valuation-thermometer 联动（新增）

**目的**：漂移等级作为估值温度的修正因子。

**修正规则**：

| 漂移等级 | 估值温度修正 | 说明 |
|---------|------------|------|
| 🟢 未漂移 | 无修正 | 景气逻辑完好，估值判定维持原档 |
| 🟡 轻微漂移 | **-0.3档** | 景气逻辑微瑕，估值容忍度略微降低 |
| 🟠 显著漂移 | **-0.5档** | 核心假设受损，估值应更保守 |
| 🔴 严重漂移 | **-1.0档** | 逻辑全面证伪，估值判定大幅下调 |

> **修正幅度上限**：±1.0档，防止过度修正。例如原估值温度"合理"（0.8~1.2），严重漂移修正-1.0档后变为"显著低估"档以下，此时不应加仓，而应触发 exit-signal。

**阈值口径说明**：

> 理念文档 V2.0 对 PEG 阈值有三处表述：第一部分"PEG<1 低估、1~1.2 合理、>1.5 高估"；第三部分"合理区间 0.8~1.2、<0.8 绝佳买点、>1.5 高估"；备忘卡"PEG<1.2 买入、>1.5 减仓"。本技能对齐 valuation-thermometer V1.0 的五档口径：`<0.8` 显著低估 / `0.8~1.2` 合理 / `1.2~1.5` 偏贵 / `>1.5` 高估 / `>2` 严重透支。其中"1.2~1.5 偏贵"档为衔接 1.2 买入线与 1.5 高估线而新设的过渡档。

### 第十一步：矛盾化解方案融入（新增）

将理念文档 V2.0 第五部分"四大矛盾化解方案"融入漂移检测逻辑：

#### 矛盾一：买点冲突（止损 vs 越跌越买）

> **底仓/机动仓区间**：底仓占总仓位的 60%~80%（长线核心，赚企业1~3年成长的钱），机动仓占 20%~40%（平滑波动，赚估值波动的钱）。单只个股初始≤10%，逻辑验证后≤15%，绝对上限≤20%，单一行业≤40%。

| 漂移等级 + 仓位状态 | 决策规则 |
|-------------------|---------|
| 🟢 未漂移 + 建仓初期（<50%仓位） | 若股价下跌>8%，按欧奈尔规则止损，不加仓 |
| 🟢 未漂移 + 底仓已建（≥50%仓位） | 若股价下跌10%~20%且三维度（产业/管理层/财务）未恶化，可在估值下限加仓 |
| ≥🟡 轻微漂移 + 任意仓位 | 禁止加仓，无论跌幅多大 |
| 🔴 严重漂移 + 任意仓位 | **立即清仓，不存在"越跌越买"** |

#### 矛盾二：单季噪音 vs 趋势拐点

| 数据类型 | 判定规则 |
|---------|---------|
| 单季数据异常（如单季增速骤降） | **不判拐点**，标记为"噪音"，等待下季确认 |
| 连续3季数据趋势一致（如连续3季减速） | **确认拐点**，判定为完全漂移 |
| 连续2季数据异常但第3季反弹 | 降级为"部分漂移"，继续观察 |

#### 矛盾三：长期持有 vs 中期兑现

| 条件 | 决策 |
|------|------|
| 持有 < 4季度 + 漂移等级 ≤ 🟡 | 继续持有，等待逻辑兑现 |
| 持有 ≥ 4季度 + 漂移等级 ≥ 🟡 | **触发时间止损（P2）**，减仓至观察仓 |
| 持有 ≥ 4季度 + 漂移等级 🟢 | 不触发时间止损，逻辑仍在兑现 |

#### 矛盾四：分散 vs 集中

| 组合状态 | 漂移后操作 |
|---------|----------|
| 单只个股漂移 + 同行业其他标的正常 | 仅减该标的机动仓，行业仓位不变 |
| 同行业多只标的同时漂移 | 行业级别减仓（映射 mid-industry-research 行业级漂移） |
| 漂移后替换标的需满足 | 新标的 PEG 显著更低 + 产业趋势更强 + 每季度最多1次 |

### 第十二步：风控硬编码（新增）

以下规则为**硬性规则**，不允许 AI 自由裁量或"灵活解读"：

| 编号 | 规则 | 说明 |
|------|------|------|
| R-1 | 连续3季负加速 → 必须判完全漂移 | 禁止以"基数效应""季节性"等理由豁免 |
| R-2 | 单季负加速 → 不得判拐点 | 必须等待连续3季确认 |
| R-3 | 持有≥4季度 + 漂移≥🟡 → 必须触发时间止损（P2） | 禁止以"长期看好"为由豁免 |
| R-4 | 漂移等级 🔴 → 必须触发 exit-signal | 禁止AI"综合判断"后降级 |
| R-5 | PEG > 1.5 → 必须标注"估值高估" | 对齐 valuation-thermometer V1.0 |
| R-6 | PEG > 2.0 → 必须标注"严重透支" | 对齐 valuation-thermometer V1.0 |
| R-7 | PE 历史分位 > 90% → 必须标注"估值极端" | 对齐 valuation-thermometer V1.0 |
| R-8 | 修正幅度上限 ±1.0档 | 漂移对估值温度的修正不得超过±1档 |
| R-9 | 禁止跳过P0检查 | 若发现治理线索，必须标注并建议运行 exit-signal |
| R-10 | 利润增速负+营收增速正 → 必须标注"利润营收不匹配" | 费用失控预警 |

> **核心原则**：所有硬性规则的输出必须包含明确的规则编号引用（如"触发 R-1"），确保可审计、可追溯。

## 决策优先级速查卡（新增）

快速参考，对齐理念文档 V2.0 "决策优先级金字塔"：

```
P0 治理一票否决 → 管理层失信/造假/立案 → 立即清仓（本技能附带检测）
P1 硬止损       → 亏损8%~10%           → 无条件止损（trend-momentum-scan 覆盖）
P2 逻辑止损     → 连续2季低于预期/时间止损 → 减仓或清仓（本技能核心覆盖）
P3 产业景气拐点  → 渗透率减速/ROE拐头    → 减机动仓（本技能核心覆盖）
P4 估值透支     → PEG>1.5减机动/PEG>2.0清机动（valuation-thermometer 覆盖）
P5 性价比替换   → 其他标的更优           → 调仓（portfolio-review 覆盖）
```

**检查顺序**：P0 → P1 → P2 → P3 → P4 → P5，命中即停，禁止跳过P0。

## 注意要点

### 1. 与长期 `thesis-drift` 的本质区别

| 维度 | 长期 `thesis-drift` | **中期 `mid-thesis-drift`** |
|------|-------------------|---------------------------|
| **核心追问** | "护城河还在吗？" | **"景气假设还在吗？"** |
| **检测维度** | 商业模式、竞争格局、管理层 | **渗透率/订单/ROE/毛利率/加速度/地缘政治** |
| **判定标准** | 护城河崩塌为漂移 | **≥4项景气假设被证伪为严重漂移** |
| **检测频率** | 年度/半年度 | **季度** |
| **时间止损** | 可容忍数年业绩平淡 | **满4季度逻辑未兑现即触发P2** |
| **参考大师** | 巴菲特（护城河评估） | **郑希（景气跟踪）+ 李进（二阶导）** |

### 2. 禁止行为

- ❌ 将"护城河评估"作为漂移检测的核心
- ❌ 使用"永续经营"等长期框架术语
- ❌ 忽视加速度（二阶导）信号
- ❌ 单季数据判拐点（必须连续3季）
- ❌ "我认为逻辑已经变了"等无数据支撑的主观判断
- ❌ 漂移等级 🔴 时不触发 exit-signal（硬性规则 R-4）
- ❌ 使用 `--mode` 参数（统一使用 `--horizon`）

### 3. 检查频率

| 模式 | 触发时机 | 适用场景 |
|------|----------|----------|
| **季度检查** | 每季报发布后 | 常规逻辑漂移检测（必做） |
| **事件驱动** | 股价异动、行业重大变化、地缘政治冲击 | 评估逻辑是否被突发事件破坏 |
| **时间止损检查** | 持有满4季度时 | 专项时间止损检测 |

### 4. 数据不足处理

| 场景 | 处理方式 |
|------|----------|
| 无法获取最新渗透率数据 | H1标记"数据不足，不纳入漂移计数"，在报告中标注 |
| 合同负债数据缺失（部分港股/美股） | H2标记"数据不足"，用订单数据替代（如有） |
| 论文中某假设未明确写出 | 标记"论文中未找到该假设，不纳入计数" |
| qoq-accelerator 报告不存在 | 本技能独立计算加速度，标注"未消费qoq-accelerator报告" |
| trend-momentum-scan 报告不存在 | 跳过技术面联动，标注"技术面数据不可用" |

## 局限性

1. **论文质量依赖**：漂移检测质量取决于建仓论文的假设是否清晰可量化
2. **渗透率数据可得性**：部分新兴行业渗透率数据可能不完整
3. **季度数据滞后**：季报发布有1-2个月滞后，检测可能滞后于现实
4. **行业差异**：六大假设框架对景气成长型行业更适用，周期行业需调整权重
5. **地缘政治量化困难**：H6维度较难精确量化，更多依赖定性判断
6. **不构成投资建议**：本技能仅为逻辑验证工具，需结合其他技能综合决策
7. **阈值硬性规则的一刀切**："偏差20%""偏差15%"等阈值为硬性规则，可能存在一刀切问题——实际使用中可结合行业特性在允许范围内微调
