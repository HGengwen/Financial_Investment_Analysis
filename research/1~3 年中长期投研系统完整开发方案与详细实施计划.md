## 一、项目概述

### 1.1 项目背景

当前系统（V2.0）已实现**10 年长期价值投资**框架，包含 **21 个 SKILL.md 技能**（行业研究 3、公司深度 4、买入决策 4、财报跟踪 2、持仓管理 4、基础工具与内容输出 4、未上市研究 1）、完整的三市场数据工具链（A 股/港股/美股）、以及四位投资大师（欧奈尔、林奇、郑希、李进）分析体系（针对1~3年中长期投研分析）。

其中 `mid-trend-tech-screen` 技能（原 `trend-tech-screen`）及 `tools/specialized/trend_tech_screen.py` 工具**已先行落地 1~3 年景气筛选能力**，且 `tools/common/financial_rigor.py` 已内置 PEG/PSG/PE 分位等估值命令。因此，本方案的核心不是"从零构建"，而是**补齐中期投研闭环的剩余环节**：估值温度计、季度加速度、持仓动量体检、中期逻辑漂移检测、卖出信号触发，以及贯穿全链的导航与路由。

### 1.2 项目目标

| 维度 | 目标 |
| --- | --- |
| 功能目标 | 提供从"行业景气扫描 → 个股验证 → 估值择时 → 持仓管理 → 卖出触发"的完整 1~3 年投研闭环 |
| 输出形态 | Markdown 结构化研究报告（不实现复杂 UI） |
| 性能目标 | 单标的完整分析 ≤ 3 分钟；行业扫描（30 家）≤ 15 分钟 |
| 兼容目标 | 与长期系统共享数据层/工具层，逻辑层物理隔离，互不干扰 |
| 质量目标 | 卖出决策与理念文档 V2.0"决策优先级金字塔"完全对齐，风控规则硬编码 |

### 1.3 项目范围

**包含**：
- 6 个新增中期技能（`mid-` 前缀 2 个 + 功能命名 4 个，与长期技能同级存放）
- 2 个共享技能参数化增强（`--horizon` 条件分支）
- 1 份独立的《证券AI中长期（1~3年）价值投资研究工作步骤.md》导航文档
- 路由决策规则建立与实施（含 `mid-` 前缀显式调用识别）

**不包含**：UI 开发、自动交易、高频数据接入、长期技能核心逻辑修改。

## 二、核心理念与设计原则

### 2.1 三大核心理念（与长期投资的区别）

| 理念 | 内涵 | 与长期投资的区别 |
| --- | --- | --- |
| 产业景气是 β | 选赛道比选个股更重要，渗透率 10%~30% 为黄金区 | 长期投资更看重护城河永续性 |
| 估值是温度计 | PEG 与 PE 历史分位决定买卖时点，而非 DCF 绝对估值 | 长期用 DCF 看内在价值，中期用 PEG 看估值弹性 |
| 时间是法官 | 持有满 4 个季度未兑现即触发替换建议 | 长期可容忍数年业绩平淡 |

### 2.2 设计原则

1. **分支独立，绝不修改长期技能核心文件**：中期特有技能新建 `mid-` 前缀文件，与长期技能在 `.trae/skills/` 同级存放，不采用子目录隔离。
2. **数据层完全共享**：`tools/` 下 Python 工具零改动复用。
3. **路由显式化**：按持有周期关键词显式路由；`mid-` 前缀显式调用优先匹配。
4. **文档双轨制**：长期/中期各自独立导航文档。
5. **风控硬编码**：止损、时间止损、破位、估值透支作为硬性规则写入 Prompt，不允许 AI 自由裁量。
6. **命名一致**：存量中期能力 `trend-tech-screen` 统一重命名为 `mid-trend-tech-screen`，消除无前缀特例。

### 2.3 四位大师在中期框架中的角色重定位

| 大师 | 长期角色 | 中期角色（调整后） |
| --- | --- | --- |
| 欧奈尔 | 底线止损（8%） | **提升至最高风控级**：8%~10% 硬止损 + 突破新高买入 + 抛售日识别 |
| 林奇 | 常识选股起点 | **增加 GARP 维度**：PEG<1.2 合理，关注"增速与估值匹配" |
| 郑希 | ROE 拐点定方向 | **核心主轴**：全球产业链景气追踪 + ROE 拐点 + 供给创造需求 |
| 李进 | 渗透率定位产业阶段 | **保留并强化**：15% 临界点 + 渗透率 50% 后考虑兑现 + 二阶导思维（增速的加速度） |

### 2.4 四大矛盾与化解方案（吸收理念文档 V2.0）

| 矛盾 | 双方立场 | 化解方案 |
| --- | --- | --- |
| 止损 vs 越跌越买 | 欧奈尔 8% 无条件止损；林奇/郑希好公司下跌是机会 | 引入"仓位状态"：建仓初期（<最终仓位 50%）止损优先；底仓已立且三维度（产业/管理层/财务）未恶化时，才在估值下限加仓；逻辑证伪立即清仓 |
| 分散 vs 集中 | 林奇极分散；欧奈尔/郑希/李进相对集中 | 取"3+2"中间路线：3 只核心（各 12%~15%）+ 2~3 只卫星（各 5%~8%），行业分散、个股集中 |
| 单季噪音 vs 趋势拐点 | 单季数据波动大；趋势拐点需连续验证 | 以**连续 3 个季度数据趋势**区分波动与拐点 |
| 长期持有 vs 中期兑现 | 长期可数年平淡；中期要求节奏 | 满 4 季度逻辑未兑现触发时间止损 |

### 2.5 决策优先级金字塔（卖出决策的"宪法"，`exit-signal` 的底层依据）

| 优先级 | 触发条件 | 决策 | 思想来源 |
| --- | --- | --- | --- |
| 第一（一票否决） | 管理层诚信问题、财务造假实锤、监管立案 | 立即清仓，不看估值趋势 | 李进（治理） |
| 第二（硬止损） | 单笔亏损 8%~10%，且无基本面反转信号 | 无条件止损 | 欧奈尔 |
| 第三（逻辑止损） | 连续 2 季业绩低于预期，且产业景气未改善；或持有满 4 季度逻辑未兑现（时间止损） | 减仓或清仓 | 林奇+郑希 |
| 第四（产业景气） | 前三项未触发，但渗透率/ROE 出现拐点 | 按景气方向调仓 | 李进+郑希 |
| 第五（估值） | 以上未触发，仅估值水位偏高 | 底仓不动、机动仓调整 | 林奇 |

**核心原则**：先保命（防造假/止损），再谈收益（景气/估值）。此金字塔将直接映射为 `exit-signal` 的 P0~P5 检查顺序（见 6.6）。其中"时间止损（满 4 季度未兑现）"与"连续 2 季低于预期"**同属第三级**，归入 P2。

## 四、兼容性方案：一套引擎，两套驾驶舱

### 4.1 架构决策

**结论**：不拆分两个系统，采用"一套代码基座 + 两种策略模式"。

**依据**：数据层（akshare/缓存）完全共享，拆分双倍维护；用户常同时持有长期底仓与中期机动仓，需统一组合管理；工具库完全通用。

### 4.2 物理隔离方案（`mid-` 前缀 + 同级存放 + 存量重命名）

**核心原则**：中期特有技能一律新建文件，不改动任何长期技能核心文件；文件存放于 `.trae/skills/` 根级，与长期技能同级，通过 `mid-` 前缀区分，不建子目录。

**命名规则**：

| 类型 | 命名方式 | 示例 |
| --- | --- | --- |
| 中期行业研究 / 漂移检测 | `mid-` 前缀 | `mid-industry-research`、`mid-thesis-drift` |
| 中期专用功能（无长期对应物） | 功能命名，无前缀 | `valuation-thermometer`、`qoq-accelerator`、`trend-momentum-scan`、`exit-signal` |
| 存量中期能力（历史遗留） | 统一重命名加 `mid-` 前缀 | `trend-tech-screen` → `mid-trend-tech-screen` |

**为何不建子目录**：现有 21 个技能均为 `.trae/skills/{skill-name}/SKILL.md` 平铺结构，技能加载机制按根级目录识别。新建子目录（如 `.trae/skills/mid-term/`）会破坏既有加载约定，增加迁移成本。前缀区分是零风险、零迁移的方案。

**前缀冲突处理**：存量中期技能 `trend-tech-screen` 统一重命名为 `mid-trend-tech-screen`（F-7），由 Sprint 0 执行目录重命名并同步更新 SKILL.md/README.md 及全部引用文档（CLAUDE.md、长期导航文档、docs/ 指南、tools-scripts 参考文档、tools/tests 注释）；路由上归入中期链（见附录 A）（已完成统一命令）。

### 4.3 共享技能的条件分支（`--horizon`）

## 六、新增与修改技能清单

### 6.1 `mid-industry-research` — 中期行业景气深度研究（`mid-` 前缀）

**目标**：对 1~3 年景气赛道做深度研究，输出"景气阶段 + 渗透率位置 + 头部公司 + 地缘风险"四维判断。

**核心逻辑**（吸收理念文档 V2.0 第一部分"第 1 步赛道选择"）：

- 产业空间：TAM ≥ 1000 亿，未来 3 年复合增速 ≥ 20%；
- 渗透率位置：10%~30% 为黄金区（李进"15% 临界点"理论）；
- 业绩兑现度：连续 2 季度营收增速 > 行业平均、毛利率稳定或提升；
- 地缘政治风险敞口：海外收入依赖度、供应链可控性、制裁清单风险、本地化对冲能力。

**数据依赖**：`tools/common/anysearch.py --tag finance`（券商研报/行业数据）、`doubao_search.py --finance`（实时政策）、`tools/specialized/in_research_scan.py`（在研项目）。

**输出**：`reports/{行业名}-mid-industry-{YYYYMMDD}.md`。

### 6.2 `valuation-thermometer` — 估值温度计

**目标**：用 PEG / PSG / PE 历史分位 / implied-growth 四工具给出"低估/合理/偏贵/高估/透支"五档温度，并映射到底仓/机动仓操作。

**核心阈值**（对齐理念文档 V2.0 第三部分 + F-9）：

| 档位 | PEG 区间 | 操作建议 |
| --- | --- | --- |
| 显著低估 | < 0.8 | 绝佳买点，底仓可加 |
| 合理 | 0.8 ~ 1.2 | 合理买入区间，先建 1/3 底仓 |
| 偏贵 | 1.2 ~ 1.5 | 机动仓观望（本档为方案新设过渡档） |
| 高估 | > 1.5 | 机动仓减持 |
| 严重透支 | > 2 | 加速清机动仓 |

> **阈值口径说明**：理念文档 V2.0 对 PEG 阈值有三处表述——第一部分"PEG<1 低估、1~1.2 合理、>1.5 高估"（第 144 行）；第三部分"合理区间 0.8~1.2、<0.8 绝佳买点、>1.5 高估"（第 235 行）；备忘卡"PEG<1.2 买入、>1.5 减仓"（第 410 行）。本表以第三部分"0.8~1.2 合理区间"为主锚，将 0.8~1.2 档操作建议对齐为"合理买入区间、先建 1/3 底仓"（与第一部分第 150 行"合理买入区间先建 1/3 底仓"、备忘卡"PEG<1.2 买入"一致），而非"持有"；"1.2~1.5 偏贵"档为衔接 1.2 买入线与 1.5 高估线而**新设的过渡档**，理念文档无此档。

**数据依赖（零开发，直接调用已内置命令）**：

```bash
python tools/common/financial_rigor.py peg --pe 25 --growth 20
python tools/common/financial_rigor.py ps-g --ps 5 --revenue-growth 30
python tools/common/financial_rigor.py pe-percentile --pe-series "..." --current 25
python tools/common/financial_rigor.py implied-growth --market-cap 1000 --target-pe 25 --net-margin 0.15 --ttm-revenue 100 --guidance-growth 0.3
```

**输出**：`reports/valuation/{公司名}-valuation-{YYYYMMDD}.md`。

### 6.3 `qoq-accelerator` — 季度加速度分析

**目标**：用连续 3 个季度财务数据判断"增速的加速度"（二阶导），区分短期波动与趋势拐点（理念文档矛盾二化解方案）。

**核心逻辑**：

- 营收增速环比（QoQ）与同比（YoY）双口径；
- 利润增速 vs 营收增速匹配度（警惕费用失控）；
- 连续 3 季度趋势判定：连续加速 = 景气向上；连续减速 = 趋势拐点预警。

**数据依赖（零开发，F-10 修正科目归属）**：

```bash
python tools/a_share/stock_financial.py --code {code} --indicator ROE,毛利率,营业总收入,归母净利润
python tools/a_share/stock_financial.py --code {code} --advanced   # 合同负债/存货/研发费用等先行指标
```

**输出**：`reports/{公司名}/{公司名}-qoq-{YYYYMMDD}.md`。

### 6.4 `trend-momentum-scan` — 持仓动量体检

**目标**：对**已持仓**标的做纯技术面体检（SMR/RSI50/MA50/MA200），判断趋势是否走坏，触发技术破位预警（F-6 与 `mid-trend-tech-screen` 选股区分）。

**核心逻辑**：

- SMR（6 个月相对强度）正向/负向；
- RSI50 超买/超卖；
- MA50 vs MA200 多空排列；
- 结合 `--auto-peers` 板块截面判断相对强弱。

**数据依赖（零开发）**：

```bash
python tools/a_share/stock_quote.py --code {code} --momentum --auto-peers
```

**输出**：`reports/{公司名}/{公司名}-momentum-{YYYYMMDD}.md`。

### 6.5 `mid-thesis-drift` — 中期逻辑漂移检测（`mid-` 前缀）

**目标**：对比新旧中期报告，基于证据判定"景气逻辑是否漂移"（对标长期 `thesis-drift`，但聚焦 1-3 年景气变量）。

**核心逻辑**：

- 抽取景气假设（渗透率、订单、ROE 趋势、毛利率）；
- 用最新季度数据逐条验证假设是否仍成立；
- 输出"漂移/未漂移"证据链。

**数据依赖**：`qoq-accelerator` + `trend-momentum-scan` 的输出 + 搜索工具。

**输出**：`reports/{公司名}/{公司名}-mid-drift-{YYYYMMDD}.md`。

### 6.6 `exit-signal` — 卖出信号（P0~P5 六级优先级）

**目标**：将理念文档"决策优先级金字塔"（五级）+ "一页纸备忘卡"的卖出条目，映射为**硬编码**的 P0~P5 六级检查顺序，不允许 AI 自由裁量。

**P0~P5 映射表**（对齐理念文档 V2.0 第五部分"决策优先级金字塔" + 第六部分"备忘卡" + F-5）：

| 级别 | 触发条件 | 决策 | 思想来源 |
| --- | --- | --- | --- |
| P0 治理一票否决 | 管理层失信、财务造假实锤、监管立案 | 立即清仓，不看估值趋势 | 李进（治理） |
| P1 硬止损 | 单笔亏损 8%~10%，且无基本面反转信号 | 无条件止损 | 欧奈尔 |
| P2 逻辑止损 | 连续 2 季业绩低于预期，且产业景气未改善；**或持有满 4 季度逻辑未兑现（时间止损）** | 减仓或清仓 | 林奇+郑希 |
| P3 产业景气拐点 | 渗透率减速 / ROE 拐头向下 | 减机动仓 | 李进+郑希 |
| P4 估值透支 | PEG > 1.5（减机动仓）；PEG > 2（加速清机动仓） | 减/清机动仓 | 林奇 |
| P5 性价比替换 | 其他标的 PEG 显著更低且产业趋势更强 | 调仓（每季度最多 1 次） | 机会成本 |

**关键设计**：理念文档"时间止损（满 4 季度未兑现）"在金字塔中无独立层级（仅见于风险表与备忘卡"补充"条目），本方案将其**归入 P2**，与"连续 2 季低于预期"并列，消除"五级金字塔 vs 六级 P0~P5"的层级歧义。

**执行顺序**：从 P0 到 P5 依次检查，命中即停止，输出对应动作（硬编码，禁止跳过 P0）。

**输出**：`reports/exit-signals/{公司名}-exit-{YYYYMMDD}.md`。

## 九、技术实现要点

### 9.1 数据层零改动复用

所有中期技能直接调用 `tools/` 下既有工具，不新增任何 Python 代码。

### 9.2 精确计算

市值、估值、跨源校验一律走 `tools/common/financial_rigor.py`，禁止 LLM 心算。

### 9.3 风控硬编码

止损 8%~10%、时间止损 4 季度、PEG 阈值、底仓/机动仓区间作为硬性规则写入 Prompt，不允许 AI 自由裁量。

### 9.4 输出形态

全部为 Markdown 结构化报告，不实现 UI。

### 9.5 多源交叉验证

关键财务数据至少两个独立来源，误差 >1% 标记（遵循研究质量规则）。
