### 3.3 🔧 核心算法升级（`tools/common/financial_rigor.py`）

#### 3.3.1 `peg_ratio()` — PEG 评级口径 3 档→5 档

**变更前（3 档）**：

| PEG 范围 | 评级 |
| --- | --- |
| `< 1` | 低估 |
| `1 ≤ PEG ≤ 1.5` | 合理 |
| `> 1.5` | 高估 |
| `≥ 3` | 警告信息 |

**变更后（5 档）**：

| PEG 范围 | 评级 | 标识 |
| --- | --- | --- |
| `< 0.8` | **显著低估** | ✅ |
| `0.8 ≤ PEG ≤ 1.2` | **合理** | ✅ |
| `1.2 < PEG ≤ 1.5` | **偏贵** | ⚠️ |
| `1.5 < PEG ≤ 2.0` | **高估** | 🔴 |
| `> 2.0` | **严重透支** | 🔴 |
| `> 2` | 警告信息（修改） | — |

> 📌 关键含义：原 3 档边界（1.0/1.5）改为更细的 5 档边界（0.8/1.2/1.5/2.0），与 `valuation-thermometer` 五档温度表完全对齐。

#### 3.3.2 `pe_percentile()` — 分位计算从 `≤` 改为 `<`

**变更前**：

```
below = sum(1 for v in hist if v <= current_pe_val)
```

**变更后**：

```
# 分位 = 历史中 < 当前PE 的比例 (0-100)，历史最小值→0%
below = sum(1 for v in hist if v < current_pe_val)
```

> 📌 关键含义：保证「历史最小值→分位 0%」的硬约束生效，测试用例 `test_pe_percentile_high` 从 `100.0%` 修正为 `80.0%`（\[20,25,30,28,26\] 中 30 是最大值，仅 30 等于自身，4 个 < 30，故 4/5=80%）。

### 3.4 🛡️ `tools/common/pdf_extract.py` 关键 IO 修复

**变更原因**：

旧代码通过 `io.TextIOWrapper` 替换 `sys.stdout` 对象，导致 `pytest capsys` 无法捕获输出（pytest 失败时测试显示 PASS）。新代码用 `reconfigure(encoding="utf-8")` 原地修改流编码，保留对象引用。

**变更前后对比**：

```
- # 将 stdout 和 stderr 均包装为 UTF-8 编码，避免 Windows 控制台 GBK 编码
- if hasattr(sys.stdout, "buffer"):
-     sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8")
- if hasattr(sys.stderr, "buffer"):
-     sys.stderr = io.TextIOWrapper(sys.stderr.buffer, encoding="utf-8")
+ # 使用 reconfigure 原地修改编码，而非替换 sys.stdout/sys.stderr 对象，
+ # 以保留调用方（如 pytest capsys）对标准流的捕获，避免输出丢失。
+ for _stream in (sys.stdout, sys.stderr):
+     try:
+         _stream.reconfigure(encoding="utf-8")
+     except (AttributeError, ValueError):
+         pass
```

## 4\. 影响与风险评估

### 4.1 ⚠️ 破坏性变更

| 变更 | 影响 | 缓解 |
| --- | --- | --- |
| **PEG 评级 3 档→5 档** | 任何依赖 `peg_ratio` 输出 `rating` 字段的下游解析/报告需同步更新 | 已同步更新 `tests/common/test_financial_rigor.py` 用例；下游 5 个中期技能（valuation-thermometer/mid-industry-funnel/mid-investment-checklist/mid-industry-research/exit-signal）均使用五档口径引用 |
| **`pe_percentile` 分位计算** | 测试 `test_pe_percentile_high` 期望值从 100.0% 改为 80.0% | 已同步修复测试断言 |
| **报告路径 `{公司名}-research-...` → `{公司名}-investment-research-...`** | 任何外部脚本/链接引用旧路径会 404 | 仅 4 处文档同步修改；无生产路径数据 |
| **`sys.stdout` 替换 → `reconfigure`** | 旧 PDF 提取脚本可能不再强制 stdout 为 UTF-8 文本流 | `reconfigure` 在原对象上原地修改，行为等价；不支持的 stream 用 try/except 兜底 |
