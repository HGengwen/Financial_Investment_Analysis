# GARP 宏观环境适配：三表校准（1~5 年独立档）

对 $ARGUMENTS 执行《中长期价值成长（GARP）投资框架》**第五部分·四「宏观环境适配」**，回答一个问题：

> **当前宏观环境下，我的估值容忍度该放宽还是收紧？该留多少现金、单只最多押多少？**

> **独立档声明**：**本技能属 GARP 独立档（1~5 年，五大师：费雪 / 林奇 / 郑希 / 李进 / 欧奈尔），与 1~3 年中期链、10 年长期链口径物理隔离、功能互补。** 本技能只调用 `macro_calibrator.py` 完成查表与校准，**一律不心算**；只为下游**提供参数**，不判断个股价值、不产出买卖时机。

> 💬 **李进式提醒**："系统的稳健性来自参数随环境切换，而不是一套参数走到底。宏观不给方向，只给你该出多少钱、冒多大风险。"

> 💬 **费雪式提醒**："留现金不是看空，是为了在别人被迫卖出时，你还有子弹。"

---

## 设计理念与定位

框架前文的估值区间、仓位上限、现金比例均以「中性宏观环境」为基准设定，但利率、信用与经济周期会系统性改变成长股的**估值中枢**与**风险偏好**，因此**框架参数必须随宏观环境动态校准，而非当作常数使用**。

本技能的定位是**参数时变调节器**——它只做两件事：

| 调节对象 | 输出参数 |
| --- | --- |
| **估值容忍度** | 调整后 PEG 合理买入上限（含低估 / 高估阈值与「合理偏贵」中间带） |
| **仓位尺度** | 现金仓位下限 + 单只上限（初始 / 验证后 / 绝对三档）+ 单一行业上限 |

### 本技能的三条硬纪律

| # | 纪律 | 原因 |
| --- | --- | --- |
| 1 | **工具判定，禁止心算** | 三表参数与校准结论一律由 `macro_calibrator.py` 产出，任何自行推算的 PEG 区间 / 仓位上限均属违规 |
| 2 | **stage 收口优先于分表** | 框架明示以「（一）+（二）算参数、（三）美林矩阵总收口」；出现冲突时必须收口为**单一**结论（见「三表收口规则」） |
| 3 | **软判定必须人工确认** | `data` 的阶段判定为非权威启发式（`manual_review=true` / `confidence=低`），未经确认前所有参数只能标为「暂定」 |

## 边界声明（本技能核心，须在每次输出中体现）

框架原文明确三条边界，本技能严格遵从：

1. **不替代个股基本面判断** —— 宏观决定当前该出多少钱、冒多大风险；**内在价值才是长期收益的来源**。本技能不评估公司盈利、治理、景气与护城河。
2. **不作为择时清仓的依据** —— 宏观**不产出卖出 / 清仓信号**，也**不向卖出类技能转出任何信号**；卖出一律交 `garp-exit`（GARP 五级卖出）。
3. **数据需按月 / 季更新** —— 宏观参数是**时变**的，禁止刻舟求剑；每次输出必须标注数据截止日期，过期须刷新复跑。

## 适用场景 / 不适用场景

| 类型 | 场景 |
| --- | --- |
| **适用** | ① 建仓前确定**仓位尺度**（现金下限 / 单只上限 / 行业上限）；② 定期（按月 / 季）**参数复核**，检查既有持仓是否超出当前宏观上限；③ 为估值环节提供**宏观校准后的 PEG 区间**；④ 极端阶段（衰退 / 滞胀）的**仓位收紧** |
| **不适用** | ① 个股价值判断（转 `garp-valuation` / `garp-investment-research`）；② 买入门槛与五大支柱（转 `garp-investment-checklist`）；③ **卖出 / 清仓决策**（转 `garp-exit`）；④ 地缘政策前置（转 `garp-geo-policy`）；⑤ 组合集中度与相关性分析（转 `garp-portfolio-review`） |

## 执行流程（六步）

### 第一步：确认参数与数据基准

先运行 `date` 确认当天日期，作为「数据截止日期」基准（全局规则 1）。

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `{市场}` | 目标市场：`A股` / `港股` / `美股`，决定 stage 判定的宏观数据源（见「按市场分层的 stage 判定输入」） | `A股` |
| `--stage` | 用户直接指定美林四档（`衰退`/`复苏`/`过热`/`滞胀`），填则**跳过软判定**直接查表 | 无 |
| `--peg` | 标的当前调整后 PEG（>0），填则执行标的级校准 | 无 |
| `--current-cash` | 当前现金占总资产 %（0~100），配合 `--peg` | 无 |
| `--single-stake` | 当前标的占总资产 %（0~100），配合 `--peg` | 无 |
| `--stake-tier` | 单只上限档位 `initial` / `verified` / `absolute` | `verified` |
| `--no-cache` | 强制刷新宏观数据缓存（透传 `data --no-cache`） | 关闭 |

未给 `{市场}` 时取默认 `A股` 并**显式声明**；不要默默假设。

### 第二步：宏观指标取数与阶段软判定

```bash
python tools/specialized/macro_calibrator.py data            # A股：中国宏观六指标
python tools/specialized/macro_calibrator.py data --no-cache # 强制刷新缓存
```

**读回并展示**（缺一不可）：

| 字段 | 用途 |
| --- | --- |
| `data_ts` | 数据截止日期（写入报告头部） |
| `rate_stage` / `econ_stage` | 利率阶段 / 经济阶段**软判定**结果 |
| `rate_stage.basis` / `econ_stage.basis` | 判定依据（须展示，供人工判断） |
| `confidence` / `manual_review` | **原样透传**（非权威标注） |
| `indicators` | 六项指标现值与 `as_of` |
| `source` / `degraded` / `cache_status` | 来源 / 降级 / 缓存状态（`stale` 或 `degraded=true` 时提示 `--no-cache` 刷新） |
| `search_hints` | 指标缺失时的检索提示（按提示用搜索工具补齐） |

- **按 `{市场}` 分层补充锚**：见下节。
- `data` 仅覆盖中国宏观指标，**不得**用其结果直接充当非 A 股市场的 stage。

### 第三步：人工确认闸门（stage 定稿，强制）

向用户呈现：**软判定结果 + `basis` + 六指标现值 + 数据截止日期 + 非权威标注**，请用户确认或修正宏观阶段。

| 情形 | 处置 |
| --- | --- |
| 用户确认软判定 | stage 定稿；报告中标注「软判定经人工确认」 |
| 用户修正为其他阶段 | 以用户结论为 stage；报告中标注「经人工修正」 |
| 用户提供 `--stage` | 直接采用；标注「stage 由用户提供，未做数据核验」 |
| **尚未确认** | 所有下游参数**一律标注「暂定（待 stage 确认）」**，不得作为最终校准依据 |

---

### 第四步：三表查表（工具调用，禁止心算）

```bash
python tools/specialized/macro_calibrator.py stage --stage {已确认阶段} --markdown
```

- 读回三段参数：`rate_stage`（利率表）/ `econ_stage`（经济表）/ `merrill_stage`（美林矩阵）+ 聚合字段 `peg_interval` / `cash_floor` / `single_cap`。
- **按「三表收口规则」收口为单一结论**（不并列罗列多套参数），并写出收口说明。
- 输出四项参数：调整后 PEG 合理买入上限（含低估 / 高估阈值与「合理偏贵」中间带）+ 现金仓位下限 + 单只上限三档 + 单一行业上限。

---

### 第五步：标的级校准（可选，仅当提供 `--peg` 及其仓位输入）

```bash
python tools/specialized/macro_calibrator.py calibrate \
  --stage {已确认阶段} --peg {PEG} --current-cash {现金%} --single-stake {单只%} \
  [--stake-tier verified]
```

- 读回：`calibrated_peg_verdict`（`verdict` / `peg_interval` / `peg_ceiling` / `red_flag`）、`cash_floor_min` / `cash_ok` / `cash_gap`、`single_cap_value` / `single_cap_ok` / `single_cap_gap` / `single_caps` / `industry_cap`、`validation`（可审计复现）。
- `red_flag=true`（PEG > 2）时须显式提示「**严重透支红线，不因降息而取消**」。
- **未提供 `--peg`（或仓位输入）时跳过本步**，仅输出三表参数，并在报告中显式说明「未做标的级校准（缺 PEG / 仓位输入）」。
- PEG 取值来自 `financial_rigor.py adjusted-peg`，本技能不自行计算。

| 市场 | stage 判定输入 | 工具支持 | 降级路径 |

## 三表收口规则（强制，对应框架坐标轴索引）

**总规则**：**（一）+（二）算参数 +（三）美林矩阵总收口**。出现不一致时按下表处置，禁止多表并列罗列而不收口。

| 宏观阶段 | 利率环境（（一）表） | 经济档（（二）表） | 收口要求 |
| --- | --- | --- | --- |
| **衰退** | 降息启动（**临时按 1.0**） | 衰退档（收紧） | 虽启动降息，但盈利下行与信用收缩主导、风险偏好极低 → **上限临时收紧至 1.0**，而非降息档 1.5；待「宽信用」实质落地（信贷脉冲转正）后再切 1.5 |
| **复苏** | 低利率（放宽至 1.5） | 中性 / 复苏档（基准） | 直接采用放宽档 1.5 |
| **过热** | 加息（收紧至 1.0） | 过热档（收紧） | 直接采用收紧档 1.0 |
| **滞胀** | 高利率 + 信用收缩（0.8） | 滞胀档（最紧） | 较加息档更紧，上限取 **0.8**（即 PEG ≥ 0.8 不新建仓） |

**补充收口纪律**：

1. **美林时钟定「风格与行业 beta」，信用周期定「总仓位与现金」**；二者**同向时信号最可靠，背离时以信用周期（更接近资金面真相）为准**。
2. **矩阵「单只上限」为「验证后」一档口径**，完整三档（初始 / 验证后 / 绝对）按经济表同向收紧；单一行业上限同向收紧。
3. **现金仓位为默认目标下限**：中性 / 复苏下限 10%（不主动低于 10%）；估值分位 > 80% 时提高至 20%~30%；进入衰退 / 滞胀 / 过热后按矩阵值抬升下限。
4. **适配性提示**：本框架的科技 / 国产化成长赛道最适配**复苏期**（低利率 + 信用扩张）；进入**滞胀 / 衰退**应优先降仓位，而非硬扛高估值。
5. **确定性三锚**（影响偏贵上限）：连续 2~3 个季度增速稳定性 / 订单可见度 / 竞争格局固化程度，**任一偏弱则偏贵上限收紧至 1.2**。
6. **PEG > 2 为严重透支红线，不因降息而取消**，只可在降息周期放缓减仓节奏。

## 注意事项

1. **先定 stage，再谈参数** —— stage 未确认前，所有参数一律标注「暂定」。
2. **收口优先** —— （一）（二）（三）不一致时必须收口为单一结论并写出说明；**衰退期降息不等于放宽**。
3. **背离以信用周期为准** —— 美林时钟与信用周期背离时，总仓位与现金以信用周期为准。
4. **禁止心算** —— 任何数值必须来自工具输出；用户直接口述参数时须标注「由用户提供，未做工具核验」。
5. **数据截止日期必填** —— `data_ts` 与检索时间必须写入报告；`stale` / `degraded=true` 须如实标注并提示 `--no-cache` 刷新。
6. **软判定非权威** —— `confidence=低` 与 `manual_review=true` 必须原样透传，不得省略、不得改写为确定语气。
7. **跨市场不得套用** —— 中国指标软判定结果不得直接充当港股 / 美股的 stage；非覆盖市场走 `--stage` 直填并标注来源。
8. **PEG 与仓位输入来源要写清** —— PEG 来自 `financial_rigor.py adjusted-peg`；现金 / 单只占比来自用户或组合管理技能。
9. **不越界** —— 不判断个股价值、不产出买卖时机、不做组合集中度分析。
10. **不替代人工判断** —— 宏观阶段与风格倾向需人工确认；本技能提供参数与依据，不替用户做宏观决策。
11. **独立档术语纪律** —— 本技能所有卖出口径一律指向 `garp-exit`（GARP 五级卖出），不得使用中期链或长期链的卖出体系术语与参数口径。

## 局限性

1. **工具数据的市场覆盖**：`data` 的六项指标均为中国宏观指标；港股 / 美股阶段判定依赖搜索工具或用户提供，缺锚时只能走 `--stage` 直填。
2. **软判定的非权威性**：框架只给定性规则、未给显式数值阈值，工具的阶段判定为启发式，`confidence=低`，须人工确认。
3. **信用周期的代理指标限制**：框架以社融 / 信贷脉冲刻画信用周期，非 A 股市场的信用代理（如信用利差）口径不同，跨市场可比性有限。
4. **估值分位未纳入工具**：框架要求「估值分位 > 80% 时把现金下限提高至 20%~30%」，`calibrate` 未引入分位输入，须人工复核（工具 `validation.note` 亦提示）。
5. **参数为区间而非点位**：输出的是上下限与档位，不能替代具体的仓位决策与标的甄别。
6. **数据时效**：宏观数据按月 / 季发布且存在修订，缓存 TTL 内可能非最新值。
7. **不构成投资建议**：本技能仅用于框架参数校准，不构成任何投资建议。
