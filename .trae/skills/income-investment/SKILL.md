# 收入投资分析：持久性与机会型收益评估

对 $ARGUMENTS 进行系统化收入投资分析。

> 永远不要把高显示股息率视为好机会的证据。本工作流用于学习与研究，不构成个性化投资建议。

## 设计理念

本技能专注于**收入型投资决策**——评估一家公司能否产生足够持久且有吸引力的可分配收入，以证明其在组合中的角色：

- **长期收入核心持仓**（Core Income）：优质业务、可持续且可能增长的分红、可合理长期持有
- **机会型收益仓位**（Opportunistic Income）：临时性高收益或折价，有明确的进入、监控、持有期和退出规则
- **收益陷阱识别**（Yield Trap）：覆盖不足、杠杆过高、结构性衰退或收益率主要由股价下跌驱动

与 `investment-research`（全面基本面研究）和 `portfolio-review`（组合管理）互补，本技能专注于**收入维度**的决策。

## 关联工作流

复用已有工作流而非重复：

| 需求 | 工作流 |
|------|--------|
| 验证财务数据与跨源核对 | `financial-data` |
| 全面基本面研究 | `investment-research` |
| 买入前最终决策 | `investment-checklist` |
| 组合适配、集中度与仓位 | `portfolio-review` |
| 决策后持续监控 | `thesis-tracker` |
| 财报发布后更新 | `earnings-review` |
| 离散事件快速分析 | `news-pulse` |

`income-investment` 负责收入专项决策，不得静默覆盖当前 `portfolio-review` 的结论。

## 研究纪律

1. 研究前运行 `date` 确认当天日期，在报告头部注明数据截止日期。
2. 优先使用年报、中期报告、业绩发布、投资者文档、监管文件、官方公告和交易所数据，其次用二手来源填补空白并标注为二手。
3. 遵循 `financial-data` 技能规范：关键财务数据至少两个独立来源验证，误差>1%须标记。
4. 每个时效性数据标注日期或期间。将每项重要陈述区分为**已验证事实**、**估计**、**假设**或**分析判断**。
5. 使用 `tools/common/financial_rigor.py` 进行精确的分红、收益率、估值、市值、组合收入和三情景算术运算。**禁止 LLM 心算决策敏感数据**。
6. 跨币种（港股/美股）收入折算时，先用 `python tools/common/fx_rate.py --code HKDCNY`（或 `USDCNY`）获取实时汇率，勿用固定汇率。
7. 报告保存后，运行 `tools/common/report_audit.py extract` 和 `verdict` 审核流程。未通过审核的报告是草稿，不是可发布的研究。

## 执行流程

### 第一步：解析请求与数据质量确立

- 确定标的、上市地、货币、分红货币、模式（新建/已有）、期望角色、以及可选的组合输入。
- 说明哪些毛收入、净收入、成本收益率、组合贡献和交易后收入计算可行。
- 评级证据质量：`A`（完整一手资料）、`B`（部分一手资料）、`C`（主要为二手/不完整）。基本面严重不足时触发 `数据不足` 门控。

#### 数据获取工具

> **数据源规范**：参见 `financial-data` 技能。所有财务数据必须来自两个独立来源，误差>1%须标记。

**A股**：
```bash
python tools/a_share/stock_info.py --search {公司名}
python tools/a_share/stock_financial.py --code {股票代码}
python tools/a_share/stock_quote.py --code {股票代码}
```

**港股**：
```bash
python tools/hk_stock/stock_financial.py --financial {股票代码}
python tools/hk_stock/stock_quote.py --code {股票代码}
```

**美股**：
```bash
python tools/us_stock/stock_financial.py --code {股票代码}
python tools/us_stock/stock_quote.py --code {股票代码}
```

**跨币种汇率获取**：
```bash
python tools/common/fx_rate.py --code HKDCNY   # 1港币=x人民币
python tools/common/fx_rate.py --code USDCNY   # 1美元=x人民币
```

**网络信息获取**（分红公告、税务政策等）：

禁止使用 Anthropic 官方 WebSearch/WebFetch（中国大陆不可用），统一使用本地五工具组合。完整角色定位、市场×场景选型矩阵、命令速查、多源验证示例见 [web-search-tools](../tools-scripts/web-search-tools.md)。

**收入投资分析场景下的搜索选型**：
- A股分红公告/分红政策：anysearch 主 + doubao 辅，须从交易所官方披露确认
- 港股/美股分红历史：港股 doubao + tavily 双源；美股 exa + doubao 双源
- 分红政策/指引变更：doubao --need-content 主 + anysearch 辅，抓取公告正文做精确解读
- 税务/预扣税/协定税率：doubao --finance 主 + anysearch 辅，须标注司法管辖区和生效日期
- 收益陷阱/削减信号：exa --type deep 主 + doubao 辅，深度检索分析师质疑和削减先兆

**搜索规范**（收入投资分析特有）：
- 时效性优先：使用 `--time-range month/week` 限制时间范围，分红公告须覆盖最近一个除息日
- 双源验证：港股 doubao + tavily；美股 exa + doubao；A股 anysearch + doubao
- 分红政策变更须从交易所官方披露确认，不得仅依赖第三方汇总
- 税务信息须标注司法管辖区和生效日期，协定税率因个人情况而异
- 关键信息缺失时标注"信息不足"，不得用推测填充

---

### 第二步：理解分红

覆盖至少五年（如可得）：

- 分红频率；普通、特别或可变分红状态；支付货币
- 每股年度分红及总分配
- 增加、持平、削减和暂停的次数
- 分红 CAGR，注明精确期间和特别分红处理方式
- 预告公告日、除息日、登记日和支付日

**重要提示**：等待除息日并非免费收益——股价理论上会按分红金额调整。日历可能影响执行时机，但绝不能成为买入劣质公司或延迟必要卖出的理由。

---

### 第三步：追踪可分配现金流

分析以下维度：

- 净利润派息率、自由现金流派息率
- 必要投资后现金流、现金流稳定性和质量
- 利息覆盖、净债务、债务到期结构、再融资需求
- 维持性和增长性资本开支
- 表外承诺、回购与分红的竞争关系

**不要跨行业机械套用 EPS 派息率**：

| 行业 | 必需的行业指标 |
|------|---------------|
| REIT / SIIC | FFO、AFFO、出租率、LTV |
| 银行 | CET1、可分配收益、监管约束 |
| 保险 | 偿付能力与资本生成 |
| BDC | NII、NAV、不良率 |
| 资源类 | 周期中段现金流与可变分红政策 |
| 电信 / 公用事业 | 资本开支、债务与 FCF 覆盖率 |

---

### 第四步：测试质量与持久性

评估商业模式、护城河、定价权、周期性、利率/汇率/大宗商品敏感性、收入可预测性、资本配置、管理层质量，以及在下行情景中维持分红的能力。**区分会计利润与可重复的可分配现金**。

---

### 第五步：估值收入流

分析当前收益率、历史平均收益率、适当行业倍数、FCF 收益率、合理内在价值区间、安全边际，以及价格下跌与分红削减的组合情景。

> 成本收益率仅为回溯信息，绝不是继续持有的理由。

**估值计算须使用工具**：
```bash
python tools/common/financial_rigor.py verify-valuation --pe {PE} --eps {EPS}
python tools/common/financial_rigor.py three-scenario --bull {参数} --base {参数} --bear {参数}
```

---

### 第六步：计算可用收入

仅在输入支持时，计算：

- 年度毛分红、每次频率的毛分红
- 已知来源预扣税
- 估计净收入
- 对组合收入的贡献
- 交易后年度收入

> 如果税务或账户信息不完整，展示毛收入并明确说明为何净收入不可计算。标注协定税率和税务处理的司法管辖区、账户假设和生效日期。

---

### 第七步：检查组合适配

如果提供了组合信息：

- 确定当前和建议权重
- 检查行业和地理集中度、重复风险、单一行业收入依赖
- 区分资本分散与分红分散
- 读取最新相关的 `portfolio-review` 报告（如有）

> 如果结论分歧，展示两个结论，解释原因，并将公司质量与配置适配分开。一个优质收入证券仍可能因组合集中度而标记为 `持有 - 不加仓`、`减仓` 或 `观察名单`。

当数据允许时，按月展示预期毛收入。**绝不推荐劣质公司填补空缺月份**——季度支付者可以组合出月度现金流，无需强制要求月度支付者。

> **货币口径统一**：持仓含港股时，用 `python tools/common/fx_rate.py --code HKDCNY` 获取实时汇率，将收入折算到统一货币口径。

---

### 第八步：构建三情景

提供基准、不利和严重三种情景。每个情景须说明：

- 经营假设
- 可分配现金流
- 派息覆盖
- 资产负债表/再融资影响
- 分红结果
- 估值影响

> 不利和严重情景必须**明确测试分红削减**，而非假设分红不变。

---

## 分类、门控与判决

### 收入特征分类

- **信念 + 持久收入**：优质业务、可持续且可能增长的分红、可合理长期持有
- **机会型收入**：临时性高收益或折价，有明确的进入、监控、持有期和退出规则
- **收益陷阱**：反复覆盖不足、杠杆/投资需求不兼容、结构性衰退，或收益率主要由股价下跌驱动
- **不适合收入投资**：无实质性分红、边际收益率、证据不足，或股东回报主要通过其他方式实现

### 质量评分卡

使用定性评分卡，**不计算数值平均**：

| 维度 | 评级（`强`、` adequate`、`弱`、`严重`、`未知`） | 证据 |
|------|------|------|
| 业务质量 | | |
| 现金流可见度 | | |
| 分红覆盖 | | |
| 资产负债表强度 | | |
| 分红历史 | | |
| 分红增长潜力 | | |
| 估值 | | |
| 周期性 | | |
| 削减风险 | | |
| 组合适配 | | |

### 阻断门控

在判决前检查以下阻断门控：

- 反复无覆盖的分红
- 严重债务或再融资风险
- 结构性业务恶化
- 基本面数据不足
- 重大治理或诚信问题

> 安全、债务、恶化或诚信门控失败将覆盖评分卡，通常要求 `拒绝 / 收益陷阱`（对于已有持仓，当现有组合信息无法得出立即处置结论时标记为 `减仓`）。数据不足门控要求 `数据不足`。不得用评分抵消门控失败。

### 判决

返回且仅返回一个判决：

- `核心收入`（CORE INCOME）
- `机会型收入`（OPPORTUNISTIC INCOME）
- `观察名单`（WATCHLIST）
- `持有 - 不加仓`（HOLD – DO NOT ADD）
- `减仓`（REDUCE）
- `拒绝 / 收益陷阱`（REJECT / YIELD TRAP）
- `数据不足`（INSUFFICIENT DATA）

判决须包含：可能的组合角色、主要原因、主要风险、进入条件、建议研究仓位范围（绝无普遍适用）、加仓条件、减仓/退出标准、监控指标和置信度。当组合、税务或风险承受能力信息不足时，不给出确定的个性化建议。

## 报告格式

使用以下标题，每个仅出现一次，避免重复相同分析：

1. 执行摘要
2. 判决与分类
3. 可能的组合角色
4. 业务与分配现金来源
5. 分红历史与日历
6. 分配覆盖与安全性
7. 资产负债表与再融资
8. 收入增长
9. 估值与安全边际
10. 税务与货币
11. 组合适配
12. 情景：基准、不利、严重
13. 分红削减风险
14. 买入或加仓条件
15. 减仓或卖出条件
16. 监控表
17. 一句话结论
18. 来源与数据质量

将评分卡和阻断门控结果包含在第2节，月度收入日历包含在第11节（如可计算），来源标题、发布者、发布日期、查询日期、报告期间、URL和一手/二手标签包含在第18节。

保存报告至 `reports/{company}-income-investment-{YYYYMMDD}.md`，使用文件系统安全的公司标识符。

## 发布审核

```bash
# 提取报告中的数据项
python tools/common/report_audit.py extract --report reports/{company}-income-investment-{YYYYMMDD}.md

# 验证每个提取项与可靠来源一致，然后：
python tools/common/report_audit.py verdict --results '<verified JSON>' --report reports/{company}-income-investment-{YYYYMMDD}.md
```

修复未通过项并重复审核。明确保留未解决的缺口，降低置信度而非用假设填充。

**Windows 兼容说明**：本工作流在 Windows 环境下运行时，注意以下事项：
- 不要使用 `/tmp/` 路径保存临时文件（Windows 无此目录），应使用 `%TEMP%` 环境变量或当前工作目录
- 不要使用 `2>/dev/null` 重定向 stderr，应使用 `2>$null`（PowerShell）
- 不要使用 `tr -d '\r'` 等 Unix 命令，直接在 Python 中处理换行符
- 如需提取 JSON 输出，可直接使用 `--dry-run` 参数或 `--output-json` 参数，无需通过 shell 管道处理
