# garp-valuation — GARP 估值锚定（1~5 年独立档）

> **所属档位**：GARP 独立档（1~5 年，五大师：费雪 / 林奇 / 郑希 / 李进 / 欧奈尔）
> **权威口径**：《中长期价值成长（GARP）投资框架》第4步（行 378~438）+ 第五部分·四（行 681~748）
> **版本**：1.0.0 ｜ **创建**：2026-09-17 ｜ **开发任务**：P4-5

按**公司类型**选定**唯一主锚工具**，用多工具矩阵算出估值数值，再叠加**宏观 PEG 合理区间**与 **ESG 环境折价**两层校准，收口为一个**统一估值档位**，并给出**分批建仓节奏**。

## 核心功能

### 一、公司类型五分与主锚（框架行 381~387 逐格落地）

| 公司类型 | 核心工具（主锚） | 辅助工具 | 可接受标准 |
| --- | --- | --- | --- |
| **快速增长型（盈利稳定）** | 调整后 PEG | 远期 PE、PEG 分位 | PEG < 1 低估；1~1.2 合理；1.2~1.5 合理偏贵；> 1.5 高估 |
| **高研发投入型（利润被压低）** | PS / EV/Sales | Rule of 40 | Rule of 40 ≥ 40；EV/Sales **低于同业可比** |
| **未盈利科技型** | PS、EV/Sales | 研发管线 NPV | 需有**清晰的盈利路径和里程碑节点** |
| **稳定增长型** | 远期 PE + 隐含 PEG | 股息率 | 隐含 PEG **≤ 1.2** |
| **成熟型企业** | DCF | 股息贴现 | 市值 ≤ **保守 DCF 估值的 80%** |

**类型判定优先级**（防"挑选有利类型"，`GV-1`）：盈利为负 → 未盈利科技型；净利率 <5% 或研发强度显著高于同业 → 高研发投入型；增速连续 ≥20% 且盈利稳定 → 快速增长型；增速 10%~20% → 稳定增长型；增速 <10% 且现金流成熟 → 成熟型企业。

> 报告中**必须列出数据依据与被排除的类型**，禁止无声跳档。

### 二、统一收口六档（门禁 A-1 确认）

| 档位 | 操作含义 |
| --- | --- |
| **显著低估** | 绝佳买点；底仓可加；首批可按下限建仓 |
| **低估** | 可建仓；先建 1/3 首仓 |
| **合理** | 合理买入区间；先建 1/3 首仓 |
| **合理偏贵** | **持有不加仓**；机动仓逢高择机减；**不新建仓** |
| **高估** | 不加仓；机动仓减持 |
| **严重透支** | **PEG > 2 红线**（不因降息取消）；加速清机动仓 |

**PEG 类映射**（以宏观校准后区间 `[L, U]` 判定，快速增长型）：

| 档位 | 调整后 PEG |
| --- | --- |
| 显著低估 | < L − 0.2（加息/过热档为 < 0.7） |
| 低估 | L − 0.2 ≤ PEG < L |
| 合理 | L ≤ PEG ≤ U |
| 合理偏贵 | U < PEG ≤ 1.5 |
| 高估 | 1.5 < PEG ≤ 2.0 |
| 严重透支 | > 2.0 |

**非 PEG 类映射**（**本技能操作化刻度、非框架原文**，报告须同时呈现框架原文标准）：

| 类型 | 低估 | 合理 | 合理偏贵 | 高估 | 严重透支 |
| --- | --- | --- | --- | --- | --- |
| 高研发投入型 | EV/Sales ≤ 同业 0.8× 且 Ro40 ≥ 40 | EV/Sales 0.8~1.2× 且 Ro40 ≥ 40 | 1.2~1.5× 或 Ro40 35~40 | 1.5~2.0× 或 Ro40 30~35 | > 2.0× 或 Ro40 < 30 |
| 未盈利科技型 | 里程碑全部按期兑现 + 现金跑道 ≥ 36 个月 | 里程碑兑现且盈利路径清晰 | 里程碑延期 ≤ 1 项 | 里程碑延期 ≥ 2 项 | 盈利路径不可信 / 现金跑道 < 12 个月 |
| 成熟型企业 | 安全边际 ≥ 20% | 0% ≤ 安全边际 < 20% | −20% ~ 0% | −50% ~ −20% | < −50% |

> 「未盈利科技型」**不设显著低估档**——框架对该类型未给"更便宜"的判据，不自行造激励。

### 三、宏观叠加（替换判定区间）

| 宏观 stage | 工具 `peg_interval` | 补全后判定区间 |
| --- | --- | --- |
| **过热**（加息） | `[0.8, 1.0]` | `[0.8, 1.0]` |
| **衰退** | `[1.0]`（仅上限） | `[0.8, 1.0]`（门禁 B-1） |
| **滞胀** | `[0.8]`（仅上限） | `[0.8, 0.8]` → PEG ≥ 0.8 一律不新建仓 |
| **复苏**（降息） | `[1.2, 1.5]` | `[1.2, 1.5]` |

> **衰退/滞胀的下限 0.8 为沿用加息档口径、框架未显式定义**，报告须标注。`cash_floor` / `single_cap` / `industry_cap` **只透传，不裁量**（归 `garp-portfolio-review`）。
>
>  **宏观不作为择时清仓依据**（框架行 685）。

### 四、ESG 环境折价叠加（在宏观校准后的结果之上）

| 情形 | 框架折价 | 本技能叠加方式 |
| --- | --- | --- |
| 高环境风险（无转型路径） | 再打 **8~9 折** | PEG 类：区间上限 × `discount_factor`；DCF 类：`per_share` × `discount_factor` |
| 有**可验证**转型路径 | 收窄至 **≤5% 或豁免** | 同上（工具给更小 `discount_pct`） |
| **搁浅资产**风险 | 折价加大 **且上调贴现率** | DCF 类：`--r` 显式加 `discount_rate_adj_bps ÷ 100` 百分点后重算 |
| **ESG 评级尾部** | **先降仓位上限** | **只透传** `position_cap_after`（归 P4-8） |

**三条硬边界**：① 折价是**叠加、不是替代**（须同时呈现折价前后数值）；② 折价率**只来自工具**，技能层不得自估 10/15/20%（`GV-6`）；③ 报告**不得出现"建议单只上限 X%"**（`GV-7`）。

> **顺序（门禁 C-1）**：**先宏观 → 后 ESG**，留痕固定为「基准 → 宏观校准后 → ESG 折价后 → 最终档位」。

### 五、交叉校验与降级（只降不升）

| 校验项 | 规则 | 冲突处置 |
| --- | --- | --- |
| PE 历史分位（`pe-percentile`） | <40% 低估 / 40~60% 合理 / >60% 偏高 | 与主锚冲突 → **主锚降一档** |
| 隐含增速（`implied-growth`） | red / yellow / green 三灯 | red → **降一档**；yellow → 偏贵预警；green → 未透支 |
| 宏观区间 | 加息/过热收紧、降息/复苏放宽、滞胀最紧 | **替换区间后再判定**（非事后调档） |

> **单向性（`GV-5`）**：辅助工具**只能降档、不得升档**。

### 六、估值陷阱四项强制核查（框架行 416~421）

| # | 陷阱 | 核查动作 |
| --- | --- | --- |
| 1 | **低 PE 陷阱** | 结合行业周期位置；周期顶点 → PEG 不适用，改走 DCF |
| 2 | **高 PE 但增速不可持续** | 剔除一次性收益后**重算真实 PEG** |
| 3 | **忽略股权稀释** | 同时核对总利润增速与**股本变化** |
| 4 | **研发费用化扭曲** | **必须**用核心经营利润口径回算调整后 PE |

### 七、分批建仓规则（框架行 393~401）

| 路径 | 适用 | 节奏 |
| --- | --- | --- |
| **默认三分法** | **绝大多数标的** | 1/3 首仓 → 右侧确认后补至 2/3 → 连续 2~3 季兑现后补齐 |
| **左侧布局** | 杀估值而非杀逻辑 | 首批 ≤ **最终仓位的 50%**（可建上限、非必须建到） |
| **右侧一次性 2/3** | **仅**三信号共振启用 | 渗透率突破 15% 临界点 + 财报连续 2 季超预期 + 行业景气明确上行；剩余 1/3 回调 20 日均线补 |

> **止损优先于补仓**：建仓初期（持仓 < 最终仓位 50%，**或** ≥50% 但逻辑未经 2~3 季财报验证）执行 **8%~10% 硬止损**，**不得**以"股价更便宜"为由逆向补仓。

## 使用示例

### 示例 1：快速增长型（调整后 PEG 消除研发费用化扭曲，验收 6.2）

```bash
python tools/common/financial_rigor.py adjusted-peg \
  --market-cap 1000 --core-operating-profit 20 --rnd-expense 25 --growth 30
```

实测输出：`adjusted_pe=22.22`、`adjusted_peg=0.74`、`tier="低估"`；同场景报表口径 `peg --pe 50 --growth 30` → `peg=1.67`、`rating="高估 (>1.5)"`。

**本技能处置**：取**调整后 PEG = 0.74**（**忽略**工具 `tier`，`GV-2`），按中性基准区间 `[1.0, 1.2]` 映射 → **显著低估**（< 1.0 − 0.2 = 0.8）。
> **对照**：若误用报表 PE，同一标的会被判「严重透支」——**研发费用化扭曲足以让结论反转两档**。

### 示例 2：宏观叠加改变档位（验收 6.3）

```bash
python tools/specialized/macro_calibrator.py stage --stage 滞胀
python tools/specialized/macro_calibrator.py calibrate --stage 滞胀 --peg 1.14 --current-cash 15 --single-stake 12
```

实测输出：`peg_interval=[0.8]`、`cash_floor="≥40%"`、`single_cap="≤10%"`；`calibrated_peg_verdict.verdict="超出合理上限（不新建仓）"`、`cash_ok=false`、`single_cap_ok=false`、`validation.peg_compare="1.14 > 0.8 → 超出合理上限（不新建仓）"`。

**本技能处置**：同一 PEG = 1.14，在中性基准区间 [1.0, 1.2] 下为 **合理**，在滞胀档（`[0.8, 0.8]`）下为 **合理偏贵**（PEG > 0.8 即不新建仓，与工具 `calibrated_peg_verdict` 的「超出合理上限（不新建仓）」一致）——**同一估值，两种结论，差异完全来自宏观**。仓位项（`cash_floor` / `single_cap` / `single_caps`）**原样透传**，报告**不出现"建议单只上限 X%"**。

### 示例 3：ESG 折价叠加（验收 6.4）

```bash
python tools/specialized/governance_data.py esg \
  --env-risk-level 高 --transition-pathway 无 --stranded-asset --esg-tail \
  --position-cap-base 20.0 --as-of 2026-09-17
```

实测输出：`discount_factor=0.8`、`discount_pct=20.0`、`discount_range="0.80~0.90"`、`discount_rate_adj_bps=150`、`position_cap_after=15.0`、`position_cap_downgrade=5.0`、`esg_tail_triggered=true`、`stranded_asset_triggered=true`。

**本技能处置**（DCF 类示例，`--r` 由 9.0% 上调至 10.5%）：

| 项 | 折价前 | 折价后 |
| --- | --- | --- |
| `per_share` | **101.87** | **82.92** |
| `margin_of_safety_pct` | **21.47%** | **3.52%** |
| 档位 | 低估（安全边际 ≥20%） | **合理**（0% ≤ 安全边际 < 20%） |

> 重算触发 `audit.passed=false` + `C1: 折现率 r=10.50% 不在 CNY 的 [6.0%, 9.0%] 区间内`——该告警**由 ESG 搁浅资产叠加触发，属既定叠加而非参数失误**，须在报告中显式区分；**不得为消除告警而下调 `--r`**（那等于取消框架行 431 的要求）。

### 示例 4：交叉校验只降不升（验收 6.5）

主锚 `adjusted_peg=1.10` → 中性基准区间 `[1.0, 1.2]` → **合理**；但 `pe-percentile --current 58` 实测 `percentile=80.0%`、`rating="偏高 (>60%)"` → 与主锚冲突 → **降一档至「合理偏贵」**，并在报告中写明触发项与数值。

> **反例（禁止）**：若 PE 分位为 10%（低估）而主锚为「合理偏贵」，**不得**据此升档（`GV-5`）。

### 示例 5：未盈利科技型（主锚 + 研发管线 NPV，验收 6.6/6.10）

```bash
python tools/specialized/in_research_scan.py pipeline-npv \
  --projects p.json --discount-rate 0.10 --currency CNY --as-of-year 2026 --json \
  --sensitivity "r=0.01;p=0.10"
```

实测输出：`pipeline_npv=57.13749060856498`、`npv_low=43.366960824959364`、`npv_high=71.58140860166064`、`data_insufficient=false`、`defaults_applied=[]`。

**本技能处置**：主锚仍为 **PS / EV-Sales**（研发管线 NPV 是**辅助**）；NPV 参数（折现率 / 概率 / 峰值收入 / 商业化年份 / `source`）**全部由调用方提供**，工具不内置任何默认假设；若 `data_insufficient=true` → 数值为 `null`，**标"未量化"并终止该项**（`GV-10`），同时逐条列出「里程碑 → 预计兑现时点 → 证据来源」，缺一即标"不满足"。

## 强制纪律（GV-1 ~ GV-12 摘要）

| 编码 | 一句话 |
| --- | --- |
| **GV-1** | 类型判定须留依据与被排除类型，禁止为套宽松阈值而挑类型 |
| **GV-2** | 工具内置 `tier` / `rating` **不进档位判定**，只取数值二次映射 |
| **GV-3** | 「同业可比」须 **≥2 家并列表**，不得以"行业均值"替代 |
| **GV-4** | DCF 参数须保守且受三条硬约束（r−g 宽度 / 币种一致 / 离散风险归属） |
| **GV-5** | 辅助工具**只降不升** |
| **GV-6** | 宏观与 ESG 参数**只能来自工具**，禁止自换算、自估折价率 |
| **GV-7** | 仓位量**只透传、不裁量**；报告不得出现"建议单只上限 X%" |
| **GV-8** | **不建独立聚合器**，本技能是编排层 |
| **GV-9** | 「不适用」须**显式判定**（增速 ≤0 / 亏损 / 周期顶点） |
| **GV-10** | 未量化项**不得臆造**（研发管线 NPV / 里程碑） |
| **GV-11** | **数据截止日期强制标注** |
| **GV-12** | 估值陷阱**四项逐项留痕** |

## 工具实测已知约束（务必遵守）

1. **量纲三档不一致**：`adjusted-peg` / `rule-of-40` / `peg` 用**百分点**；`implied-growth` 的 `--net-margin` / `--guidance-growth` 用**小数**；`pe-percentile` 用 **PE 数值**。写错量纲不报错，只会给出错误结论。
2. **`calc` 不支持 `^`**，幂运算写 `**`；负号开头须加引号 `--expr="-3+12"`。
3. **`macro_calibrator stage` 枚举仅 4 档**（衰退 / 复苏 / 过热 / 滞胀），**无"中性"**；中性基准区间 `1.0~1.2` 按回退规则处理。
4. **`data` 返回两个语义不同的 stage 字段**：`--stage` **取 `econ_stage.stage`**（美林阶段，实测 `"衰退"`，属 4 档合法枚举、可直接串联）；`rate_stage.stage` 为**利率阶段**（实测 `"降息/低利率"`，**非** `stage` 枚举），语义不同**不可混用**。取数后须保留 `manual_review=true`。
5. **`dcf` 的 C1 审计**：`--g-terminal` 有币种上限（CNY 实测 2.0%）、`--r` 有币种区间（CNY 实测 `[6.0%, 9.0%]`）——ESG 上调 `--r` 越界属**既定叠加**，须留痕而非消警。
6. **`governance_data esg --env-risk-level` 取值 `高` / `低`**（传"高风险"会报错）。
7. **`governance_data.py` / `macro_calibrator.py` 的 `--help` 在 GBK 控制台可能抛中文编码异常**，加 `$env:PYTHONIOENCODING="utf-8"` 可解；不影响子命令执行。

## 核心原则

1. **类型决定尺子**——类型选错，后面全错，故必须留证。
2. **阈值是宏观的函数**——先查宏观参数，再判档位。
3. **折价是叠加不是替代**——折价前的基本面数值必须同时呈现。
4. **只取数值、不取评级**——工具的分档线与本框架不同，照抄会系统性低估风险。
5. **越界即违规**——不做门槛判定、不定卖出、不给仓位数值、不建聚合器。
