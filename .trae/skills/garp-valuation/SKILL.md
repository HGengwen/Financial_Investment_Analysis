# GARP 估值锚定：多工具矩阵 + 宏观与 ESG 叠加（1~5 年独立档）

对 $ARGUMENTS 执行《中长期价值成长（GARP）投资框架》**第4步·估值锚定**与**第五部分·四·宏观环境适配**的估值化落地，回答一个问题：

> **这家公司当前贵不贵？该按什么节奏建仓？**

> **独立档声明**：**本技能属 GARP 独立档（1~5 年，五大师：费雪 / 林奇 / 郑希 / 李进 / 欧奈尔），与 1~3 年中期链、10 年长期链口径物理隔离、功能互补。** 所有估值数值**一律由工具产出**（`financial_rigor.py` / `macro_calibrator.py` / `governance_data.py` / `in_research_scan.py`），宏观区间与 ESG 折价**只透传工具字段**；本技能只做**类型分流、工具编排、区间替换、档位收口、建仓节奏与下游转接**，全程**禁止 LLM 心算、禁止自造阈值**。

> 💬 **费雪式提醒**："估值不是算出一串数字，而是判断这家公司的成长能否持续到让今天的价格显得便宜。"
>
> 💬 **林奇式提醒**："任何一家公司股票如果定价合理的话，市盈率就会与收益增长率相等——PEG 是尺子，不是结论；先分清它属于哪一类公司，尺子才有意义。"
>
>  **郑希式提醒**："科技股的利润被研发费用压住了，用报表 PE 去算 PEG，等于把最值钱的投入当成成本扣掉——必须把研发加回来再看。"
>
> 💬 **李进式提醒**："同一家公司，在不同宏观环境下该给的估值容忍度不一样。利率是贴现率的锚，锚动了，尺子就得跟着动。"
>
>  **欧奈尔式提醒**："再好的公司，买在透支的价位上也是亏钱的开始。PEG>2 这条红线，不因为任何理由取消。"

## 设计理念与定位

GARP 框架第4步的核心观点是：**科技股不能只用一个 PEG 打天下**（框架行 379）。框架按公司类型给出**五类主锚工具**，并明确「上表 PEG 阈值以中性宏观环境为基准，加息/降息周期需动态上浮或下调」（框架行 391）。本技能把这三层——**类型矩阵 + 宏观校准 + ESG 折价**——收口为**一个可执行的统一档位**。

三条核心逻辑：

1. **类型决定主锚，主锚决定尺子**——快速增长型用调整后 PEG、高研发投入型用 PS/EV-Sales + Rule of 40、未盈利科技型用 PS/EV-Sales + 研发管线 NPV、稳定增长型用远期 PE + 隐含 PEG、成熟型企业用 DCF（框架行 381~387）。**类型选错，后面全是错的**，故类型判定必须留证（`GV-1`）。
2. **阈值不是常数，是宏观的函数**——PEG 合理买入区间随利率环境在 `0.8~1.0`（加息/过热）与 `1.2~1.5`（降息/复苏）之间浮动（框架行 700~704、行 736~741），滞胀最紧取 `0.8`（框架行 746）。故**先查宏观参数、再判档位**，而不是判完档位再"微调"。
3. **折价是叠加，不是替代**——ESG 环境风险折价"是在基本面估值之上再打一次折扣，不是替代前文的多工具估值"（框架行 436）。多工具估值**照算**，折价施加在其结果之上（框架行 429）。

### 本技能的四条硬纪律

| # | 纪律 | 原因 |
| --- | --- | --- |
| 1 | **类型判定须留证且不得择利** | 类型是"挑选有利阈值"的唯一入口；不留证就无法审计（`GV-1`） |
| 2 | **工具内置评级一律不进档位判定** | `adjusted-peg` / `peg` 工具自带 `tier` / `rating`，其分档口径与本框架的六档不一致；只取数值（`GV-2`） |
| 3 | **辅助工具只降不升** | 辅助指标（PE 分位、隐含增速）与主锚冲突时只能降一档，避免"用好看的辅助指标翻案"（`GV-5`） |
| 4 | **仓位量只透传、不裁量** | `cash_floor` / `single_cap` / `position_cap_after` 原样呈现，最终数值归 `garp-portfolio-review`（P4-8）（`GV-7`） |

## 边界声明（本技能的核心约束）

1. **不做买入门槛判定**——能力圈四维、财务五门槛、科技豁免、三档结论（全部达标 / 部分不达标 / 任一否决命中）归 `garp-investment-checklist`（P4-3）。本技能**以"上游已给可建仓结论"为前提**。
2. **不做卖出决策**——不内建任何止损/清仓规则；只输出「估值档位」，供 `garp-exit`（P4-6）的「估值判断」级消费。
3. **不给最终仓位数值**——只透传 `cash_floor` / `single_cap` / `position_cap_after`；**报告中不得出现"建议单只上限 X%"**（`GV-7`）。
4. **不做宏观 stage 判定**——不自行判断美林阶段；只调 `macro_calibrator.py`。上游未给 stage 时调 `data` 子命令，并**原样透传其 `manual_review` 标志**。
5. **不输出价位公式**——只输出档位与建仓节奏；价位以 DCF 的 `per_share` + `margin_of_safety_pct` 呈现，不定义额外价位公式。
6. **不新增工具、不建聚合器**——本技能是**编排层**（`GV-8`）；全部数值来自既有工具的实测输出，**技能层不写任何加权公式**。

> **范围自查**：本技能若出现「自造阈值 / 自造折价率 / 工具内置评级被当结论 / 输出最终仓位数值 / 定义卖出层级 / 输出目标价公式」，即为越界。

## 执行流程（九步）

### 第一步：确认参数与数据基准

先运行 `date` 确认当天日期，作为「估值日期基准」与报告头部"数据截止日期"（全局规则 1；`GV-11`）。

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `{公司名}` | 目标公司（A 股 / 港股 / 美股）；亦可写 `{代码}` | **必填** |
| `--type` | `fast` / `rd-heavy` / `pre-profit` / `stable` / `mature`：**显式指定公司类型**（跳过自动判定，须自证依据） | 自动判定（§类型判定规则） |
| `--stage` | `衰退` / `复苏` / `过热` / `滞胀`：宏观阶段，由 `garp-macro`（P4-2）给出 | 未给出则调 `macro_calibrator.py data` |
| `--peg-growth` | 未来盈利增速（百分点），用于调整后 PEG | **必填**（或用 `--growth-source` 标注来源） |
| `--env-risk` | `高` / `低`：环境风险等级（ESG 折价入口） | 由行业属性判定并标注依据 |
| `--depth` | `standard`（含搜索五工具实时取证）/ `fast`（仅用缓存与用户提供数据） | `standard` |
| `--sensitivity` | 估值敏感性（如 `--peg ±0.2`）——**仅呈现，不改档位** | 无 |

**参数确认后，向用户澄清**（如未在 $ARGUMENTS 中给出）：目标公司、增速来源（一致预期 or 历史外推）、宏观阶段来源。**不要默默假设**。

### 第二步：取数与双源交叉

| 数据项 | 工具 | 时效要求 |
| --- | --- | --- |
| 当前 PE / PS / 市值 / 营收 | 三市场 `stock_financial.py` / `stock_quote.py`（A 股 `tools/a_share/`、港股 `tools/hk_stock/`、美股 `tools/us_stock/`） | PE 与市值 **≤1 个交易日** |

| 未来 2/3 年 EPS 一致预期 | 搜索五工具（`anysearch` / `doubao_search` / `exa_search` / `tavily_search` / `web_search`），**≥2 个来源** | **≤3 个月**，超时须标注「预期可能已过时」 |
| 研发费用 / 核心经营利润 | 年报（`annual_report_parser.py` / `stock_equity.py --download-report` / `pdf_extract.py`） | 最近年报 |
| 有息负债 / 现金 | 三市场资产负债表（`a_stock_cache` / `hk_stock_cache` / `us_stock_cache`） | 最近报告期 |

| ESG 参数 | **`governance_data.py esg`（禁止自行估算）** | 报告期 |

**双源交叉规则**（全局规则 2）：关键财务数据须至少两个独立来源，**误差 >1% 须标记**；一致预期**误差 >10% 须标记**并取区间中值并注明。

### 第三步：公司类型判定（留证）

**类型判定规则（按「盈利稳定性优先」自上而下，框架行 381~387 + 本技能口径化兜底）**：

| 序 | 判定条件 | 类型 |
| --- | --- | --- |
| 1 | 归母净利润为**负**（未盈利） | **未盈利科技型** |
| 2 | 净利率 **<5%** 或 研发强度**显著高于同业**（利润被研发压低） | **高研发投入型** |
| 3 | 营收增速**连续 ≥20%** 且盈利稳定（净利率稳定为正、现金流为正） | **快速增长型** |
| 4 | 营收增速稳定在 **10%~20%** | **稳定增长型** |
| 5 | 营收增速 **<10%** 且经营现金流成熟稳定 | **成熟型企业** |

**四条纪律**：

1. 类型判定须**先给出数据依据**（营收增速、净利率、研发强度、经营现金流符号、上市年限），**再**套类型——不得先定类型再找理由；
2. **须显式列出被排除的类型**及排除理由，禁止无声跳档；
3. 满足多个类型特征时按上表**优先级**（序 1 → 序 5）判定；
4. **不得为"套用更宽松阈值"而挑选类型**（`GV-1`）。

**"PEG 不适用"判定（框架行 391、行 416~421）**——满足任一即**不得**用 PEG 系主锚：

| 情形 | 处置 |
| --- | --- |
| 增速 ≤ 0（负增长） | 判 PEG 不适用 → 按本表重定类型（多为未盈利科技型或成熟型） |
| 归母净利润为负（亏损） | 判 PEG 不适用 → 未盈利科技型（PS / EV-Sales + 研发管线 NPV） |
| 周期性顶点（低 PE 但盈利将下行） | 判 PEG 不适用 → 成熟型企业（DCF）+ 触发"低 PE 陷阱"核查 |
| 三次重定类型仍不适用 | 出「**数据不足，无法估值**」结论（`GV-9`） |

### 第四步：按类型调用主锚 + 辅助工具

```bash
# ① 快速增长型主锚：调整后 PEG（研发费用回加）
```

### 第七步：ESG 环境折价叠加（在宏观校准后的结果之上）

```bash

  --env-risk-level {高/低} --transition-pathway {明确/无} \
```

**四情形与处置（框架行 427~432）**：

| 情形 | 框架折价幅度 | 工具字段 | 本技能的叠加方式 |
| --- | --- | --- | --- |
| 高环境风险（**无明确转型路径**） | 合理估值再打 **8~9 折**（10%~20%） | `discount_factor` / `discount_pct` / `discount_range` | **PEG 类**：合理区间上限 × `discount_factor`；**DCF 类**：`per_share` × `discount_factor` 作折价后目标价 |
| 有明确碳减排承诺与**可验证**转型路径 | 折价收窄至 **≤5% 或豁免** | 同上（由工具依入参判定） | 同上（工具会给更小的 `discount_pct`） |
| 面临**「搁浅资产」风险** | 折价加大 **且上调贴现率** | `stranded_asset_triggered` / `discount_rate_adj_bps` / `discount_rate_adj_range_bps` | **DCF 类**：把 `discount_rate_adj_bps ÷ 100` 百分点**显式加在 `--r` 上重算** |
| **ESG 评级处于行业尾部/最低档** | **不下调估值，先降仓位上限** | `esg_tail_triggered` / `position_cap_after` / `position_cap_downgrade` | **只透传**，归 `garp-portfolio-review`（P4-8）（`GV-7`） |

**折价后合理区间上限的算法（本技能操作化实现，须在报告中标注）**：

```
合理区间上限' = 宏观校准后上限 × discount_factor
（并受框架行 429「合理 PEG 上限下调至约 1.0」的中性基准校验：
  中性基准 1.2 × 0.8 = 0.96 ≈ 1.0，与框架表述一致）
```

若 `合理区间上限' < 宏观校准后下限`，则区间**退化为单点**，判定按 **`[下限, 下限]`** 执行，并在报告中显式标注「ESG 折价后合理上限低于宏观下限，区间退化，按单点执行」。

**三条硬边界**：

1. **折价是叠加、不是替代**（框架行 436）——报告须**同时呈现**折价前的基本面数值与折价后的数值，**不得只给折价后结论**；
2. **折价率只来自工具透传**——技能层**不得自行估算** 10% / 15% / 20%（`GV-6`）；
3. **仓位量只透传、不裁量**——报告**不得出现"建议单只上限 X%"**（`GV-7`）。

**ESG 数据缺失处置**：标「**ESG 未判定**」，**不做折价**（**不得默认无折价**），并在报告中显式提示「未纳入 ESG 折价，结论偏乐观」。

> **⚠️ 实测口径张力（属预期告警，须留痕）**：`dcf` 的 C1 审计对 `--r` 设了币种区间（如 CNY 为 `[6.0%, 9.0%]`）。当搁浅资产使 `--r` 上调至 9.0% 以上时，重算会返回 `audit.passed=false` + `C1: 折现率 r=… 不在 CNY 的 [6.0%, 9.0%] 区间内`。该告警**由 ESG 折价叠加触发、属既定叠加而非参数失误**——须在报告中显式区分并说明，**不得**为消除告警而擅自下调 `--r`（那等于取消框架行 431 要求的贴现率上调）。
>
> **处置口径（门禁确认）**：**维持 C1 护栏不变**（不改 `financial_rigor.py` 判分行为）。该告警属**预期告警**：`audit.passed=false` **不影响** `pv` / `per_share` / `verdict` 的正常输出（实测 CNY `--r 10.5` 仍输出 `verdict="低估（市值≤保守DCF 80%）"`），故**无需调整参数、无需重算**；只须在报告中标注触发原因（ESG 搁浅资产上调贴现率），并按上「三条硬边界」第 1 条**同时呈现**折价前后的 `per_share`。

## 统一收口六档与类型映射

> **门禁 A-1 确认**：采用六档统一口径。**PEG 类**严格来自框架行 383 + 宏观区间（**无自造刻度**）；**非 PEG 类**按本节第二张表**操作化刻度**换算，报告中须**同时呈现原始标准**（EV/Sales 倍数与同业对比、DCF 安全边际%）与换算后档位，并标注「**本技能操作化刻度、非框架原文**」。

### 六档操作含义（框架行 383 + 行 703、行 393~401）

| 统一档位 | 操作含义 |
| --- | --- |
| **显著低估** | 绝佳买点；底仓可加；首批可按下限建仓 |
| **低估** | 可建仓（处于合理买入区间下沿之下）；先建 1/3 首仓 |
| **合理** | 合理买入区间；先建 1/3 首仓 |
| **合理偏贵** | **持有不加仓**；机动仓逢高择机减；**不新建仓** |
| **高估** | 不加仓；机动仓减持 |
| **严重透支** | PEG > 2 红线（框架行 712，**不因降息取消**）；加速清机动仓 |

### 映射一：PEG 类主锚（快速增长型 · 稳定增长型）

记宏观校准后区间为 `[L, U]`（下限 L、上限 U；按门禁 B-1 补全下限至 0.8）：

| 档位 | 快速增长型（调整后 PEG） | 稳定增长型（隐含 PEG） |
| --- | --- | --- |
| **显著低估** | PEG < L − 0.2（加息/过热档为 < 0.7） | 隐含 PEG < 0.8 |
| **低估** | L − 0.2 ≤ PEG < L | 0.8 ≤ 隐含 PEG < 1.0 |
| **合理** | L ≤ PEG ≤ U | 1.0 ≤ 隐含 PEG ≤ 1.2 |
| **合理偏贵** | U < PEG ≤ 1.5 | 1.2 < 隐含 PEG ≤ 1.5 |
| **高估** | 1.5 < PEG ≤ 2.0 | 1.5 < 隐含 PEG ≤ 2.0 |
| **严重透支** | PEG > 2.0 | 隐含 PEG > 2.0 |

**稳定增长型的独立口径**：框架行 386 固定「隐含 PEG ≤ 1.2」为可接受线，**不随宏观浮动**——故稳定增长型的「合理」档恒为 `1.0~1.2`，其上的 1.2~1.5 / 1.5~2.0 为呈现用的六档刻度。

**滞胀档（`[0.8, 0.8]`）的退化处置**：区间为单点时按 `L = U = 0.8` 执行 → PEG < 0.6 显著低估 / 0.6 ≤ PEG < 0.8 低估 / **PEG = 0.8 合理** / PEG > 0.8 起按合理偏贵拾档，**语义等价于「PEG ≥ 0.8 一律不新建仓」**。

### 映射二：非 PEG 类主锚（**本技能操作化刻度、非框架原文**）

| 类型 | 显著低估 | 低估 | 合理 | 合理偏贵 | 高估 | 严重透支 |
| --- | --- | --- | --- | --- | --- | --- |
| **高研发投入型** | EV/Sales ≤ 同业 0.6× 且 Rule of 40 ≥ 50 | EV/Sales ≤ 同业 0.8× 且 Rule of 40 ≥ 40 | EV/Sales 0.8~1.2× 且 Rule of 40 ≥ 40 | EV/Sales 1.2~1.5× 或 Rule of 40 35~40 | EV/Sales 1.5~2.0× 或 Rule of 40 30~35 | EV/Sales > 2.0× 或 Rule of 40 < 30 |
| **未盈利科技型** | — | 里程碑全部按期兑现 + 现金跑道 ≥ 36 个月 | 里程碑兑现且盈利路径清晰 | 里程碑延期 ≤ 1 项 | 里程碑延期 ≥ 2 项 | 盈利路径不可信 / 现金跑道 < 12 个月 |
| **成熟型企业** | 安全边际 ≥ 40% | 安全边际 ≥ 20%（即市值 ≤ 保守 DCF 80%） | 0% ≤ 安全边际 < 20% | −20% ≤ 安全边际 < 0% | −50% ≤ 安全边际 < −20% | 安全边际 < −50% |

> **强制标注**：非 PEG 类的倍数带（0.6× / 0.8× / 1.2× / 1.5× / 2.0×）与安全边际带（40%/20%/0%/−20%/−50%）是**本技能为实现统一收口而设的操作化刻度**，框架未显式给出。报告中**必须**同时呈现框架原文标准（如「EV/Sales 是否低于同业可比」「市值 ≤ 保守 DCF 的 80%」）与换算后档位，并标注「**操作化刻度、非框架原文**」。
>
> 「未盈利科技型」的**显著低估档为空**——框架对该类型只给"需有清晰的盈利路径和里程碑节点"这一可接受标准，**未给"更便宜"的判据**，故**不设**显著低估档，避免自造激励。

## 宏观叠加（三表 + 作用点边界）

> **权威来源**：框架第五部分·四（行 681~748）。**核心原则（行 685）**：宏观只用于调节"估值容忍度"与"仓位尺度"，**不替代个股基本面判断，也不作为择时清仓的依据**——内在价值决定长期收益，宏观决定当前该出多少钱、冒多大风险。

### 各宏观阶段的判定区间（由工具 `peg_interval` 给出，**不得自行换算**）

| 宏观 stage | 工具 `peg_interval` | 补全后判定区间（B-1） | 合理买入区间含义 |
| --- | --- | --- | --- |
| **过热**（加息） | `[0.8, 1.0]` | `[0.8, 1.0]` | 0.7~0.8 为**空档，不主动加仓** |

## 估值陷阱四项强制核查（框架行 416~421）

> `GV-12`：四项**逐项在报告中留痕**，不得合并为一句"已检查"。

| # | 陷阱 | 框架描述 | 核查动作（须留痕） |
| --- | --- | --- | --- |
| 1 | **低 PE 陷阱** | PE 低但行业处于景气顶点（如周期股），未来盈利下降会导致 PE 被动抬升 | 结合**行业周期位置**判断；若判为周期顶点 → **PEG 不适用**，改走 DCF（`GV-9`） |

## 分批建仓规则（框架行 393~401）

> **归属声明**：本规则在框架中位于第4步·估值锚定之下，故归本技能；**仓位上限数值**（单只 10/15/20%、行业 40%）归 `garp-portfolio-review`（P4-8）。

| 路径 | 适用 | 节奏 |
| --- | --- | --- |
| **默认三分法** | **绝大多数标的**（主从关系中的默认路径） | 1/3 首仓 → 右侧确认后补至 2/3 → 连续 2~3 季兑现后补齐 |
| **左侧布局** | 行业遇短期利空（政策打压、周期低谷等），但**长期逻辑未破坏**（"杀估值"而非"杀逻辑"） | 首批 ≤ **标的最终仓位的 50%**（**可建上限、非必须建到**，越不确定越压低）；剩余待右侧信号确认后再补 |
| **右侧一次性 2/3** | **仅**在「**渗透率突破 15% 临界点 + 财报连续 2 个季度超预期 + 行业景气明确上行**」**三信号共振**时启用 | 剩余 1/3 回调至 20 日均线补 |

**三条硬约束**：

1. **补至 2/3 的常规信号 ≠ 一次性建 2/3 的门槛**——前者是"产业景气加速 / 财报超预期 / 趋势反转确认**三者至少其一**"；后者须**三信号共振**（框架行 399 的强制区分）。**不得混淆**；
2. **止损优先于补仓**——建仓初期（持仓 < 最终仓位的 50%，**或**持仓 ≥50% 但逻辑尚未经 2~3 个季度财报持续兑现验证）执行 **8%~10% 硬止损**，**优先于"跌破估值下限补仓"**；**不得以"股价更便宜"为由逆向补仓**（框架行 398）；
3. **右侧一次性 2/3 后止损仍按"建仓初期"口径**（8%~10%），待财报持续兑现、逻辑充分验证后才放宽至底仓口径（框架行 412）。

## 工具使用指南

### 工具使用注意（实测已知，务必遵守）

1. **`financial_rigor.py calc` 不支持 `^` 幂运算符**——字符白名单不含 `^`，幂运算须写 `**`；**负号开头须加引号**：`--expr="-3+12"`，否则被误解析为参数。
2. **量纲三档不同，须逐条核对**：`adjusted-peg` / `rule-of-40` / `peg` 的增速与利润率用**百分点**（35 = 35%）；`implied-growth` 的 `--net-margin` / `--guidance-growth` 用**小数**（0.12 = 12%）；`pe-percentile` 用 **PE 数值**。实测把 12 当作 12% 传入 `implied-growth` 会得到"年化净利率 1200%"的错误输出。
3. **`macro_calibrator.py stage` 的 `--stage` 枚举仅 4 个**：`衰退` / `复苏` / `过热` / `滞胀`——**没有"中性"档**；框架的中性基准区间 `1.0~1.2` 须按"宏观叠加"节回退规则处理。
4. **`macro_calibrator.py data` 返回两个语义不同的 stage 字段，取值须认字段**：`--stage` **取 `econ_stage.stage`**（美林阶段，实测 `"衰退"`，属 4 档合法枚举，可直接串联——`calibrate --stage 衰退 …` 实测 exit 0）；`rate_stage.stage` 为**利率阶段**（实测 `"降息/低利率"`，**非** `stage` 枚举），**语义不同、不可混用**（直接喂给 `--stage` 会报"非法 stage"）。两字段均带 `confidence = 低`、`manual_review = true`，须人工确认后使用。
5. **`dcf` 的 C1 审计对 `--r` 有币种区间约束**（实测 CNY 为 `[6.0%, 9.0%]`）——ESG 搁浅资产要求上调 `--r` 时可能越界触发告警，须按"执行流程·第七步"的张力说明留痕，**不得为消警而下调 `--r`**。
6. **`dcf` 的 C1 审计对 `--g-terminal` 有币种上限**（实测 CNY 为 `2.0%`）——`--g-terminal 2.5` 会触发 `C1: 永续增速 g=2.50% 超过 CNY 的上限 2.0%`。**保守口径**应取 ≤ 上限值。
7. **`in_research_scan.py` 的 `pipeline-npv` 须以脚本或 `-m` 模块形式调用**（`scan` 子命令须用 `-m` 模块形式）；`pipeline-npv` 的 `--sensitivity` 为**绝对步长**规格（如 `"r=0.01;p=0.10"`）。
8. **`governance_data.py` 的 `--env-risk-level` 取值为 `高` / `低`**（**不是**"高风险"/"低风险"，实测传"高风险"报"非法档位"）。
9. **`pe-percentile` 的 `--pe-series` 须为 JSON 数组字符串**，须加引号。
10. **`governance_data.py` / `macro_calibrator.py` 的 `--help` 在 GBK 控制台可能因中文编码抛异常**——不影响子命令本身执行；如需帮助可加 `$env:PYTHONIOENCODING="utf-8"`。

| 年报字段抽取 | `annual_report_parser.py` | 只做字段映射，不重解析 |

## 风控硬编码（GV-1 ~ GV-12）

| 编码 | 规则 | 执行要求 |
| --- | --- | --- |
| **GV-1** | **类型判定须留证且不得择利** | 须列数据依据与**被排除类型**；禁止为套宽松阈值而挑选类型 |
| **GV-2** | **工具内置评级不进入档位判定** | `adjusted-peg` 的 `tier` / `peg` 的 `rating` / `rule-of-40` 的 `verdict` 一律**只作呈现**；档位按"统一收口六档"二次映射 |
| **GV-3** | **「同业可比」须不少于 2 家并列表** | EV/Sales 判定不得以"行业均值"一句话替代；须列可比公司名、倍数、口径与数据截止日 |
| **GV-4** | **DCF 参数须保守且受硬约束** | 继承 `terminal_value.py audit` 三条（r−g 宽度 / 币种一致 / 离散风险归属）；`--g-terminal` 不得高于长期名义 GDP 增速量级、`--r` 不得低于同币种无风险利率；越界须说明理由并标「非保守口径」 |
| **GV-5** | **辅助工具只降不升** | PE 分位 / 隐含增速 / 宏观区间与主锚冲突时**只能降一档**，须写明触发项与数值；禁止升档 |
| **GV-6** | **宏观与 ESG 参数只能来自工具** | 禁止自行换算 stage、禁止自行估算折价率；报告中须贴出工具原始字段 |
| **GV-7** | **仓位量只透传、不裁量** | 报告**不得出现"建议单只上限 X%"**；`cash_floor` / `single_cap` / `industry_cap` / `single_caps` / `position_cap_after` 原样透传 |
| **GV-8** | **不建独立聚合器** | 本技能是编排层，不得新增汇总工具或内置加权公式 |
| **GV-9** | **「不适用」须显式判定** | 增速 ≤0 / 亏损 / 周期顶点等情形须标「不适用」并按类型重定，**不得硬套 PEG**；三次重定仍不适用则出「数据不足，无法估值」 |
| **GV-10** | **未量化项不得臆造** | 研发管线 NPV 无有效参数时标 `data_insufficient` 并终止该项量化；里程碑无证据时只作定性并标注数据缺口 |
| **GV-11** | **数据截止日期强制标注** | PE / 市值 / 一致预期 / 研发强度 / 宏观参数 / ESG 评级均为时变项，结论仅对截止日有效 |
| **GV-12** | **估值陷阱四项强制核查** | 低 PE 陷阱 / 一次性收益 / 股权稀释 / 研发费用化扭曲，**逐项**在报告中留痕 |

## 注意事项

1. **`GV-2` 是最容易出错的一条**——`adjusted-peg` 工具自带 `tier="低估"`，`peg` 工具自带 `rating="合理 (0.8~1.2)"`，其分档线是 `0.8 / 1.2`，而本框架的低估线是 **`1.0`**（框架行 383）。**照抄工具评级会造成系统性低估风险**。实测示例：调整后 PEG = 1.10 时工具判"合理"，而本框架在加息/过热档（区间 `[0.8, 1.0]`）判「**合理偏贵**」。
2. **量纲三档不一致是本任务最隐蔽的坑**——`implied-growth` 用小数、`adjusted-peg` / `rule-of-40` / `peg` 用百分点。写错量纲不会报错，只会给出错误结论。**每次调用前核对量纲**。
3. **`macro_calibrator data` 的 stage 名不能直接喂给 `stage`**——实测 `data` 给出 `"降息/低利率"`，而 `stage` 只接受 `衰退 / 复苏 / 过热 / 滞胀`。须**人工确认映射**并保留 `manual_review=true` 标注。
4. **ESG 上调 `--r` 会触发 DCF 的 C1 审计告警**——这是**既定叠加的必然结果**（框架行 431），不是参数错误。报告中须显式区分「C1 由 ESG 叠加触发」与「参数本身越界」。**不得为消除告警而下调 `--r`**。
5. **ESG 折价可能与宏观区间冲突**——当 `宏观上限 × discount_factor < 宏观下限` 时区间退化为单点，须按单点执行并显式标注（见"执行流程·第七步"）。
6. **稳定增长型的隐含 PEG 上限不随宏观浮动**——框架行 386 固定「≤1.2」；宏观档位只影响报告呈现与建仓节奏提示，**不改写 1.2 这条可接受线**。
7. **未盈利科技型的 ESG 折价**——该类型主锚是 PS / EV-Sales，折价施加于「EV/Sales 同业可比倍数」之上（即要求更低的 EV/Sales 才达同一档位）；**不得**把折价直接加到现金流上。
8. **多地上市须分别取数**——同一公司的 A/H/美股 PE、市值、股本口径存在差异，须分别取证并显式标注所用市场口径。

## 局限性

1. **五类主锚的可接受标准颗粒度不均**——「快速增长型」有明确四档 PEG 阈值，而「未盈利科技型」只有定性的"清晰的盈利路径和里程碑节点"。本技能用统一六档（A-1）收口，但**非 PEG 类的刻度是本技能操作化产物**，其绝对数值不具备框架原文的权威性。
2. **一致预期的时效短**——未来 2~3 年 EPS 一致预期的有效窗口 ≤3 个月；超过即须标注"预期可能已过时"，结论可靠性随之下降（`GV-11`）。
3. **宏观 stage 的判定不由本技能保证**——本技能只消费 `garp-macro`（P4-2）的 stage；stage 判错会通过区间替换**系统性地**改变全部档位结论。
4. **ESG 评级信号滞后且口径不一**（框架行 318 同源提醒）——`esg` 工具的折价率由入参决定，入参本身依赖定性判断（转型路径是否"可验证"）。
5. **DCF 对输入高度敏感**——`--g-terminal` 与 `--r` 的小幅变化会显著改变 `per_share`；本技能用 `GV-4` 三条硬约束与审计告警兜底，但**不消除**该敏感性。
6. **本技能不判断"值不值得买"**——档位只回答"贵不贵"；是否建仓仍须 `garp-investment-checklist`（P4-3）的门槛结论与 `garp-exit`（P4-6）的卖出纪律共同约束。
