# 深度公司系列（1~3年景气）(Mid-Term Deep Company Series)

3-8 篇长文拆一家公司：从认知重置到决策框架完整闭环（1~3 年景气投资框架）

> 本技能属**中期链（1-3 年）**，与长期链 `deep-company-series`（10 年 / 巴芒段李框架）**物理隔离、功能互补**。核心理念：**景气驱动，动态持有，纪律退出**——融合欧奈尔/林奇/郑希/李进四位景气大师视角，为指定公司撰写可公开发布的深度长文系列。**禁止使用「护城河永续」「终局思维」「持有10年」等长期框架术语。**

## 核心功能

为指定公司撰写一个深度长文系列（3-8 篇，按公司复杂度定，约 3-12 万字），从认知重置到决策框架完整闭环，适合公众号/视频号等公开渠道发布。**核心 IP 不是"会写"，而是"会改"——99% 的财经文章在违反本 skill 的事实核查标准**。

### 四大师视角分工（对齐 V2.0 权威分工）

| 大师 | 思维模式 | 职责 | 对应篇目 |
|------|---------|------|---------|
| 林奇 | 侦探思维 · 常识与求证 | 选股起点 + 估值定价 | 01/03/04 选股、08 PEG 估值 |
| 郑希 | 物理学家思维 · 周期与第一性原理 | 赛道选择（ROE 拐点、产业景气、地缘政治） | 02/05/06 ROE、景气、地缘 |
| 李进 | 系统工程师思维 · 均衡与渗透率 | 组合管理 + 治理（渗透率、二阶导、管理层、治理一票否决） | 03/05/06/07 |
| 欧奈尔 | 工程师思维 · 信号与纪律 | 风控底线（止损位、卖出触发） | 08 止损与卖出纪律 |

### 篇数适配公司复杂度

篇数不固定为 8，取决于公司复杂度：

| 复杂度 | 特征 | 篇数 | 例子 |
|--------|------|------|------|
| 高 | 多条业务线各自成生意 + 隐藏资产/投资组合 + 管理层史料丰富 | 7-8 篇 | 腾讯 |
| 中 | 2-3 条业务线 + 一个重大时代变量 | 4-6 篇 | — |
| 低 | 主业清晰、核心问题少而集中 | **3 篇** | 快手 |

**3 篇标准合并方式**：01 认知重置+生意概览 / 02 最大变量（含产业景气）/ 03 决策终章（PEG 估值 + P0~P5 卖出纪律）。

### 8 主轴全模板（复杂公司用；简单公司当检查清单折叠）

| # | 篇名模板 | 核心问题 | 核心思想来源 | 字数 |
|---|---------|---------|------------|------|
| 01 | 你以为你看懂了 X，其实没有 | 认知重置：破 3 个常见错觉 | 林奇"常识验证" | 4,000-5,000 |
| 02 | X 的护城河——`<生意本质一句话>` | 护城河深不深、**1~3年景气周期中能否支撑ROE向上** | 郑希"ROE护城河" | 6,000-8,000 |
| 03 | X 的最大利润引擎——`<最赚钱业务>` | 主业是什么、为什么能持续、**景气周期位置** | 林奇+李进 | 6,000-8,000 |
| 04 | X 藏在账上的另一家公司——`<隐藏资产>` | 投资组合 / 子公司 / 隐藏价值 | 林奇"隐蔽资产型" | 8,000-10,000 |
| 05 | AI与产业景气时代，X 是赢家还是输家 | **分业务拆AI影响 + 渗透率与产业景气判断 + 地缘政治风险** | 郑希+李进 | 8,000-10,000 |
| 06 | 拆X的财报：ROE、现金流与景气信号 | **ROE 8季度趋势、毛利率/FCF、二阶导、渗透率** | 郑希+李进 | 8,000-10,000 |
| 07 | `<管理层金句>`——X 的管理层值不值得托付 | **李进四维度20分制+科研转化20分制+治理一票否决** | 李进 | 8,000-10,000 |
| 08 | 多少钱值得买，什么信号必须卖（系列终章） | **PEG为核心估值（引用 valuation-thermometer）+ 分批建仓 + P0~P5 卖出纪律（引用 exit-signal）** | 林奇PEG+欧奈尔止损 | 10,000-12,000 |

加一篇 `00-系列说明.md` 作为目录索引（不发表，含信息丰富度评级）。

**篇目必须适配公司**：模板是腾讯长出来的，不是套子。某篇没有独立内容，就替换成该公司特有的主轴，或按 3 篇标准合并方式折进更少的篇数。

## 写作标准

### 写作风格规范

- **语气**：直接、犀利、不说废话，第一句就给数字或反常识结论
- **景气投资框架**：欧奈尔/林奇/郑希/李进视角穿插（但不堆砌名言）
- **不预设立场**：先摆数据→推逻辑→得结论
- **呈现正反两面**：每个核心判断都附"但另一方面..."的反方
- **公众号体感**：前 18-20 字必须能独立站住（手机预览）
- **标题风格**：用反差数字或反共识结论做钩子（"ROE连续8季度攀升"），避免流量党比喻

### 禁用词（含中期口径红线）

| 禁用 | 原因 | 替代 |
|------|------|------|
| 显然 / 必然 / 一定 | 主观绝对化 | 数据显示 / 证据表明 |
| 我认为 / 我觉得 | 主观腔调 | 删除或改为"按本框架" |
| 教科书级别 / 神来之笔 | 流量党褒奖 | 描述具体事实 |
| 严重不匹配 / 严重低估 | 强主观词 | 给具体折让百分比 |
| 完美 / 无可挑剔 | 单边判断 | 加上反方观察 |
| "长期持有" / "永远不卖" / "买入并遗忘" | 长期框架术语（中期口径红线） | "1~3年景气持有" / "每季度用景气数据体检" |
| 护城河永续 / 终局思维 / 持有10年 | 长期框架术语（中期口径红线） | 1~3 年景气周期中护城河是否支撑 ROE 向上 |

### 篇内结构模板

每篇有固定骨架：
- **头部引用块**：`> 《看懂X》系列 · 第 0N 篇 · <主轴>`，开篇加阅读时间
- **第一节永远是钩子**：一组反常识数字 / 一条反常曲线 / 一个让市场担心的数字，不写背景铺垫
- **每篇末尾**：`## 本篇要点回顾`（5-8 条，数字与正文严格一致）+ `## 下期预告`（用尖锐问题预告，不剧透结论）
- **结尾两行斜体**：`*本文是《看懂X》系列第 0N 篇...*` + `*本系列基于公开信息和1~3年景气投资框架研究，不构成任何投资建议。*`

### 严苛事实核查 Checklist

#### 写之前就要警惕的"伪精确"陷阱

1. **概率加权期望值** — 只列情景 + 触发条件 + 方向，不算加权期望
2. **第三方测算 MAU/份额** — 用最可信两个 anchor，其他定性描述
3. **历史增速线性外推** — 改用情景假设 + 高/低区间 + 不是承诺
4. **未公开的持股比例** — 给区间，标"不可知"
5. **强归因** — 多重原因都列出来，不做单一归因
6. **渗透率精确值** — 标注"估计"并注明来源，黄金区/加速临界点口径对齐 `mid-industry-research`

#### 修订时必跑的 7 项检查

```
□ 1. 跨篇数字一致性：总市值、净利润、关键持股 %、ROE、PEG 全系列对齐
□ 2. 口径标注：Non-IFRS / GAAP / Non-IFRS-SBC / FCF / PEG 各用哪个，全文清楚
□ 3. 重复加计扫描：已并表子公司不在"投资组合"里、SOTP 不双算
□ 4. 横向比较公平性：不能"主业 PE" vs "对手 PE（不剔）"
□ 5. 概率加权全删
□ 6. 绝对化表述全弱化：grep "显然|必然|严重|教科书|完美|长期持有|永远不卖"
□ 7. 第三方数据来源标注：每条非财报数据后跟"（来源：X）"
```

#### 模型偏好（已知硬错误风险，1~3 年景气版）

- 历史回报倍数：必须用累计投入口径（如 Riot 33 倍 不是 58 倍）
- 持股比例：必须看最新富途/财报口径（如腾讯持有美团 1.5% 不是 6.4%）
- "派息分派"会计处理：视同处置收益按 IFRIC 17 在宣派日确认
- 总股本会反弹：SBC 集中年初授予会让股本短期上升
- **PEG 必须用 `financial_rigor.py` 计算，禁止 LLM 心算**；档位判定以 `valuation-thermometer` 五档输出为准
- **ROE 8 季度趋势**：连续 3 季同向才判拐点，单季波动判噪音（对齐郑希口径）

## 执行流程

### 阶段 1：调研（写 01-02 篇前完成）

1. **信息丰富度评级（AI 研究偏见预警，必执行）**

   | 等级 | 特征 | AI 研究陷阱 | 应对策略 |
   |------|------|-----------|----------|
   | **A级（信息充裕）** | 上市多年、券商覆盖广 | 共识过强，输出趋同市场定价 | 重点做**反面检验**与**非共识视角** |
   | **B级（信息适中）** | 上市 1-3 年、覆盖有限 | 用「合理推测」填补空白，产生虚假确定性 | 推算数据标注置信度 |
   | **C级（信息稀缺）** | 冷门/新上市/新兴市场 | 因资料不足过度保守 | 转「第一性原理模式」，聚焦核心问题 |

   评级结果影响各篇调研深度，并在 `00-系列说明.md` 中注明。
2. **阅读公司近 5 年年报、最新季报** — 使用对应市场数据工具 + 搜索工具
3. **阅读至少 3 份独立卖方研报**（找共识 + 反共识）
4. **使用 `/mid-investment-research` 先生成内部研究底稿** — 快速四大师报告中期版，替代长期版 `/quality-screen` 去劣筛选
5. **与用户确认核心论点**（避免写完才发现方向不对）

### 阶段 2：写作（按 01→末篇顺序写，不跳）

- 每篇写完先存 `reports/{公司名}/《看懂{公司名}》-mid-{YYYYMMDD}/0X-XX.md`
- 不立即推 GitHub——等用户审阅再提交

### 阶段 3：跨篇一致性扫描（全部篇目写完后）

检查同一数字跨篇是否一致、同一术语首次出现是否解释、引用关系是否对应、要点回顾 vs 正文数字是否一致。

### 阶段 4：数据抽检与发布前最终核查

```bash
# Step 1 - 提取抽检清单（15%随机抽样）
python tools/common/report_audit.py extract \
  --report reports/{公司名}/《看懂{公司名}》-mid-{YYYYMMDD}/00-系列说明.md --seed 42

# Step 2 - 对清单每项从可靠信源取数（按市场分别使用对应工具）
#   计算验算：tools/common/financial_rigor.py（禁止 LLM 心算）

# Step 3 - 输出准出/打回判决
python tools/common/report_audit.py verdict \
  --results '<填好的JSON>' --report {系列目录}
```

- **【准出】** 所有抽检点偏差 ≤ 1% → 报告可发布
- **【打回】** 任意点偏差 > 1% → 修正后重新抽检

```bash
# 推送前必须本地 grep 一次（按本工作区隐私规则）
grep -r "<本机用户名>\|/Users/\|<个人身份信息>" reports/ | head
```

确认无误后才 `git pull --rebase && git commit && git push`。

## 修订意见处理流程

### 1. 先核查事实（不要直接改）

用户说"X 数据不对"时，先用工具找原始数据交叉验证，给出"用户说的数据 vs 我查到的数据 vs 我之前用的数据"三方对比。

### 2. 判断修订级别

| 级别 | 类型 | 处理 |
|------|------|------|
| 🔥 硬错误 | 数字错、归因错、口径错 | 必改，不需犹豫 |
| ⚠️ 主观化 | 强主观词、绝对化、流量党比喻 | 弱化或删除 |
| 🔬 颗粒度 | 来源标注、口径细化 | 优先级低，按可读性平衡 |
| ❓ 不可靠 | 第三方测算差异大 | **删比改更稳** |

### 3. 修订后联动检查

修一处先想"哪些地方还会引用这个数字/概念"——改了总市值，全系列联动改 PE；改了持股 %，改 TOP 10 排序；改了术语口径，改首次定义 + 后续引用。

### 4. 推送后立即报告

推送成功（commit hash），[N] 处修订总结带表。

## 核心原则

1. **事实核查标准** — 每个数据必须来自可靠来源，修订时必跑 7 项检查
2. **数据必须标注来源** — 关键数据至少 2 个来源交叉验证
3. **不虚构数据** — 搜不到就标注"估计"或"不可知"
4. **不用AI腔调** — 禁止"让我们一起来看看"等套话
5. **客观性原则** — 区分事实与观点，用数据支撑判断
6. **呈现正反两面** — 每个核心判断附反面论据
7. **诚实面对信息缺口** — 宁可标注"数据不足"，也不用推测填充
8. **不算期望年化回报加权值** — 主观概率分配会误导读者
9. **引用不重复定义** — 估值引用 `valuation-thermometer`，卖出引用 `exit-signal`（P0~P5，时间止损归 P2），景气引用 `mid-industry-research`，管理层引用 `mid-management-deep-dive`
10. **中期口径红线** — 禁止「护城河永续」「终局思维」「持有10年」等长期术语，持有周期以景气周期长度为准
11. **禁止 LLM 心算** — PE/ROE/PEG/市值必须用 `financial_rigor.py` 验算

## 注意事项

- 网络搜索须使用本地五工具组合（详见 [web-search-tools](../tools-scripts/web-search-tools.md)），港股须 doubao+tavily 双源、美股须 exa+doubao 双源
- 市值必须手算校验：股价 × 总股本，与报告市值对比
- 货币单位要明确（港币/人民币/美元），防止混淆
- PEG = PE(TTM) ÷ 未来2年预期利润增速（%），档位判定以 `valuation-thermometer` 五档输出为准（0.8/1.2/1.5/2.0 边界），不自行重复定义阈值
- 卖出纪律统一引用 `exit-signal` P0~P5（时间止损归 P2），不用自造层级
- 管理层 20 分制 / 科研转化 20 分制口径对齐 V2.0 与 `mid-management-deep-dive`
- 信息丰富度评级（A/B/C 级）必须在 `00-系列说明.md` 中注明
- 报告发布前必须通过 `tools/common/report_audit.py` 数据抽检（偏差 ≤1% 准出、>1% 打回）
- 推送前必须用 grep 扫描本机用户名、`/Users/`、真实姓名等隐私字段
- 报告写完后主动询问是否推送到 GitHub

## 局限性说明

- 港股小票、新上市公司可能无法获取到完整信息
- 扫描版PDF限制：A股年报常为扫描版PDF，可能无法提取文本内容
- 非实时数据：工具获取的数据可能有延迟

- 写作框架非决策工具：本技能产出的是内容，不替代买入决策技能（`mid-investment-checklist`）与卖出决策技能（`exit-signal`）
- 深度长文耗时/字数大：适合公开内容输出场景，若仅需快速结论请用 `/mid-investment-research` 或 `/mid-investment-team`
- 不构成投资建议，仅供学习研究参考
