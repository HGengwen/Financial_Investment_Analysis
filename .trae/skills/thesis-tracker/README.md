# 投资论文追踪 (Thesis Tracker)

买入后的纪律系统：建立投资论文、持续追踪检查、基于证据判断论文健康度，输出系统化的持有/调仓建议

---

## 快速开始

### 基本调用方式

```
/thesis-tracker {公司名}
```

支持三种输入格式：

| 输入方式 | 示例 | 说明 |
|---------|------|------|
| 首次建立 | `/thesis-tracker 腾讯` | 不存在论文文件时，进入建立论文模式 |
| 强制重建 | `/thesis-tracker 腾讯 建立论文` | 强制重新建立投资论文 |
| 季度检查 | `/thesis-tracker 腾讯 季度检查` | 基于最新财报进行论文检查 |

例如：
- `/thesis-tracker 腾讯`
- `/thesis-tracker 茅台 建立论文`
- `/thesis-tracker 英伟达 季度检查`

---

## 核心功能

对指定公司执行投资论文追踪检查。从建立论文到持续追踪，系统化管理买入后的持有纪律，解决"该卖舍不得卖、不该卖恐慌卖出、忘记当初为什么买"三大痛点。

### 两种操作模式

1. **模式A：建立投资论文** — 首次使用时建立结构化论文，写入 `reports/{公司名}-thesis.md`
2. **模式B：追踪检查** — 后续使用时基于最新财报检查论文健康度

### 论文五要素

1. **核心论文（5句话）** — 必须用200字以内写清楚买入逻辑
2. **核心假设清单** — 拆解为3-7个可验证的具体假设
3. **红线清单** — 触发任何一条必须重新评估的致命条件
4. **估值锚点** — 买入时、乐观/中性/悲观目标价与安全边际
5. **追踪记录表** — 历次检查的健康度、核心变化、动作建议

### 建立论文五步流程

1. **A0 数据收集** — A股/港股财务数据与行情获取
2. **A1 核心论文** — 5句话写清买入逻辑
3. **A2 核心假设清单** — 3-7个可验证假设
4. **A3 红线清单** — 致命/严重/警告三级红线
5. **A4 估值锚点** — 三情景估值（使用 `financial_rigor.py`）
6. **A5 保存论文** — 写入 `reports/{公司名}-thesis.md`

### 追踪检查七步流程

1. **B1 读取现有论文** — 加载核心论文、假设清单、红线清单
2. **B2 收集最新数据** — 最新财报、重大事件、股价估值、内部人交易
3. **B3 逐条检查核心假设** — 🟢成立 / 🟡边际弱化 / 🔴受损 / ⚫破裂
4. **B4 红线检查** — 逐条检查红线是否触发
5. **B5 估值更新** — 当前估值与买入时、上次检查对比
6. **B6 输出追踪报告** — 健康度评分 + 持有/加仓/减仓/清仓建议
7. **B7 更新论文文件** — 追加检查记录到追踪记录表

## 使用示例

### 示例1：首次建立论文
```
/thesis-tracker 腾讯
```
不存在 `reports/腾讯-thesis.md` 时，进入建立论文模式，输出包含核心论文、假设清单、红线清单、估值锚点的完整论文文件。

### 示例2：季度追踪检查
```
/thesis-tracker 腾讯 季度检查
```
基于最新财报数据，逐条检查核心假设与红线，输出论文健康度评分与持有/调仓建议。

### 示例3：强制重建论文
```
/thesis-tracker 茅台 建立论文
```
强制重新建立投资论文，覆盖原有论文文件。

## 输出报告

报告将保存在以下位置：

| 报告类型 | 文件路径 |
|---------|---------|
| 投资论文 | `reports/{公司名}-thesis.md` |
| 追踪检查报告 | 追加到 `reports/{公司名}-thesis.md` 的追踪记录表 |

### 论文文件结构

```markdown
# {公司名} 投资论文
**建立日期：{YYYY-MM-DD}**

## 核心论文（5句话）
我以 ___元 买入 ___公司，因为：
1. 这门生意的本质是___
2. 它的护城河是___
3. 管理层___
4. 当前价格相当于内在价值的___折
5. 即使我错了，下行风险可控，因为___

## 核心假设清单（3-7个可验证假设）
## 红线清单（致命/严重/警告三级）
## 估值锚点（买入时/乐观/中性/悲观）
## 追踪记录表（历次检查记录）
```

### 追踪报告结构

```markdown
# {公司名} 投资论文追踪报告
**检查日期：{YYYY-MM-DD}**

## 一、论文健康度评分（X / 10分）
## 二、核心假设检查结果
## 三、红线检查结果
## 四、本期关键变化（不超过500字）
## 五、估值更新
## 六、结论与行动建议（持有/加仓/减仓/清仓）
## 七、下次检查需关注的重点
```

### 结论必须明确回答

1. **论文还完整吗？** 完整 / 边际弱化 / 受损 / 破裂
2. **该怎么做？** 加仓 / 持有 / 减仓 / 清仓
3. **下次检查时间**：下一个季报发布后 / 某个特定事件后

## 追踪标准

### 设计理念

大多数投资者的流程是：研究 → 买入 → 祈祷。缺少买入后的系统化跟踪。巴菲特和李录的做法是：**买入前就写下卖出条件**，然后每个季度检查论文是否完整。

### 论文健康度评分

**计算公式**：
```
健康度 = 10 - (⚫破裂假设数×3) - (🔴受损假设数×2) - (🟡弱化假设数×1) - (红线触发数×5)
最低1分，最高10分
```

| 评分 | 含义 | 建议动作 |
|:----:|------|---------|
| 9-10 | 所有假设成立，论文比买入时更强 | 考虑加仓 |
| 7-8 | 核心假设成立，个别边际弱化 | 继续持有 |
| 5-6 | 1-2个假设受损，但核心逻辑未变 | 持有但提高警惕 |
| 3-4 | 多个假设受损，论文基础动摇 | 考虑减仓 |
| 1-2 | 红线触发或核心假设破裂 | 强烈建议卖出 |

### 假设状态定义

| 状态 | 含义 |
|------|------|
| 🟢 **成立** | 最新数据支持该假设 |
| 🟡 **边际弱化** | 数据仍在可接受范围，但趋势不利 |
| 🔴 **受损** | 数据明确不支持该假设 |
| ⚫ **破裂** | 假设已被推翻 |

## 核心原则

1. **买入前就写好卖出条件** — 冷静时做的决策比恐慌时做的好
2. **论文要具体到可验证** — "公司很好"不是论文，"ROE>25%且趋势稳定"才是
3. **红线一旦触发就行动** — 最怕的是"再等等看"，这是亏大钱的开始
4. **论文破裂 ≠ 股价下跌** — 股价跌30%不一定要卖，论文破裂才要卖
5. **诚实面对错误** — 论文建错了就承认，不要为了面子硬撑
6. **不预设立场** — 不因为持有就倾向于"论文完整"，证据指向哪边就写哪边
7. **数据准确性** — 关键数据至少两个来源交叉验证
8. **客观性原则** — 区分事实与观点，用数据支撑判断

---

## 注意事项

- 禁止使用 WebSearch 和 WebFetch 工具（中国大陆地区不可用）
- 估值数据须使用 `financial_rigor.py verify-valuation` 和 `three-scenario` 精确计算
- 关键财务数据必须至少两个来源交叉验证
- 论文核心必须用5句话写清楚，写不完整说明买入决策不够清晰
- 核心假设清单通常3-7个，太少说明思考不够深入，太多说明论文不够聚焦
- 红线触发时在报告中用醒目标注，给出明确的行动建议
- 不预设立场：先摆数据 → 推逻辑 → 出结论

---

## 局限性说明

- **数据可得性**：港股小票、新上市公司可能无法获取到完整信息
- **估值估算主观性**：内在价值估算存在主观判断，不同方法可能得出不同结论
- **假设验证滞后性**：某些假设需要多个季度才能验证，短期内难以判断
- **非实时数据**：工具获取的数据可能有延迟，不是实时数据
- **论文建立质量依赖**：如果初始论文建立质量不高，后续追踪效果会大打折扣
- 不构成投资建议，仅供学习研究参考
