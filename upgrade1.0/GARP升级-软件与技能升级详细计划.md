## 0. 使用说明与拆分原则

### 0.1 拆分结论速览

总计划 Phase 0~5 的 16 个粗粒度任务，按「一个任务一个可独立验收交付目标」纪律（见总计划 2.0 第 1 条），进一步拆分为 **48 个子任务**：

### 0.2 拆分基本原则

1. **一个交付目标一个任务**：凡交付目标可独立验收（一个工具子命令 / 一个技能 / 一个数据字段组 / 一个评分器），即独立成子任务。
2. **可拆可不拆则以「验收标准唯一性」为准**：若子块拥有与其他子块不同的验收标准、且其失败会独立造成返工，则拆开；否则合并。
3. **不拆分的情形**：
   - Phase 0 的 P0-1 命名冲突处理属「单一交付目标（重命名 2 技能 + 同步全部引用）」，且两处重命名必须一次原子完成以保证 `garp-` 前缀一致性 → **不拆**；
   - Phase 2 的 P2-1 三表（利率/经济/美林）同属能力域 C20，共享同一数据结构与「逐格一致」验收标准，拆分会造成同一文件反复改同一张 dict → **不拆**；
   - Phase 3 的 P3-7 治理字段（质押率/管理层持股/分红回购/销售费用率/ESG 摘录）同属「一个数据字段组」，共享同一抽取框架与 `confidence + 源文本摘录` 输出 → **不拆**，列为内部子步骤。

### 0.3 编号规则与映射

- 子任务编号形如 `P{Phase}-{序号}`，Phase 内序号连续。
- 每个子任务正文首行标注 `来源`（对应总计划编号），用于追溯「详细计划 ↔ 总计划」映射（完整映射见第 2 节总表）。
- 子任务编号 = 该任务的编排子目录名（如 `upgrade1.0/P1-1/`）。

### 0.4 执行纪律（刚性，继承总计划 2.0）

每个子任务正式开发前，仍须**先产出该子任务的《开发方案与计划》**，并经用户**明确确认（开工门禁）**方可开发；开发完成后，须向用户呈报「任务完成判定」（交付件清单 + 验收标准逐条对照 + 回归无损/口径隔离结论），经用户**明确确认（完成门禁）**后方可流转下一任务。**不跳步、不合并推进、不以 AI 单方判定替代用户确认。** 每个 Phase 全部子任务通过完成门禁后，还须完成该 Phase 的文档与技能同步（见 0.6），并纳入 Phase 完成呈报。

**《回归核对记录》的独立性论证要求（刚性，2026-09-17 新增，P4-6~P4-22 统一遵循）**

判定「既有技能 / 既有工具零改动」时，**不得单独依赖文件时间戳**——工作区可能发生「批量重新物化事件」，使既有文件的时间戳被统一重写而不改内容（**已实测四批，内容均未变**：① 2026-09-17 11:41:59~11:42:00，`upgrade1.0/P4-1~P4-4` 全部 20 份交付物 + `.trae/skills/` 下 7 个既有 `garp-*` 技能文件被同批重写——P4-5《回归核对记录》§2.4 首次披露；② 2026-09-17 13:50:59，7 个既有 `garp-*` 技能文件（`garp-geo-policy/README.md`、`garp-investment-checklist/{README,SKILL}.md`、`garp-macro/{README,SKILL}.md`、`garp-management/{README,SKILL}.md`）——P4-6《回归核对记录》§2.4 补录；③ 2026-09-17 14:02:30~14:02:38，`garp-valuation/{README,SKILL}.md`——P4-6《回归核对记录》§2.4 补录；④ **2026-09-17 17:38:44**，**11 个既有 `garp-*` 技能文件**（`garp-exit/{SKILL,README}.md`、`garp-valuation/{SKILL,README}.md`、`garp-investment-checklist/{SKILL,README}.md`、`garp-macro/{SKILL,README}.md`、`garp-management/{SKILL,README}.md`、`garp-geo-policy/README.md`；`garp-geo-policy/SKILL.md` **未入批**，属选择性重新物化）——P4-7《回归核对记录》§2.4 补录）。故《回归核对记录》须在时间戳比对之外，**至少补充两项独立论证**：

1. **内容锚点核验**：对既有文件抽样比对**关键行的逐字一致性**（与已交付记录/声明中的引用比对），证明内容未变；
2. **状态回写检测**：检索既有文件中是否出现**本任务新增内容**（如本任务技能名、本任务交付状态标注），命中数须为 **0**。

两者结论与时间戳发生冲突时，**以内容为准**；并须在记录中**如实披露**该批量事件及其判定依据，不得以「时间戳晚于 X」的单一推理下结论。

### 0.6 每个 Phase 完成后文档与技能同步（刚性）

每个 Phase（0~5）全部子任务依次通过「完成门禁」后，须**在该 Phase 收口前同步更新**本 Phase 实际触及的工具所对应的文档与技能参考，确保「工具实现 ↔ 用户指南 ↔ 技能参考」三者口径一致、不留陈旧引用。

**同步对象（两处，仅限本 Phase 实际触及者）**：

1. `docs/` 三个工具使用指南：
   - `docs/A股工具使用指南.md`
   - `docs/港股工具使用指南.md`
   - `docs/美股工具使用指南.md`
2. `.trae/skills/tools-scripts/` 工具技能参考文档（如 `financial-calc.md`、`annual-report-parser.md`、`terminal-value.md`、`trend-tech-screen.md`、`web-search-tools.md` 等）。

**同步内容**：本 Phase 新增/修改的工具子命令、函数签名、输入参数、输出字段（JSON）、量化口径说明与命令示例；替换或删除已失效的旧示例与旧字段。

**同步范围约束**：

- 仅同步「本 Phase 实际改动」的工具；未触及的工具其指南与参考文档**不越权改动**。
- 工具新增能力若属 GARP 专用、不应写入 `docs/` 三指南，则按 P4-23 约定写入 `.trae/skills/tools-scripts/`，不写入三指南。

**与 Phase 5 的关系**：本纪律为「增量最小同步」；P5-3 另做三指南与技能参考的「全量一致性核对」作为终态兜底。二者不冲突——增量先做，Phase 5 复查收口。

**纳入 Phase 完成门禁呈报**：Phase 完成门禁报告须列明本 Phase 触及的工具清单，以及对应已更新的三指南/`tools-scripts/` 参考文档（含 diff 摘要），供用户确认。

### P1-3 `financial_rigor.py` 新增 `wacc` 子命令

- **来源**：总计划 P1-1（拆分）。
- **目标与范围**：新增 `wacc`，计算加权平均资本成本。
- **关键量化口径**（权威=框架第3步·支柱二，供 ROIC 比较）：WACC = E/(E+D)·re + D/(E+D)·rd·(1−t)。
- **输入/输出签名**：输入 `--equity-value`、`--debt-value`、`--cost-equity`、`--cost-debt`、`--tax-rate`；输出 `{wacc, weights, after_tax_debt_cost}`，2 位小数。
