## 1. 目标与范围

### 1.1 目标

产出 GARP 独立档（**1~5 年**）的**深度公司系列长文**技能 `/garp-deep-company-series {公司名}`，并做到——

1. **五大师口径贯穿全篇**（共性 1 + 验收要点）：设计理念由骨架「四位景气大师（欧奈尔 / 林奇 / 郑希 / 李进）」**扩为五大师**（**费雪 / 林奇 / 郑希 / 李进 / 欧奈尔**）；**六处**落位刚性（设计理念表 / 头部引语块 / 附录 A 速查卡 / 8 主轴表「核心思想来源」列 / 篇内结构模板表「核心思想来源」列 / 篇 07-08 专属口径）；**费雪质化落位 01 / 02 / 05 / 07 / 08 篇**；交付物中 `四大师` 命中 **= 0**（`GDS-2`）。
2. **3~8 篇定目刚性**（验收要点）：篇数**按公司复杂度定**（高 7-8 / 中 4-6 / **低 3**），**不固定为 8**；**3 篇标准合并方式 GARP 化**（01 认知重置 + 生意与护城河 / 02 最大变量含产业景气 + 渗透率 / 03 决策终章含 **GARP 估值 + 五级卖出**）；**每篇须能用一个「尖锐问题」独立成文**；「凑内容」→ 合并，「超 12,000 字塞不下」→ 拆分（`GDS-1`）。
3. **共性口径七处替换全命中**：共性 **1 / 2 / 4 / 6** 为**点名差异**；共性 **3 / 5 / 7** 为**连带替换**（§7.2 刚性要求）；逐项对照见 §4.4。
4. **渗透率按 GARP 黄金窗判定**（共性 2）：渗透率判定由骨架「`10%~30%` 黄金区 / `15%` 加速临界点」改为 **`15%~40%` 五档** + **TAM ≥1000 亿**；**<5% 且无 EPS / 订单支撑 → 判题材**；每处并列标注**国产化率四梯队**（只读 `localize`）（`GDS-3`）。
5. **口径零复制（引用不重复定义）**：渗透率 / 国产化率 / 财务五门槛 / 科技豁免 / ROIC 四档 / 管理层 7+7+6 与科研转化 8+8+4 / 诚信前置闸门 / 三维交叉矩阵 / 多工具估值矩阵 / ESG 折价 / 宏观三表 / 五级卖出 / 仓位纪律 / ATR 止损 / 暂时性困难 vs 永久性衰退 / 六类分类**一律引用**（指向框架章节号或 `garp-*` 技能出口或工具命令），本技能**只定义写作流程与编排**。
6. **三档并存路由隔离**：技能内引用**只指向** `garp-*` 系列；**禁止**引用 1~3 年中期链（`mid-*`）与 10 年长期链（`deep-company-series` / `wechat-article` / `quality-screen` / `investment-research`）技能；**禁止**出现 `--horizon`、`P0~P5`、`mid-deep-company-series`、`-mid-deep-`、`-mid-{YYYYMMDD}` 等档位切换类口令与跨档路径（`GDS-12`）。
7. **风控硬编码 `GDS-1`~`GDS-12`**：骨架有编号化风控 `DCS-1`~`DCS-10`（实测 **11 处**命中：1 处标题 + 10 条规则），本技能**新建编号族**并附 **`DCS-` → `GDS-` 逐条映射表**，保持「一技能一编号族」定例与三档隔离。
8. **零新增 CLI、引擎零改动**：`tools/common/*` 与 `tools/specialized/*` **不改签名、不改行为、不新增子命令**；估值档位经 `garp-valuation` 转接、卖出阈值经 `garp-exit` 转接、管理层计分经 `garp-management` 转接、地缘矩阵经 `garp-geo-policy` 转接、宏观参数经 `garp-macro` 转接；本技能不自建档位链 / 止损链 / 计分链 / 地缘评分链；**禁用** `terminal_value.py`。
9. **「内容输出」而非「下指令」的刚性边界**：本技能输出**可公开发布的系列长文**；**不回答**「现在是否买入」；**不含**目标仓位 / 减仓百分比 / ATR 止损价等指令性数值；终章的分批建仓与止损**只读** GARP 出口技能，买入前须执行 `/garp-investment-checklist`（P4-3，**已交付**）。
10. **报告路径 + 命名规约 + 四基准**：产出 `reports/{公司名}/《看懂{公司名}》-garp-{YYYYMMDD}/`（含 `00-系列说明.md`），报告头部必注明**四基准**（数据 / 估值 / 资料 / 口径），见 §2.12。
11. **发布前准出刚性**（验收要点）：全部篇目写完后**必须**跑**跨篇一致性扫描四项**（数字 / 术语 / 引用 / 要点回顾）+ **`report_audit.py` 抽检**（偏差 ≤1% 准出、>1% 打回）+ **隐私 grep**；**未通过不得推送 GitHub**（`GDS-9` / `GDS-10` / `GDS-11`）。
12. **双门禁 + 七项交付件**：开工门禁 A~H（本文件 §9）+ 完成门禁留痕（详细计划 §0.7）；交付件严格对齐 §0.5「技能类七项」。

### 2.12 写作风格、禁用词与 GARP 术语红线

**语气四则（骨架承接）**：直接、犀利、不说废话（第一句给数字或反常识结论）；五大师视角穿插（不堆砌名言）；不预设立场（先摆数据 → 再推逻辑 → 最后得结论）；呈现正反两面（每个核心判断都附「但另一方面...」）。

**禁用词表（GARP 独立档版）**：

| 禁用 | 原因 | 替代 |
| --- | --- | --- |
| 显然 / 必然 / 一定 | 主观绝对化 | 数据显示 / 证据表明 |
| 我认为 / 我觉得 | 主观腔调 | 删除或改为「按本框架」 |
| 教科书级别 / 神来之笔 | 流量党褒奖 | 描述具体事实 |
| 严重不匹配 / 严重低估 | 强主观词 | 给具体折让百分比 |
| 完美 / 无可挑剔 | 单边判断 | 加上反方观察 |
| 「长期持有」/「永远不卖」/「买入并遗忘」 | **长期框架术语（禁）** | 「GARP 独立档周期内持有」/「每季度按 GARP 口径体检」 |
| 护城河永续 / 终局思维 / 持有10年 | **长期框架术语（禁）** | **1~5 年 GARP 周期中护城河是否支撑 ROE 向上** |

- **标题风格（骨架承接）**：用**反差数字**或**反共识结论**做钩子（「15 年 7 次挑战全失败」「ROE 连续 8 季度攀升」）；副标题中性概括；避免流量党比喻（「小巴菲特」「中国版 X」「YYDS」一律避开）；用专业读者熟悉的术语（「PEG」「二阶导」）。

## 3. 执行流程与工具编排

### 3.1 执行流程（四阶段，骨架承接 + GARP 化）

#### 阶段 0：定篇数与定目（**本技能前置，骨架隐含**，`GDS-1`）

1. **判断公司复杂度** → 定篇数（高 7-8 / 中 4-6 / 低 **3**），产**定目表**（篇号 / 篇名 / 核心问题 / 核心思想来源 / 字数）。
2. **与用户确认核心论点与定目**（避免写完才发现方向不对），**不跳步**。

#### 阶段 1：调研（写 01-02 篇前完成）

1. **信息丰富度评级（AI 研究偏见预警，必执行）**

   | 等级 | 特征 | AI 研究陷阱 | 应对策略 |
   | --- | --- | --- | --- |
   | **A 级（信息充裕）** | 上市多年、券商覆盖广、媒体报道密集 | 共识过强，AI 输出趋同于市场定价 | 重点做**反面检验**与**非共识视角** |
   | **B 级（信息适中）** | 上市 1-3 年、覆盖有限、部分数据需推算 | 用「合理推测」填补空白，产生虚假确定性 | 每个推算数据标注置信度 |
   | **C 级（信息稀缺）** | 冷门 / 新上市 / 新兴市场、几乎无覆盖 | 因资料不足过度保守，误判「看不清 = 不好」 | 转「**第一性原理模式**」，不追求系列完整性，聚焦核心问题 |

   关键提醒：**资料多 ≠ 确定性高，资料少 ≠ 确定性低**。评级结果影响各篇调研深度，并在 `00-系列说明.md` 中注明。

2. **阅读公司近 5 年年报、最新季报**（按市场选择工具，§2.14）。
3. **阅读至少 3 份独立卖方研报**（找共识 + 反共识）。
4. **使用 `/garp-investment-research`（P4-12，已交付）先生成内部研究底稿**——替代骨架的 `/mid-investment-research`；GARP 档**无**质量筛选技能（§4.5 **G18**），本系列面向**已入选赛道的好公司**，故不设 `/quality-screen` 环节。
5. **确认口径出口可调用性**：`garp-valuation` / `garp-exit` / `garp-management` / `garp-geo-policy` / `garp-macro` 五出口**逐一探测**；不可达则按 §3.3 #4 降级，**不阻断**。

#### 阶段 2：写作（按 01 → 末篇顺序写，**不跳**）

- 每篇写完先存 `reports/{公司名}/《看懂{公司名}》-garp-{YYYYMMDD}/0X-XX.md`。
- **目录冲突规则**：新系列写入带日期后缀的新文件夹 `-garp-{YYYYMMDD}`，旧文件夹（含中期版 `-mid-` 与长期版无后缀目录）**原样保留**，**不覆盖、不混放**。
- **每篇写完即跑本篇级检查**：四项共性结构齐全（头部引用块 / 首节钩子 / 要点回顾 + 下期预告 / 结尾两行斜体）+ §2.12 禁用词零命中。
- **不立即推 GitHub**——等用户审阅。

#### 阶段 3：跨篇一致性扫描（全部篇目写完后，`GDS-9`）

**派 Explore agent 并行扫描全系列**，四项检查**逐项出结论**：

1. 同一数字跨篇是否一致（总市值、净利润、关键持股 %、ROE、PEG）
2. 同一术语首次出现是否解释
3. 引用关系是否对应
4. **要点回顾 vs 正文数字是否一致**

#### 阶段 4：数据抽检与发布前最终核查（`GDS-10` / `GDS-11`）

```bash
# Step 1 - 提取抽检清单（15% 随机抽样）
python tools/common/report_audit.py extract \
  --report reports/{公司名}/《看懂{公司名}》-garp-{YYYYMMDD}/00-系列说明.md --seed 42

# Step 2 - 对清单每项从可靠信源取数（按市场分别使用对应工具）
```

- **【打回】** 任意点偏差 **> 1%** → 修正后**重新抽检**

### 3.6 修订意见处理流程（骨架承接 + GARP 化）

1. **先核查事实，不要直接改**：用户说「X 数据不对」时，先用工具找原始数据交叉验证，给出「**用户说的数据 vs 我查到的数据 vs 我之前用的数据**」三方对比。
2. **判断修订级别**：

   | 级别 | 类型 | 处理 |
   | --- | --- | --- |
   | 🔥 硬错误 | 数字错、归因错、口径错 | **必改**，不需犹豫 |
   | ⚠️ 主观化 | 强主观词、绝对化、流量党比喻 | 弱化或删除 |
   | 🔬 颗粒度 | 来源标注、口径细化 | 按可读性平衡 |
   | ❓ 不可靠 | 第三方测算差异大 | **删比改更稳** |

3. **修订后联动检查**：修一处先想「哪些地方还会引用这个数字 / 概念」——改了总市值 → 全系列联动改 PE；改了持股 % → 改 TOP 10 排序；改了术语口径 → 改**首次定义 + 后续引用**。
4. **推送后立即报告**：推送成功（commit hash）+ [N] 处修订总结带表。
