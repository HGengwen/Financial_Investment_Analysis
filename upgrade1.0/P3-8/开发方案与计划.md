## 0. 结论摘要（TL;DR）

P3-8 是 GARP 升级中**唯一一个在 Phase 3 之后追加的工具类子任务**，交付物是在既有《在研重大项目扫描器》`in_research_scan.py` 上新增一个**纯计算型子命令** `pipeline-npv`：把「未盈利科技型」公司在研项目的管线价值，按调用方显式给定的参数折现为一个**可追溯、可复算**的 NPV 数值与敏感性区间。

本方案的四条核心难点：

1. **「不内置任何默认假设」是本任务的刚性红线**——框架行 385 只把「研发管线 NPV」列为**辅助工具**、并无参数口径；该工具的合法性完全建立在「**参数全部由调用方显式提供、来源可回显**」之上。因此成功率、折现率、峰值收入、商业化年份**一律必填或透明回显**，缺项时输出 `data_insufficient=true` 而非任何替代值；**工具自身永不产生一个"看起来合理"的数字**。这是本任务与普通估值工具最本质的区别。
2. **「粗算子」的边界必须写死**——本工具只做**单期峰值现金流折现 + 概率线性调整**（§2.2 公式），不做分年爬坡、不做管线相关性、不做税率/摊销建模；复杂度上限写死，避免工具演化为一个"半成品 DCF"而诱导上层过度信任其精度。报告口径上它只回答「这条管线的量级与敏感性区间是多少」，**不回答「目标价是多少」**。
3. **与既有 `scan` 子命令的边界要切干净**——`scan` 负责「找到有哪些在研项目」（8 渠道检索），`pipeline-npv` 负责「给定参数算 NPV」。二者的唯一衔接是**可选的 `--from-scan`**：只从 `scan --json` 结果中提取**项目名候选**送入 `project_candidates` 字段（作为上层补参数的清单），**绝不自动生成任何数值参数**；未提供 `--from-scan` 时该字段为空数组。
4. **回归无损是硬约束**——`in_research_scan.py` 现有 `scan` / `list` 两个子命令的**参数、输出 JSON 结构、退出码均不得改动**（该文件属既有 43 技能链的共享工具，被 `mid-trend-tech-screen` 引用）；本任务只做「新增子命令 + 新增纯函数」，不改既有函数签名。

**本任务不涉及**：技能文件、GARP 口径阈值、任何估值档位判定（档位归 P4-5 技能层）、汇率换算。

## 2. 关键量化口径

> 本章为**唯一权威**：任何实现与本章不一致时以本章为准；**禁止 LLM 心算、禁止在实现中新增任何默认值**。

### 2.1 参数语义（全部由调用方提供）

| 参数 | 来源 | 单位/取值 | 默认值 |
| --- | --- | --- | --- |
| `--discount-rate` | 调用方（必填） | 小数，如 `0.10` | **无默认**（不得回退 WACC / 无风险利率） |
| `--currency` | 调用方（必填） | `CNY` / `HKD` / `USD` | **无默认**（不得假定 CNY） |
| `--as-of-year` | 调用方（可选） | 4 位年份 | 缺省取系统当前年份，**须回显 `as_of_year`** |
| `--projects` | 调用方（必填） | JSON 文件路径或 `-`（stdin） | 无 |
| `--sensitivity` | 调用方（可选） | 步长规格字符串（§2.3） | **无默认步长**；未提供则敏感性字段为 `null` |
| `--from-scan` | 调用方（可选） | `scan --json` 结果文件路径 | 无；未提供则 `project_candidates = []` |

**项目级必填字段**：`name` / `peak_revenue` / `launch_year` / `probability` / `source`。
**项目级可选字段**：`cost`（缺省视为 `0`，**必须**在 `defaults_applied` 中回显）。

### 2.2 计算口径（单期峰值现金流折现 + 概率线性调整，写死）

对每个项目 $i$（$r$ = `--discount-rate`，$Y$ = `as_of_year`）：

```
n_i        = launch_year_i − Y            # 折现期数；n_i < 0 → 用法错误（退出码 2）
PV_peak_i  = peak_revenue_i / (1 + r) ** n_i
PV_cost_i  = cost_i / (1 + r) ** n_i      # cost_i 缺省为 0（须回显）
NPV_i      = probability_i × PV_peak_i − PV_cost_i
pipeline_npv = Σ_i NPV_i
```

**四条硬规则**：

1. **概率是唯一风险调整因子**（线性调整，不做对数/分段调整）；
2. **不做税率、摊销、分期投入、残值假设**（复杂度上限）；
3. $probability_i$ 必须落在 $[0, 1]$，越界**报错**（退出码 2），**不得截断**；
4. 折现期数 $n_i$ 必须 ≥ 0，$n_i = 0$ 表示当年商业化（合法，$PV = 名义值$）。

### 2.3 敏感性口径（可选）

`--sensitivity` 规格形如 `r=0.01;p=0.10`（分号分隔，等号赋值，**绝对步长**）：

```
r 网格：{ r − Δr, r, r + Δr }   （r − Δr ≤ 0 → 用法错误，退出码 2）
p 网格：{ p − Δp, p, p + Δp }   （逐项目概率按绝对步长平移，越界者**截断至 [0,1] 并标注 clipped=true**）
输出 3×3 合计 NPV 网格 + npv_low / npv_high（网格极值）+ base（= pipeline_npv）
未提供 --sensitivity：sensitivity = null，**不得内置默认步长**
```

### 2.4 与框架/P4-5 的口径衔接

| 事项 | 本工具 | 下游 P4-5 |
| --- | --- | --- |
| 框架行 385「研发管线 NPV」 | 提供**数值**（NPV + 敏感性区间） | 作为未盈利科技型的**辅助**输入，与 PS / EV-Sales 主锚并列 |
| 框架行 385「需有清晰的盈利路径和里程碑节点」 | 通过**必填 `launch_year` + `probability` + `source`** 强制调用方给出里程碑与依据；依据缺失时 `data_insufficient=true` | 在报告中呈现「里程碑清晰度」定性判断 |
| 数据缺口 | 输出 `missing[]`，**不填补** | 按 P4-5 §2.5「定性 + 数据缺口标注」降级，**不得声称 NPV 已量化** |

## 3. 输入/输出签名

### 3.1 命令行

```bash
# 基本用法（全部参数显式提供）
python tools/specialized/in_research_scan.py pipeline-npv \
    --projects reports/pipeline/示例公司_在研项目.json \
    --discount-rate 0.10 --currency CNY --as-of-year 2026 --json

# 含敏感性 + 复用 scan 结果提取项目名候选
python tools/specialized/in_research_scan.py pipeline-npv --projects - --discount-rate 0.10 \
    --currency CNY --sensitivity "r=0.01;p=0.10" \
    --from-scan reports/in_research_示例公司_20260917.json --json
```

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `--projects` | ✅ | JSON 文件路径；`-` 表示从 stdin 读取 |
| `--discount-rate` | ✅ | 小数（`0.10` 表示 10%）；`≤ -1` 或非法值 → 退出码 2 |
| `--currency` | ✅ | `CNY` / `HKD` / `USD`（**不换算**） |
| `--as-of-year` |  | 缺省=系统当前年份，回显 `as_of_year` |
| `--sensitivity` | ✖ | `r=Δ;p=Δ` 规格（§2.3） |
| `--from-scan` | ✖ | `scan --json` 输出文件，仅提取项目名候选 |
| `--json` | ✖ | 输出 JSON（缺省输出人读摘要） |

### 3.2 `--projects` 输入 JSON schema

```json
{
  "currency": "CNY",
  "projects": [
    {
      "name": "示例在研项目A",
      "peak_revenue": 100.0,
      "launch_year": 2029,
      "probability": 0.4,
      "cost": 20.0,
      "source": "公司2025年报·管理层讨论与分析·在研项目章节（第 X 页）"
    }
  ]
}
```

- `currency` 与 CLI `--currency` **同时提供且不一致 → 用法错误（退出码 2）**（不得静默取其一）；
- `source` 必填（非空字符串）：用于「参数来源回显」与下游报告的可追溯性；
- 金额单位由调用方自定义（亿元/百万元），但**必须全项目同口径**，工具只做**同比运算、不解释单位**（输出不回写单位推断）。

### 3.3 输出 JSON 契约

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `command` | str | 固定 `"pipeline-npv"` |
| `as_of_year` / `discount_rate` / `currency` | int/float/str | 回显实际使用的口径 |
| `data_insufficient` | bool | 项目级缺项时为 `true` |
| `missing` | list[str] | 缺项清单（形如 `projects[1].probability`） |
| `defaults_applied` | list[str] | 透明化清单（形如 `projects[1].cost=0`） |
| `projects[]` | list | 每项含 `name` / `launch_year` / `years_to_launch` / `probability` / `peak_revenue` / `cost` / `pv_peak` / `pv_cost` / `npv` / `source` |
| `pipeline_npv` | float\|null | 合计 NPV；`data_insufficient=true` 时为 `null` |
| `sensitivity` | object\|null | `{spec, grid, npv_low, npv_high, base}`；未提供 `--sensitivity` 时为 `null` |
| `project_candidates` | list[str] | 仅 `--from-scan` 时填充的项目名候选（**不含任何数值**） |

**退出码约定**：

| 场景 | 退出码 |
| --- | --- |
| 正常（含 `data_insufficient=true`） | `0` |
| 用法错误：JSON 解析失败 / 必填 CLI 参数缺失（argparse）/ 概率越界 / `n_i < 0` / 币种冲突 / 敏感性格格非法 | `2`（错误信息写 **stderr**，stdout 不输出 JSON） |
| 既有 `scan` / `list` | 保持 `0`（不变） |

### 3.4 `--from-scan` 衔接口径

- 读取 `scan --json` 结果中 `channels[*].top_links[*].title`，**按标题规则粗提项目名候选**（去重、去空），写入 `project_candidates`；
- **不得**从 scan 结果中推断任何数值（金额/年份/概率）；
- `--from-scan` 文件不存在或解析失败 → 退出码 2（不静默忽略）；
- 未提供时 `project_candidates = []`。

### §9.A `--projects` 的输入形态

- **推荐 A-1（推荐）**：`--projects` 接受 **JSON 文件路径**，并支持 `-` 从 stdin 读取。理由：契约可版本化、便于 P4-5 生成中间文件后调用、便于单测用固定文件对拍。
- 备选 A-2：同时接受内联 JSON 字符串（`--projects '{"projects":[...]}'`）。代价：命令行长度与引号转义在 Windows 下易出错。
- 备选 A-3：CSV / YAML 输入。代价：嵌套字段与类型校验成本上升。

### §9.B NPV 计算公式与风险调整方式

- **推荐 B-1（推荐）**：**单期峰值现金流折现 + 概率线性调整**（§2.2 公式）。理由：参数最少、与「粗算子」定位一致、可完全复算；概率作为唯一风险调整因子易于解释。
- 备选 B-2：分年爬坡现金流（需额外 `ramp` 参数组）。代价：参数膨胀、与粗算子定位冲突、上游（P4-5）无稳定数据源。
- 备选 B-3：不做概率调整，只输出确定性 NPV（概率仅作展示）。代价：失去管线估值的核心语义。

### §9.C `cost` 缺省语义

- **推荐 C-1（推荐）**：`cost` 允许缺省、缺省视为 `0`，但**强制**在 `defaults_applied` 中回显（透明化）。理由：多数早期管线尚未编制投入预算，硬性必填会导致大面积 `data_insufficient`；透明回显既保留可追溯性又不引入隐藏假设。
- 备选 C-2：`cost` **必填**（无缺省）。代价：可用性下降，可能迫使调用方填 0 或编造。
- 备选 C-3：`cost` 缺省时整体判 `data_insufficient`。代价：过度保守，与「辅助工具」定位不符。

### §9.D 敏感性规格形态

- **推荐 D-1（推荐）**：`--sensitivity "r=0.01;p=0.10"`（**绝对值步长**，分号分隔，等号赋值），输出 3×3 网格 + `npv_low` / `npv_high`。理由：显式、无隐藏默认；调用方按自身假设精度给步长。
- 备选 D-2：内置默认步长（±1pp / ±10pp）后仅 `--sensitivity` 开关。代价：**违反「无默认假设」红线**。
- 备选 D-3：仅一元敏感性（只动折现率或只动概率）。代价：无法体现「概率×折现率」的双重不确定性。

### §9.E 输出契约与退出码

- **推荐 E-1（推荐）**：**项目级缺项 → `data_insufficient=true` + `missing[]`，退出码 0**；**用法错误（JSON 解析失败 / 必填 CLI 参数缺失 / 概率越界 / `n_i<0` / 币种冲突）→ 退出码 2，错误写 stderr**。理由：与既有 `scan` / `list` 的 `return 0` 约定一致；「数据不足」是业务状态而非程序错误，便于上游脚本连续处理。
- 备选 E-2：所有缺项一律退出码 2。代价：上游无法用统一流程处理「多公司批量算、部分数据未齐」的场景。
- 备选 E-3：`data_insufficient=true` 时退出码 3（独立状态码）。代价：与项目既有约定不一致。

### §9.F 衔接、文书同步与增量参数

- **推荐 F-1（推荐）**：①采纳增量参数 `--currency` / `--as-of-year` / `--from-scan`（详细计划未列，但为「无默认假设」与「scan 衔接」所必需）；②`--from-scan` 只提取**项目名候选**，不得生成数值；③工具参考文档写入 `.trae/skills/tools-scripts/`（GARP 专用，不写入 `docs/` 三指南）；④单元测试**追加到既有** `tests/specialized/test_in_research_scan.py`（新增 `TestPipelineNpv*` 类，与 P3-7 先例一致）。
- 备选 F-2：不采纳增量参数（严格照详细计划字面）：`--currency` 缺省 CNY、`as_of_year` 缺省当年、无 `--from-scan`。代价：**引入隐藏默认值**，与 R1 红线冲突。
- 备选 F-3：测试独立新建文件 `tests/specialized/test_in_research_scan_pipeline_npv.py`。代价：同工具测试分散两处。
