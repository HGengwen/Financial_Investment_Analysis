## 0. 结论摘要（TL;DR）

本任务在既有 `tools/specialized/governance_data.py` 中新增 `research` 子命令，将框架第 3 步·支柱三的「科研转化评估清单（20 分制）」下沉为可执行命令，禁止 LLM 心算。

- **输入**：研发投入（8 分）+ 研发产出（8 分）+ 资本回报（4 分）三个维度的评分项；资本回报维度以数值透传方式引用 P1-1 `roic` / P1-2 `incremental-roic` / P1-3 `wacc` 的结果。
- **输出**：JSON，核心字段 `{total, verdict(重仓/观察/放弃), score_breakdown}`，附 `warning` 降级提示、`data_as_of` 时效回显与口径来源标注。
- **与 P3-4 `management` 的关键差异**：`research` **无诚信否决闸门**（诚信否决属 `management` 专属）；资本回报维度**不重算 ROIC**，而是引用既有 roic 结果数值；新增 `warning` 字段承载缺省降级提示。
- **核心难点**：框架只给出「8+8+4=20」三个维度的**总分**，未给出各维度内部子项的精确分值；本方案将「子项 → 分数」的加权/切点规则固化为可测试的确定性规则（§5.3），并以代码常量落地，消除 LLM 临场判断。
- **两套收口边界**：框架行 280 规定科技股「管理层 + 科研转化两套 20 分制**都须≥15**」，但**两套合成（都须≥15）由 P4-6 技能编排承担**，本任务只输出单套科研转化 `verdict`，不实现「与管理层求交」的合成逻辑。
- **时变性与边界（与 P3-1 / P3-4 同构分层）**：8+8+4 权重与 ≥15/10 阈值是**静态标签**（框架明示）；但各评分项的「取值判定」是**时变项**——研发强度、资本化率、研发人员占比、新产品收入占比、专利质量档位、ROIC/WACC/增量ROIC 等事实，随财报/公告动态变化。故本工具**不检索、不判定事实真伪、不固化事实**（实时取证交由 P3-7 与技能编排），只对调用方传入的电平值做确定性评分。

## 1. 目标与范围

### 1.1 目标

在既有 `tools/specialized/governance_data.py` 中新增 `research` 子命令，实现：

1. **三维求和**：研发投入"质"与"量" 8 分 + 研发产出效率 8 分 + 资本回报效率 4 分 = 20 分。
2. **资本回报关联 ROIC**：以数值透传方式引用 P1-1 `roic`（存量 ROIC）、P1-2 `incremental-roic`（增量 ROIC）、P1-3 `wacc`（加权资本成本）结果，完成「ROIC > WACC」「增量 ROIC > 存量 ROIC」两项判定。
3. **三档判定**：≥15 重仓；10~14 观察（单只上限 ≤5%，不重仓）；<10 放弃。

### 1.2 包含范围

- 科研转化三维子项权重表（§5.3，常量固化）。
- 资本回报维度数值透传引用（`--roic` / `--incremental-roic` / `--wacc`，严格大于判定）。
- 三档 `verdict` 与退档规则（与 P3-4 `management` 同口径）。 
- 输入校验（数值范围 + 档位词表 + 资本回报百分数允许负值，fail-fast 拒绝非法输入）。
- 缺省降级语义（`--roic` / `--wacc` / `--incremental-roic` 缺省 → 对应子项 0 分 + `warning` 提示，不猜、不报错退出）。
- 可选入参 `--as-of`（评分数据截止日期）透传 + 输出时效警示。
- CLI 子命令 `research`（单次评分，输出 JSON）。
- 单元测试（三维满分=20 + 三档边界 + 子项权重逐项 + 资本回报缺省降级 + 输入越界拒绝 + JSON 可解析），且**不动 P3-4 既有 42 个测试用例**。

### 1.3 不包含范围（明确排除，防范围蔓延）

- **不含**诚信否决闸门——诚信否决属 `management` 专属，`research` 无 `integrity_veto` / `integrity_veto_reasons` 字段。
- **不含**「管理层 + 科研转化两套都须≥15」的**合成逻辑**（框架行 280），交 P4-6 技能编排。
- **不含** ESG 环境风险折价（8~9 折 / 搁浅资产贴现率 / 仓位上限下调，P3-6）。
- **不重算 ROIC**：`roic / incremental-roic / wacc` 值由技能编排先跑 P1-1/P1-2/P1-3 子命令后以 `--roic/--incremental-roic/--wacc` 传入；本工具**不 import `financial_rigor` 内部函数**（其函数含 `print` 副作用，不适于进程内复用）。
- **不做**事实取证与网络检索——研发强度/资本化率/研发人员占比/新产品占比/专利质量及 ROIC 系列数值的取值，属 P3-7 与技能编排职责；本工具仅做「给定输入 → 确定性评分」。
- **不含**科技股专用估值调整（研发费用加回 → 调整后 PE，框架行 328，属 P1-6 `adjusted-peg`）；仅在 `note` 提示其存在。
- **不改动** `management` 子命令及其 42 个测试用例。
- **不改动** `financial_rigor.py` / `geo_policy_screen.py` / `annual_report_parser.py`（仅作数值来源或风格参照）。
- **不改动** `.trae/skills/` 下既有技能文件。

## 2. 关键量化口径（唯一权威 = 框架第 3 步·支柱三）

> 以下全部取自《中长期价值成长（GARP）投资框架》第 3 步·支柱三（行 280、320~328）。任何实现与本文档或总计划/详细计划不一致时，**以框架正文为准**。

### 2.1 两套 20 分制合成规则（行 280）

- 管理层评估为**通用硬门槛**（无论行业，管理层评分须 ≥15 方可重仓）。
- 科技股在此基础上**再叠加**科研转化评分 ≥15 分，即「**两套都须≥15**」而非合计/加权。
- 科研转化的 <15 分退档规则同管理层：**10~14 观察（单只上限 ≤5%，不重仓）、<10 放弃**。
- 普通行业不适用科研转化清单时，仅以管理层 20 分制判定。

> **本任务边界**：只实现单套科研转化 20 分制及其三档判定；「两套都须≥15」的求交由 P4-6 技能编排负责（见 §1.3）。

### 2.2 科研转化评估清单（行 320~326）

| 维度 | 检查项（框架原文） | 满分 |
| --- | --- | --- |
| **研发投入"质"与"量"** | 研发强度 ≥15% 且逐年提升；资本化率 <30% 为审慎；研发人员占比 ≥30% | 8 |
| **研发产出效率** | 发明专利数量与质量；新产品收入占比 ≥20%；技术产品化周期；重大科研项目节点推进 | 8 |
| **资本回报效率** | ROIC > WACC；增量资本回报率 > 存量 ROIC | 4 |

### 2.3 资本回报引用口径

| 引用项 | 来源工具/子命令 | 输出字段（供透传） | 单位/符号 |
| --- | --- | --- | --- |
| 存量 ROIC | P1-1 `financial_rigor.py roic` | `roic`（%，2 位小数；投入资本 ≤0 时 `None`） | 百分数，可为负 |
| 增量 ROIC | P1-2 `financial_rigor.py incremental-roic` | `delta_roic`（%，2 位小数；Δ投入资本 ≤0 时 `None`） | 百分数，可为负 |
| WACC | P1-3 `financial_rigor.py wacc` | `wacc`（%，2 位小数；E+D ≤0 时 `None`） | 百分数，一般为正 |

> **判定均为「严格大于」**（框架原文 `>`，而非 `≥`）：
> - ROIC > WACC → 该项得分。
> - 增量资本回报率 > 存量 ROIC → 该项得分。
>
> 引用方式为**数值透传**：技能编排先运行上述子命令读回上述字段的数值，再作为 §3.1 的 `--roic / --incremental-roic / --wacc` 传入本工具。本工具不调用 `financial_rigor` 内部函数（避免 `print` 副作用污染 JSON stdout），也不重复计算 ROIC。

### 2.4 科技股专用估值调整提示（行 328）

研发费用化会压低当期利润，导致 PE 虚高、PEG 被动变大；应参考费用化研发支出加回（核心经营利润）计算调整后 PE。该项属 P1-6 `adjusted-peg`，**本工具仅在 `note` 提示，不纳入科研转化计分**。

### 2.5 阈值与退档规则（权威照录）

- **≥15 分 → 重仓**。
- **10~14 分 → 部分不达标，退观察仓**（单只上限 ≤5%，不重仓）。
- **<10 分 → 放弃**。

## 3. 输入/输出签名

### 3.1 输入项与档位词表

**研发投入"质"与"量"（8 分）**

| 输入参数 | 类型 | 语义 / 触发条件 |
| --- | --- | --- |
| `--rd-intensity` | float | 研发强度（%，0~100） |
| `--rd-intensity-rising` | flag | 研发强度是否逐年提升 |
| `--capitalization-rate` | float | 研发支出资本化率（%，0~100） |
| `--rd-personnel-ratio` | float | 研发人员占比（%，0~100） |

**研发产出效率（8 分）**

| 输入参数 | 类型 | 语义 / 档位词表 |
| --- | --- | --- |
| `--patent-quality` | 档位 | 发明专利数量与质量：`优`/`中`/`差` |
| `--new-product-revenue-ratio` | float | 新产品收入占比（%，0~100） |
| `--commercialization-cycle` | 档位 | 技术产品化周期：`优`/`中`/`差` |
| `--project-milestone` | 档位 | 重大科研项目节点推进：`优`/`中`/`差` |

**资本回报效率（4 分）**

| 输入参数 | 类型 | 语义 |
| --- | --- | --- |
| `--roic` | float | 存量 ROIC（%，可为负），引用 P1-1 `roic` 字段 |
| `--wacc` | float | WACC（%，一般为正），引用 P1-3 `wacc` 字段（可选） |
| `--incremental-roic` | float | 增量 ROIC（%，可为负），引用 P1-2 `delta_roic` 字段（可选） |

**时效**

| 输入参数 | 类型 | 语义 |
| --- | --- | --- |
| `--as-of` | str | 评分数据截止日期（可选，仅透传） |

> **档位词表**：定性档位统一取 `优` / `中` / `差` 三档。
> **数值解析分两类**：
> - 研发强度、资本化率、研发人员占比、新产品收入占比 → 0~100 的 float，越界拒绝。
> - `--roic` / `--incremental-roic` / `--wacc` → **百分数，允许负值**（ROIC 可为负、增量 ROIC 可为负），拒绝布尔/非数值/NaN/Inf，但不套用 0~100 硬边界（与 `_parse_rate` 分开实现）。
> - 任何档位非法或数值非法 → 打印错误并返回非零退出码，**拒绝判分**（fail-fast，不猜）。
> - 缺省降级（仅资本回报维度）：`--roic`/`--wacc`/`--incremental-roic` 缺省时**不报错**，对应子项按 0 分计并追加 `warning`（见 §5.3 / §3.3）。

## 5. 实现设计（五步，与详细计划对齐）

### 5.1 数据模型

- 常量 `RESEARCH_DIMENSIONS`：三维度名 → 满分与子项键序列（`rd_input`/`rd_output`/`capital_return` = 8/8/4）。
- 常量 `RESEARCH_ITEM_LABELS`：科研子项键 → 中文标签。
- 常量 `RESEARCH_SUBITEM_MAX`：科研子项键 → 满分。
- 常量 `_assert_research_weights()`：导入时自检三维子项权重和恰为 8/8/4 且总和为 20（同 `_assert_dimension_weights` 思想）。
- `build_research_result(...) -> Dict[str, Any]`：组装 §3.3 顶层 JSON。

### 5.2 缺省降级语义（实现步骤①，资本回报维度专属）

资本回报维度两个子项均依赖引用数值；缺省时**不报错、降级 0 分 + warning**（纯计算工具「不猜、标注缺口」）：

| 缺省情形 | 降级结果 |
| --- | --- |
| `--roic` 缺省 | 「ROIC > WACC」与「增量 > 存量」两项均 0 分，warning 提示「未提供 ROIC，资本回报维度无法判定，两项均按 0 分计」 |
| `--wacc` 缺省（roic 提供） | 「ROIC > WACC」0 分，warning「未提供 WACC，无法判定『ROIC > WACC』，该项按 0 分计」 |
| `--incremental-roic` 缺省（roic 提供） | 「增量 > 存量」0 分，warning「未提供增量 ROIC，无法判定『增量资本回报率 > 存量 ROIC』，该项按 0 分计」 |

> `--rd-intensity / --capitalization-rate / --rd-personnel-ratio / --new-product-revenue-ratio` 及三个定性档位为**必填**（缺省 fail-fast 拒绝），不适用降级语义——只有资本回报维度的引用数值允许缺省降级（对应详细计划「可选 ROIC」）。研发投入/研发产出两个维度不依赖外部引用，故无缺省降级。

### 5.3 子项打分（实现步骤②，本任务核心难点 → §9.A/B 待确认）

框架只给三维总分，未给子项精确分值。本方案将三维内部权重+切点固化为以下确定性规则：

**研发投入"质"与"量"（满 8 分）**

| 子项 | 计分规则 | 分值 |
| --- | --- | --- |
| 研发强度及逐年提升 `rd_intensity` + `rd_intensity_rising` | ≥15% 且提升 = 3；≥15% 未提升 = 2；<15% = 0 | 3 |
| 资本化审慎 `capitalization_rate` | <30% = 2；≥30% = 0 | 2 |
| 研发人员占比 `rd_personnel_ratio` | ≥30% = 3；15%~30% = 1；<15% = 0 | 3 |

**研发产出效率（满 8 分）**

| 子项 | 计分规则 | 分值 |
| --- | --- | --- |
| 发明专利数量与质量 `patent_quality` | 优=2；中=1；差=0 | 2 |
| 新产品收入占比 `new_product_revenue_ratio` | ≥20% = 2；10%~20% = 1；<10% = 0 | 2 |
| 技术产品化周期 `commercialization_cycle` | 优=2；中=1；差=0 | 2 |
| 重大科研项目节点推进 `project_milestone` | 优=2；中=1；差=0 | 2 |

**资本回报效率（满 4 分）**

| 子项 | 计分规则 | 分值 |
| --- | --- | --- |
| ROIC > WACC `roic` vs `wacc` | roic 提供且 wacc 提供且 `roic > wacc` → 2；否则 0 | 2 |
| 增量 > 存量 ROIC `incremental_roic` vs `roic` | roic 提供且增量提供且 `incremental_roic > roic` → 2；否则 0 | 2 |

> **数值切点边界约定（左闭右开）**：
> - 研发人员占比 `[30, 100]` / `[15, 30)` / `[0, 15)`。
> - 新产品收入占比 `[20, 100]` / `[10, 20)` / `[0, 10)`。
> - 资本化率 `[0, 30)`（审慎得 2）/ `[30, 100]`（0）。
> - 研发强度 ≥15 阈值恒为 `[15, 100]`；「逐年提升」用独立 flag `--rd-intensity-rising` 表达（复合条件：强度达标 + flag）。
> - 资本回报两项为**严格大于**（`>`，非 `>=`）。
> 其中研发人员占比中间档 15%、新产品收入占比中间档 10% 为框架未明示的自定档，随 §9.B 一并确认。

### 5.4 阈值与 verdict 判定（实现步骤③）

```text
if total >= 15:
    verdict = "重仓"
elif 10 <= total < 15:
    verdict = "观察"  # 部分不达标→观察仓，单只上限≤5%
else:  # total < 10
    verdict = "放弃"
```

> 无诚信否决闸门，判定顺序为「解析输入 → 三个维度打分 → 求和 → 三档判定」。与 `management` 的差异：`management` 先跑诚信否决闸门，`research` 无此步。

### 5.5 样例（实现步骤④）

- **满分通过例**：三维全满 → `total=20`、`verdict=重仓`。
- **缺省降级例**：未提供 `--wacc` / `--incremental-roic` → `--roic` 提供时资本回报两子项 0 分、`warning` 两条。
- **边界例**：`total=15` → 重仓；`total=14` → 观察；`total=10` → 观察；`total=9` → 放弃。
- **严格大于判定例**：`roic == wacc`（等值）→ ROIC>WACC 不得分；`incremental_roic == roic`（等值）→ 增量>存量不得分。

- 未改动 `.trae/skills/` 任一既有技能。
