## 0. 升级总原则与硬约束

1. **技能修改变更最小化**：不修改 `.trae/skills/` 下任何**已完成的技能文件**（`tools-scripts/` 下的工具参考文档除外，允许增补）。GARP 独立档一律以**新增独立技能**落地，通过"引用不重复定义"复用既有权威口径。**唯一例外**：复用 2 技能（`qoq-accelerator`、`trend-momentum-scan`）为落地出口转接声明，允许**仅修改其 `SKILL.md` 与 `README.md`**（增补出口转接段，不改核心口令与流程）。
2. **工具层可增补/新增**：优先**扩展已有工具**（`financial_rigor.py`、`momentum.py`、`annual_report_parser.py`），仅当职责独立时**新增 `specialized/` 专用工具**，避免重复造轮子。
3. **地基复用**：三市场数据工具、搜索五工具、缓存层、报告审核、景气打分引擎全部复用，不重建。
4. **禁止 LLM 心算**：新增的一切算术（ROIC/WACC/ATR/Rule of 40/EV-Sales/DCF/隐含 PEG/宏观参数）全部下沉为工具命令。
5. **口径单一权威**：GARP 版的渗透率 / PEG 档 / 卖出级别 / 管理层 20 分制自身为唯一权威，并在技能内与中期链（10%~30%、P0~P5、5+5+5+5）显式隔离，避免混用。
6. **数据快照即时核验**：国产化率、产业基金、制裁清单、宏观数据均为时变项，工具一律走"缓存 + 实时刷新 + 失败降级旧缓存"模式，与项目既有 `a_stock_cache` 一致。**获取策略（已确认）**：结构化数据 akshare 优先，质量不足时搜索五工具回退，最终统一标注数据截止日期。

## 2. 分阶段实施计划

### 2.0 任务细分与确认门禁（本方案执行纪律）

本次升级幅度较大，开发过程中仍存在大量判断与决策，因此**不允许直接按 Phase 粗粒度开工**。鉴于任务本身具有高度不确定性，整体升级采用**人在回路（Human-in-the-Loop，HITL）**方式逐步推进——每个子任务的**方案与计划**、以及该任务**是否完成的判定**，均须经用户**明确确认**后方可流转。AI 不得单方面推进；也不得把多个任务合并为一、绕过逐个确认关口继续开发。须执行以下增量细分与确认门禁：

1. **任务进一步细分**：将每个 Phase 拆解为独立的一个或多个「任务（Task）」，每个任务只对应一个可独立验收的交付目标（一个工具子命令 / 一个技能 / 一个数据字段组），禁止一任务多目标。
2. **明确任务内子步骤**：每个任务列明子步骤（需求口径 → 接口设计 → 实现 → 样例自测 → 回归核对），子步骤按顺序执行，前后有依赖。
3. **每任务开发方案与计划**：每个任务开工前，先产出该任务的《###开发方案与计划》，明确：目标与范围、输入/输出签名、关键量化口径（唯一权威来源）、复用与新增点、验收标准、风险与依赖。
4. **必要交付件**：每任务交付件至少包含——①###开发方案与计划；②实现代码（工具类）/ 技能文件 `SKILL.md` + `README.md` 两件同批完成（技能类）；③样例输入与期望输出；④单元/集成测试（工具类）/ 样例运行记录 + 引用完整性检查（技能类）；⑤回归无损核对记录；⑥口径隔离声明（是否触及既有 43 技能/既有工具签名）。
5. **人在回路与双确认门禁（刚性）**：每个任务设两个**必须经用户明确确认**的关口——
   - **开工门禁（方案确认）**：该任务的《###发方案与计划》经用户**明确确认*后，方可进入该任务的下一步开发；
   - **完成门禁（验收确认）**：任务开发完成、经验收标准自检通过后，须向用户呈报「任务完成判定」——交付件清单 + 验收标准逐条对照 + 回归无损/口径隔离结论，经用户**明确确认该任务完成**后，方可流转至下一任务。
     两个关口均不得跳步、合并推进，也不得以「默认继续」或 AI 单方判定替代用户明确确认。
6. **开发文档落盘规范**：开发阶段产生的全部文档统一保存在 `upgrade1.0/` 路径下；**每个任务在 `upgrade1.0/` 下建同名子目录**（以任务编号命名，如 `upgrade1.0/P1-1/`、`upgrade1.0/P4-5/`）存放该任务的开发文档，包括但不限于——`###开发方案与计划.md`、`样例与期望输出.md`、`测试记录.md`、`回归核对记录.md`、`口径隔离声明.md`，以及任何临时的口径决策记录；工具代码与技能文件仍按项目既有目录规范落地到 `tools/`、`.trae/skills/`，交付文档不散落在源码目录。
7. **工具文档同步纪律**：凡任务触碰 `docs/` 下三份市场工具使用指南已登记的工具签名或输出字段（本轮为 `--momentum` 新增 `atr14`、`financial_rigor.py` 新增 7 子命令、`annual_report_parser.py` 新增治理字段），须在**该任务验收通过后**同步更新受影响指南（列为该任务交付件之一），并在 P5-3 路由同步时做一次三指南全量一致性核对；跨市场、市场无关的 GARP 专用新增工具（`macro_calibrator.py`/`geo_policy_screen.py`/`governance_data.py`）**不写入三份市场指南**，统一由 `.trae/skills/tools-scripts/` 下 4 个 GARP 工具参考 md 承载。

## 6. 验收标准（总纲）

1. **工具可复现**：任一新增命令用固定输入可复现输出，结构化 JSON 优先。
2. **禁止心算达标**：GARP 全部量化口径（ROIC/WACC/ATR/Rule40/EV-Sales/隐含PEG/DCF/宏观参数）均无 LLM 手算。
3. **口径隔离达标**：新增技能头部声明独立档，渗透率/卖出/管理层口径不与中期链混用。
4. **数据约束达标**：日期确认、双源交叉验证（误差>1% 标记）、不确定性标注、报告审核四约束贯穿。
5. **回归无损**：既有 43 技能与既有工具命令不受影响（扩展为新增子命令，不改既有签名）。
