## 1. 子任务定位与权威依据

P1-6 是 `financial_rigor.py` 计算核心扩展的第 6 个子命令，目标是为 GARP 框架「第4步 估值锚定——多工具矩阵」中**高研发投入、研发费用化压低当期利润**的快速增长型公司提供「研发费用加回核心经营利润」口径的调整后 PE 与调整后 PEG。

权威口径（框架第4步行 328 科技股专用提示 + 详细计划 P1-6）：

$$
调整后 PE = 市值 \div (核心经营利润 + 研发费用回加)
$$

$$
调整后 PEG = 调整后 PE \div 未来增速(\%)
$$

档位判定（框架第4步行 384 快速增长型，权威）：

| 调整后 PEG | 档位 |
| --- | --- |
| `<1` | 低估（可加仓） |
| `1 ~ 1.2` | 合理 |
| `1.2 ~ 1.5` | 合理偏贵（持有不加仓、机动仓择机减） |
| `>1.5` | 高估（减机动仓） |

> 说明：框架另有 `>2` 严重透支 → 加速清机动仓（行 500），本工具在归纳档位（tier）时以四级主档为准，严重透支语义可并入 `高估` 档补充提示（见 D3）。

## 2. 目标与范围

### 2.1 目标

1. 新增 `adjusted_peg()` 函数，精确计算「研发加回」调整后 PE 与调整后 PEG（2 位小数）。
2. 新增 `adjusted-peg` 子命令（argparse 注册 + `main()` 派发）。
3. 输出结构化 JSON，核心字段 `{adjusted_pe, adjusted_peg, tier}`（对齐详细计划签名）。
4. 复用 `peg_ratio` 的档位判定思想，但档位边界固化为框架第4步口径。

### 2.2 范围

**做什么：**

- `调整后经营利润 = 核心经营利润 + 研发费用回加` 精确加法。
- `调整后 PE = 市值 / 调整后经营利润` 精确除法。
- `调整后 PEG = 调整后 PE / 未来增速` 精确除法。
- 结果 `quantize(Decimal("0.01"))` 后转 float，2 位小数。
- 档位判定 + 合理性告警（负分母、负增速、负研发、回加后仍亏损）。

**不做什么：**

- **不定义「核心经营利润」的会计科目抽取规则**（科目数据抽取归调用方技能，本工具只接收单一数值；但会提供静态口径提示）。
- **不做研发费用「资本化摊销」多期建模**（只做当期费用化研发一次性回加口径）。
- **不做同业可比 / ESG / 宏观 PEG 区间动态调整**（P4 技能编排层职责）。
- **不引入** `--currency` / `--unit`（市值与利润同货币单位，乘除消除单位，见 D1）。
- **不回改**既有 15 个子命令签名/行为，不回改 `terminal_value.py`。

## 6. 函数与 CLI 实现设计

### 6.1 `adjusted_peg()` 函数签名

```python
def adjusted_peg(market_cap, core_operating_profit, rnd_expense, growth):
    """计算研发费用加回核心经营利润口径的调整后 PE 与调整后 PEG。

    adjusted_pe = market_cap / (core_operating_profit + rnd_expense)
    adjusted_peg = adjusted_pe / growth

    Args:
        market_cap: 市值（与利润同货币单位）。
        core_operating_profit: 核心经营利润（同货币单位）。
        rnd_expense: 当期费用化研发支出（同货币单位）。
        growth: 未来盈利增速，百分点（如 30 表示 30%）。

    Returns:
        dict: 含 adjusted_pe / adjusted_peg / tier / verdict /
              warnings / inputs 审计回显字段。
    """
```

### 6.2 核心计算与护栏（伪代码）

```python
mc = exact(market_cap)
op = exact(core_operating_profit)
rnd = exact(rnd_expense)
g = exact(growth)

# 护栏 1：增速 ≤ 0 → 负/零增长 PEG 无意义 → 降级 N/A
if g <= 0:
    return {adjusted_pe/peg/tier 为 None, verdict: "增速≤0，PEG无意义", ...}

# 合理性告警（不拒绝）
warnings = []
if rnd < 0: warnings.append("研发费用为负（数据异常）")
if mc < 0: warnings.append("市值为负（数据异常）")

core_adj = op + rnd  # 调整后经营利润

# 护栏 2：调整后经营利润 ≤ 0 → 回加后仍亏损，PE/PEG 无意义 → 降级 N/A
if core_adj <= 0:
    return {adjusted_pe/peg/tier 为 None, warnings: [..., "回加研发后仍亏损"], ...}

adjusted_pe = (mc / core_adj).quantize(0.01)
adjusted_peg = (adjusted_pe / g).quantize(0.01)
tier, verdict = _tier_adjusted_peg(adjusted_peg)
```

### 6.3 档位判定函数（新增）

```python
def _tier_adjusted_peg(peg_val):
    """按框架第4步快速增长型四档判定调整后 PEG 档位。"""
    if peg_val < 1:
        return "低估", "低估（PEG<1，可加仓）"
    if peg_val <= 1.2:
        return "合理", "合理（1≤PEG≤1.2）"
    if peg_val <= 1.5:
        return "合理偏贵", "合理偏贵（1.2<PEG≤1.5，持有不加仓、机动仓择机减）"
    return "高估", "高估（PEG>1.5，减机动仓）"
```

> 是否将 `>2` 严重透支作为额外提示并入 `高估` 档，见 D3。

## 9. 验收标准

1. **调整后 PE/PEG 正确至 2 位小数**：标准样例 `→ adjusted_pe=13.33, adjusted_peg=0.44`。
2. **档位与框架一致**：`0.44→低估`、`1.0~1.2→合理`、`1.2~1.5→合理偏贵`、`>1.5→高估`。
3. **护栏**：`growth ≤ 0` 与 `核心经营利润+研发回加 ≤ 0` 降级 N/A 且无异常退出；负研发/负市值计入 `warnings`。
4. **JSON 可解析**：`adjusted_pe` / `adjusted_peg` 为数值，`tier` 为四档或 `N/A`。
5. **回归无扰动**：既有 15 个子命令（原 10 + `roic`/`incremental-roic`/`wacc`/`rule-of-40`/`ev-sales`）功能不受影响。

## 12. 风险与限制

- **核心经营利润口径依赖调用方**：工具无法从「净利润」自动剥离一次性损益，若调用方把 GAAP 净利润误作核心经营利润，调整后 PE 会失真；因此静态提示口径、不越权抽取。
- **研发「一次性加回」局限性**：研发费用化加回是简化近似，未做多年摊销/资本化建模，无法反映研发投入的持续性与潜在沉没成本。
- **负 PE 情形**：回加研发后仍亏损时 PE 无经济意义，故降级 N/A，不强行输出负 PEG。
- **增速口径**：`growth` 用百分点数值（非小数 0.30），误用会导致 PEG 放大 100 倍，须在 `--help` 与提示强调。
- **档位非投资结论**：档位仅是估值温度参考，最终须结合同业、宏观利率区间（框架第五部分）综合判断。
