## 1. 子任务定位与权威依据

P1-4 是 `financial_rigor.py` 计算核心扩展的第 4 个子命令，目标是为 GARP 框架「第4步 估值锚定——多工具矩阵」中**高研发投入型（利润被压低）**公司提供成长质量判定工具。

权威口径（框架第 4 步，行 385/390）：

$$
Rule\ of\ 40 = 营收增速\% + 利润率\%（利润口径）\quad 或 \quad 营收增速\% + FCF利润率\%（FCF口径）
$$

- 判定阈值：`≥ 40` 通过（经营质量合格），`< 40` 不达标。
- 适用场景：高研发投入型公司（利润被研发费用化压低），`Rule of 40` 作为 `PS / EV/Sales` 主锚的**辅助工具**，衡量「增长与盈利之间的平衡质量」。
- 两种口径二选一：**利润口径**（`利润率`）或 **FCF 口径**（`FCF 利润率`）。

本子命令定位为**纯计算 + 口径标识 + 合理性提示**：接收营收增速 + 净利润率（或 FCF 利润率），输出 `rule_of_40` 分值、`passed` 布尔判定及口径标识。不在此做数据抽取（净利率/FCF 利润率由调用方技能提供）。

## 2. 目标与范围

### 2.1 目标

1. 在 `financial_rigor.py` 新增 `rule_of_40()` 函数，精确计算 Rule of 40 分值至 2 位小数。
2. 新增 `rule-of-40` 子命令（argparse 注册 + `main()` 派发）。
3. 判定 `≥40` 通过 / `<40` 不达标，输出结构化 JSON（核心字段 `rule_of_40`、`passed`）。
4. 支持利润口径与 FCF 口径二选一，并输出 `margin_type` 口径标识。

### 2.2 范围（做什么 / 不做什么）

**做什么：**

- 精确加法计算 `rule_of_40 = revenue_growth + margin`（`Decimal` 引擎）。
- `passed` 基于 2 位小数舍入后的分值与 `40.00` 比较（保证显示值与判定一致）。
- 口径二选一校验：利润口径 `--profit-margin` 与 FCF 口径 `--fcf-margin` 必须且只能提供一个。
- 合理性告警（负营收增速/负利润率等）收集进 `warnings`，不拒绝计算。
- 输出 `margin_type`（`profit` / `fcf`）与 `verdict`（中文结论）。

**不做什么：**

- **不抽取/计算**净利率或 FCF 利润率（由调用方技能基于报表提供单一数值）。
- **不做**与同业可比、PS/EV-Sales 的交叉判断（那是 `/garp-valuation` 技能编排层职责）。
- **不引入**公司类型参数或 ESG/宏观折价（折价叠加在 P4 技能层完成，本工具只做原子判定）。
- **不回改**既有 13 个子命令签名/行为。

## 3. 关键量化口径与单位规范

### 3.1 公式与单位

| 输入项 | CLI 参数 | 单位 | 说明 |
| --- | --- | --- | --- |
| 营收增速 | `--revenue-growth` | **百分点**（如 30 = 30%） | 与 P1-1 `--wacc`、P1-3 `re/rd` 口径一致 |
| 利润率 | `--profit-margin` | **百分点**（如 25 = 25%） | 利润口径（与 `--fcf-margin` 二选一） |
| FCF 利润率 | `--fcf-margin` | **百分点**（如 15 = 15%） | FCF 口径（与 `--profit-margin` 二选一） |

> 单位约定为待确认决策点 D2（见第 8 节）。

### 3.2 二选一口径规则

- 利润口径与 FCF 口径**互斥**，必须且只能提供一个：
  - 都未提供 → 降级 N/A（「未提供利润率或 FCF 利润率」）。
  - 都提供 → 降级 N/A（「利润口径与 FCF 口径互斥，请二选一」）。
- 有效时，`margin_type` 记为 `"profit"` 或 `"fcf"`。

### 3.3 判定阈值的精确比较

`passed` 判定**基于 `quantize(Decimal("0.01"))` 后的分值**与 `Decimal("40.00")` 比较（`>=` 为 True），确保控制台显示的 2 位小数分值与其判定结论严格一致，避免「显示 40.00 却判不达」的边界歧义。样例如：

- `30 + 25 = 55.00 → passed=True`
- `25 + 15 = 40.00 → passed=True`（边界恰好 ≥40）
- `15 + 10 = 25.00 → passed=False`

## 6. 函数与 CLI 实现设计

### 6.1 `rule_of_40()` 函数签名

```python
def rule_of_40(revenue_growth, profit_margin=None, fcf_margin=None):
    """判定软件/高研发型公司成长质量（Rule of 40）。

    公式：Rule of 40 = 营收增速% + 利润率%（利润口径）
                  或 = 营收增速% + FCF利润率%（FCF口径）。
    ≥40 通过，<40 不达标；利润口径与 FCF 口径二选一；单位均为百分点。

    Args:
        revenue_growth: 营收增速（百分点，如 30 表示 30%）。
        profit_margin: 利润率（百分点，如 25 表示 25%），可选，与 fcf_margin 二选一。
        fcf_margin: FCF 利润率（百分点，如 15 表示 15%），可选，与 profit_margin 二选一。

    Returns:
        dict: 含 rule_of_40 / passed / margin_type / verdict / warnings /
              inputs 审计回显字段。
    """
```

### 6.2 核心计算逻辑（伪代码）

```python
g = exact(revenue_growth)

# 口径二选一校验
if (profit_margin is None) == (fcf_margin is None):
    # 都 None 或都非 None → 降级 N/A（rule_of_40=None, passed=None）
    return result

margin_type = "profit" if profit_margin is not None else "fcf"
m = exact(profit_margin if profit_margin is not None else fcf_margin)

rule_of_40_dec = g + m
rule_of_40_val = rule_of_40_dec.quantize(Decimal("0.01"))   # 2 位小数
passed = rule_of_40_val >= Decimal("40.00")                  # 与显示值一致

# 合理性告警（不拒绝计算）
warnings = []
if g < 0: warnings.append("营收增速为负（收缩期），Rule of 40 被拉低")
if m < 0: warnings.append("利润率/FCF 利润率为负（亏损），Rule of 40 被拉低")

verdict = "通过（Rule of 40 = {:.2f} ≥ 40）" if passed else "不达标（Rule of 40 = {:.2f} < 40）"
```

1. **≥40 通过 / <40 不达标**：`30+25=55 → passed=True`；`15+10=25 → passed=False`。

## 12. 风险与限制

- **单位易混**：营收增速/利润率/FCF 利润率统一百分点（D2），需在 `--help` 与提示文案中反复强调，避免误以小数传入（0.30 会退化为 0.3 个百分点）。
- **口径取舍责任在下游**：本工具只判定「利润口径」或「FCF 口径」二选一，不判断何时该用哪种口径（由 `/garp-valuation` 按公司类型选主锚）。
- **负值不加拦截**：亏损/衰退期公司 Rule of 40 可为负，本工具按 D4 允许负值并仅告警，避免误伤真实场景；判定只依据算术结果，不叠加主观修正。
- **不构成投资决策**：`Rule of 40 ≥ 40` 只是高研发投入型公司估值矩阵的辅助项，最终还需结合 PS/EV-Sales 与同业可比综合判断。
