## 1. 子任务定位与权威依据

P1-5 是 `financial_rigor.py` 计算核心扩展的第 5 个子命令，目标是为 GARP 框架「第4步 估值锚定——多工具矩阵」中**高研发投入型（利润被压低）**与**未盈利科技型**公司提供 `EV/Sales`（企业价值/营收倍数）原子计算工具。

权威口径（框架第4步，行 385~386 + 详细计划 P1-5）：

$$
EV = 市值 + 有息负债 − 现金
$$

$$
EV/Sales = EV \div 营收
$$

- 定位：`PS` 的 EV 版本（市销率剔除资本结构差异，用企业价值替代股权市值）。
- 适用场景：高研发投入型 / 未盈利科技股（利润被研发费用化压低或无盈利）。
- 判定接口：`EV/Sales` **无绝对阈值**，框架要求「低于同业可比」（由 `/garp-valuation` 技能编排层在同业比较时判断），本工具仅做原子计算，不做阈值判定。

## 2. 目标与范围

### 2.1 目标

1. 在 `financial_rigor.py` 新增 `ev_sales()` 函数，精确计算 `EV` 与 `EV/Sales`（2 位小数）。
2. 新增 `ev-sales` 子命令（argparse 注册 + `main()` 派发）。
3. 输出结构化 JSON，核心字段 `{ev, ev_sales}`（与详细计划签名一致）。
4. 提供分母护栏、净现金/负 EV、负科目合理性提示。

### 2.2 范围（做什么 / 不做什么）

**做什么：**

- `EV = market_cap + debt − cash` 精确加减。
- `EV/Sales = EV / revenue` 精确除法。
- 结果 `quantize(Decimal("0.01"))` 后转 float，2 位小数。
- 收集合理性告警（负科目、净现金、EV 为负）进 `warnings`。

**不做什么：**

- **不做** `EV/Sales` 绝对阈值判定（无天然阈值，需同业可比）。
- **不做**同业可取到的 `EV/Sales` 对比（下游技能编排层职责）。
- **不引入** `--currency` / `--unit` 转换（四金额同单位，比值无量纲，见 D1）。
- **不叠加** ESG 折价 / 宏观调整（P4 技能层职责）。
- **不回改**既有 14 个子命令签名/行为，不回改 `terminal_value.py`。

## 3. 关键量化口径与单位规范

### 3.1 公式、输入科目与单位

| 输入项 | CLI 参数 | 科目口径 | 单位 |
| --- | --- | --- | --- |
| 市值 | `--market-cap` | 股权市值 | 与其余三金额**同一货币单位**（裸数值） |
| 有息负债 | `--debt` | 有息负债（不含应付账款等经营负债） | 同上 |
| 现金 | `--cash` | 现金及现金等价物 | 同上 |
| 营收 | `--revenue` | 最近 12 个月（TTM）营收 | 同上 |

> 单位约定为待确认决策点 D1（见第 7 节）。

### 3.2 EV 科目口径

- `debt` 为**有息负债**，不含无息经营负债；`cash` 为**现金及现金等价物**（不含受限现金口径，如受限则按框架的科目口径由调用方先行调整）。
- `EV = 市值 + 有息负债 − 现金`：把股权市值还原为「整个企业的经营价值」，剔除净现金/净负债的资本结构差异。

### 3.3 输出

- `ev`：企业价值，**原输入单位**（与四金额同单位），2 位小数。
- `ev_sales`：企业价值/营收倍数，**无量纲**（`EV ÷ revenue`，两金额同单位相除即消除单位），2 位小数。

## 6. 函数与 CLI 实现设计

### 6.1 `ev_sales()` 函数签名

```python
def ev_sales(market_cap, debt, cash, revenue):
    """计算企业价值/营收倍数（EV/Sales）。

    公式：EV = 市值 + 有息负债 − 现金；EV/Sales = EV ÷ 营收。
    适用高研发投入型 / 未盈利科技股；EV/Sales 无绝对阈值，需同业可比。

    Args:
        market_cap: 市值（与其余金额同一货币单位）。
        debt: 有息负债（同一货币单位）。
        cash: 现金及现金等价物（同一货币单位）。
        revenue: TTM 营收（同一货币单位）。

    Returns:
        dict: 含 ev / ev_sales / hint / warnings / inputs 审计回显字段。
    """
```

### 6.2 核心计算逻辑（伪代码）

```python
mc = exact(market_cap)
debt = exact(debt)
cash = exact(cash)
revenue = exact(revenue)

# 分母护栏：revenue <= 0 → 降级 N/A（除零或负分母无意义）
if revenue <= 0:
    return { "ev": None, "ev_sales": None, "hint": ..., "warnings": [“营收 ≤ 0，无法计算 EV/Sales”], ... }

ev_dec = mc + debt - cash
ev_val = ev_dec.quantize(Decimal("0.01"))

ev_sales_val = (ev_dec / revenue).quantize(Decimal("0.01"))

# 合理性告警（不拒绝计算）
warnings = []
if mc < 0: warnings.append("市值为负（数据异常）")
if debt < 0: warnings.append("有息负债为负（数据异常）")
if cash < 0: warnings.append("现金为负（数据异常）")
if ev_dec < 0: warnings.append("净现金公司：EV 为负（现金 > 市值 + 有息负债），EV/Sales 为负值")
if ev_dec == 0: warnings.append("EV = 0（现金恰好等于市值 + 有息负债），EV/Sales = 0")

hint = "EV/Sales 无绝对阈值，需与同业可比（高研发投入/未盈利科技股适用）"
```

## 9. 验收标准

1. **EV 与 EV/Sales 正确至 2 位小数**：标准样例 `800/150/50/200 → ev=900.00, ev_sales=4.50`。
2. **净现金/负 EV 正常计算**：`100/0/150/50 → ev=−50.00, ev_sales=−1.00`，且 `warnings` 提示净现金。
3. **分母护栏**：`revenue <= 0` 降级 N/A 且无异常退出。
4. **负科目告警**：`debt<0` / `cash<0` / `market-cap<0` 计入 `warnings` 不拒绝。
5. **JSON 可解析**：`ev` / `ev_sales` 类型正确（数值），`json.dumps` 输出合法。
6. **回归无扰动**：既有 14 个子命令（原 10 + `roic` + `incremental-roic` + `wacc` + `rule-of-40`）功能不受影响。

## 12. 风险与限制

- **科目口径依赖调用方**：`debt` 是否严格限定「有息负债」、`cash` 是否含「受限现金」，直接影响 EV 真实性；本工具不做科目清洗，仅按输入值原子计算。
- **单位易混**：四金额必须同单位，若混用（市值用亿元、营收用元）会导致 EV/Sales 数量级错误；工具无法跨单位校验，须在 `--help` 与提示文案强调「同一货币单位」。
- **负 EV 不加拦截**：净现金科技公司很常见，按 D3 允许负值并仅告警，避免误伤真实场景。
- **无绝对阈值**：`EV/Sales` 的「高低」本质是同业相对概念，本工具只输出倍数，不给出高估/低估结论。
- **不构成投资决策**：`EV/Sales` 只是估值矩阵辅助项，最终需结合 Rule of 40、同业可比与 DCF 综合判断。
