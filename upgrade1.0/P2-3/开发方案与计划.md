## 1. 任务定位与依据

- **来源**：总计划 P2-3（不拆）；详细计划 P2-3（第 296-305 行）。
- **目标**：在 `tools/specialized/macro_calibrator.py` 上**新增 `calibrate` 子命令**，输入标的当前 PEG、现金仓位、单只占比，按给定宏观阶段（美林四档）输出宏观校准后的 PEG 判断、现金下限、单只上限，且全程可审计复现。
- **定位**：属 Phase 2「宏观校准引擎」第三棒（收官），连接 P2-1（三表权威数据结构 + 查表）与 P2-2（取数 + 软判定 stage）：
  - P2-1 = 查表（入 stage 出参数）；
  - P2-2 = 取数 + 软判定 stage（入数据出 `rate_stage`/`econ_stage`/`indicators`）；
  - **P2-3 = 校准（入 stage + 标的三参数，出校准结论 `validation`）**。
- **本质边界**：P2-3 **只做查表与精确数值比较**，不拉取宏观数据、不做「指标 → stage」判定（那是 P2-2 职责），也不替代个股基本面判断（框架行 685）。

## 2. 目标与范围

**本任务做的**：

1. 在 `macro_calibrator.py` 新增 `calibrate` 子命令（`argparse` 子命令叠加，不破坏既有 `stage`/`data` 子命令）。
2. 实现 `calibrate(stage, peg, current_cash, single_stake, tier)` 纯函数：查 P2-1 三表 + 精确数值比较，输出校准结论。
3. 输出结构化 JSON：`{stage, peg, current_cash, single_stake, stake_tier, calibrated_peg_verdict, cash_floor, cash_ok, single_cap_upper, single_cap_ok, validation}`。

- 不新增「指标数值 → stage」的隐性阈值；P2-3 只消费既有三表与框架明示数值（见第 3 节）。
- 不改动 P2-1 既有三表结构/四函数/`stage` 子命令签名、不改动 P2-2 `data` 子命令签名（本任务为**增量新增**）。
- 不改动既有 43 技能及既有其他工具签名；不在本任务落 `docs/` 三份市场使用指南。

## 3. 关键量化口径

### 3.1 权威依据（框架第五部分·四 + 第三部分·仓位）

- 校准映射唯一权威 = 框架行 680-749「四、宏观环境适配」三表 + 行 715-730 仓位收紧口径 + 行 456-466、623-629 组合仓位口径。
- 执行顺序沿用框架行 687-694「以（一）+（二）算参数、（三）总收口」：PEG 用第（一）表，现金/单只用第（二）表，单只上限默认取「验证后」档（与 P2-1 `summary()` 决策 D4 一致）。

### 3.2 PEG 校准数值阈值表（新增常量，权威 = 框架表一 700-704 + 行 712/713/706）

| stage | 合理买入区间/上限 `peg_ceiling` | 低估阈值 `peg_under` | 高估阈值 `peg_over` | 来源 |
| --- | --- | --- | --- | --- |
| 衰退 | 1.0（临时收紧） | None（框架未给） | None（框架未给） | 行 738/746 |
| 复苏 | 1.5（放宽） | 1.2（<1.2） | 1.5（>1.5 减仓） | 行 704/739 |
| 过热 | 1.0（收紧） | 0.7（<0.7） | 1.2（>1.2） | 行 702/740 |
| 滞胀 | 0.8（最紧） | None（框架未给） | None（框架未给） | 行 713/741 |

- **全局红线**：`PEG > 2` 为严重透支（框架行 706/712），该红线不因降息取消——在 verdict 之上附加 `red_flag=true` 与提示。
- 上述阈值全部来自框架原文**明示数值**，程序硬编码为数值常量表（不解析 P2-1 展示字符串、不 LLM 心算），并逐格落盘来源行号。

### 3.3 PEG verdict 判定规则（程序精确比较）

```
若 peg_under 存在 且 peg < peg_under                 → 「低估（可加仓）」
若 peg <= peg_ceiling                               → 「合理买入」
否则：
  若 peg_over 存在 且 peg > peg_over                → 「高估（减机动仓）」
  若 peg_over 存在 且 peg_ceiling < peg <= peg_over → 「合理偏贵（持有不加仓）」
  若 peg_over 不存在（衰退/滞胀） 且 peg > ceiling   → 「超出合理上限（不新建仓）」
若 peg > 2.0                                       → 附加 red_flag=true（严重透支、加速清机动仓）
```

> 枚举不臆造：衰退/滞胀档框架未给低估/高估阈值，故不做「低估/高估」细分，只给「合理买入 / 超出合理上限」。`合理偏贵` 中间带仅当 `peg_over > peg_ceiling` 时存在（本框架实际仅「过热」档存在该中间带）。

### 3.4 现金下限数值化（新增常量，权威 = 框架行 721/729/730/748）

| stage | 现金下限数值 `cash_floor_min` | 现金仓位原始口径 |
| --- | --- | --- |
| 衰退 | 30%（30~40% 或更高） | 行 721/738 |
| 复苏 | 10%（常温 10%~20%；估值分位>80% 提高至 20%~30%） | 行 721/748 |
| 过热 | 25%（≥25%） | 行 730/740 |
| 滞胀 | 40%（≥40%） | 行 729/741 |

- `cash_ok = (current_cash >= cash_floor_min)`，`cash_gap = current_cash - cash_floor_min`（正数=满足，负数=缺口），由程序精确计算。
- 复苏档存在「估值分位>80% 时下限提高至 20%」的分位数修正，但 P2-3 不引入分位数输入（详细计划未列），仅在输出 `validation.note` 提示该边界，避免私自扩展输入面。

### 3.5 单只上限三档数值化（新增常量，权威 = 框架行 722/729/730 + 行 461）

| stage | 初始 `initial` | 验证后 `verified` | 绝对 `absolute` | 行业上限 |
| --- | --- | --- | --- | --- |
| 衰退 | 8% | 12% | 15% | 30% |
| 复苏 | 10% | 15% | 20% | 40% |
| 过热 | 8% | 12% | 15% | 25% |
| 滞胀 | 6% | 10% | 12% | 20% |

- `single_cap_upper` 按 `tier`（initial/verified/absolute）取对应档，默认 `verified`（与 P2-1 `summary()` 一致）。
- `single_cap_ok = (single_stake <= cap_value)`，`single_cap_gap = cap_value - single_stake`（正数=未超限，负数=超限），由程序精确计算。
- 输出同 stage 三档明细 `single_caps` + 行业上限 `industry_cap`，便于人工对照（不改次数值来源）。

## 6. 关键设计决策

> 决策状态：**D1~D7 已于 2026-09-15 逐项确认，均采用推荐结论**；每条给出推荐值与否决备选。

| 决策点 | 推荐结论 | 否决备选 |
| --- | --- | --- |
| D1 stage 来源 | `--stage` 显式必填为主；可选 `--from-data` 从缓存软判定带入（标记 `stage_source="soft_infer"` + `manual_review=true`） | 仅自动软判定 / 仅显式 |
| D2 PEG 判定口径 | 程序精确数值比较，阈值用显式常量表（框架明示数值，落盘行号），不解析展示字符串 | 解析 P2-1 字符串阈值 / LLM 心算 |
| D3 现金下限 | 新增数值常量表（10/30/25/40），程序比较达标；估值分位修正仅提示不扩展输入 | 引入 `--valuation-percentile` 输入 / 只回显不判定 |
| D4 单只上限档位 | 默认 `verified`（对齐 P2-1 summary），可选 `--stake-tier` 切换三档 | 只输出绝对档 / 恒输出三档不判定 |
| D5 输入校验 | PEG>0；0≤现金/单只≤100；stage/tier 枚举校验；非法即 `❌` + 非零退出 | 不校验 / 静默容错 |
| D6 validation 结构 | 记录 inputs + 来源行号 + 三段比较过程字符串 + stage_source/note | 只回显输入 / 不含比较过程 |
| D7 网络边界 | `calibrate` 默认纯离线查表（与 `stage` 一致）；仅 `--from-data` 读缓存、不刷新网络 | 每次自动调用 `data` 刷新 / 强制联网 |

**D1 — stage 来源（推荐：显式 `--stage` 为主 + 可选 `--from-data`）**
- `calibrate` 的校准映射必须以「美林四档」为唯一主键。显式 `--stage` 是**权威、确定性、可复现**的来源，与 P2-1 查表接口一致；P2-2 的 `econ_stage`/`rate_stage` 只是**软判定（manual_review=true、confidence=低）**，不应默认作为权威输入。
- 推荐：`--stage` 必填为主；提供 `--from-data` 允许从 `data/macro/macro_snapshot.json` 的缓存软判定带入 stage，但输出 `validation.stage_source="soft_infer"` 并附 `manual_review=true` 警示。
- 备选 A（仅自动软判定）：把非权威软判定当硬输入，违背「软判定可人工覆盖」原则，**不推荐**。
- 备选 B（仅显式，无 `--from-data`）：最简但弱化 P2-2→P2-3 链路衔接。

**D2 — PEG 判定口径（推荐：显式数值常量表 + 程序比较）**
- P2-1 `RATE_TABLE` 的 `peg_undervalue/peg_overvalue` 是**展示字符串**（如 `">1.5 减仓，>2 绝对透支清机动仓"`），若直接解析字符串则脆弱且反直觉；但数值阈值本就来自框架明示数值。
- 推荐：新增 `CALIBRATE_PEG` 数值常量表（3.2 节），逐格落盘来源行；`calibrate_peg` 用 `float` 精确比较，verdict 枚举见 3.3；全程无 LLM 心算。
- 备选 A（解析 P2-1 字符串）：把「展示文案」当「可计算结构」解析，脆弱且耦合既有表。
- 备选 B（LLM 心算判断区间归属）：违反「禁止 LLM 心算」硬约束，**否决**。

**D3 — 现金下限（推荐：数值常量表 + 达标判定，分位数只提示）**
- 框架行 721/729/730/748 给出「复苏 10%（常态）、衰退 30~40%、过热 ≥25%、滞胀 ≥40%」明确下限；「估值分位>80% 提高至 20~30%」是条件修正。
- 推荐：新增 `CALIBRATE_CASH_FLOOR` 取下限数值做达标判定；分位数修正不引入新输入，仅在 `validation.note` 提示边界。
- 备选 A（引入 `--valuation-percentile`）：扩展输入面，详细计划未列，**过度设计**。
- 备选 B（只回显 `cash_floor` 不判定）：弱化「校准」目标。

**D4 — 单只上限档位（推荐：默认 verified + 可选 `--stake-tier`）**
- 框架三档（初始/验证后/绝对）阈值不同；详细计划输出仅单数 `single_cap_upper`。
- 推荐：`--stake-tier`（initial/verified/absolute）默认 `verified`，与 P2-1 `summary()` 的 `single_cap` 取「验证后」档一致；输出同 stage 三档明细供人工对照。
- 备选 A（只输出绝对档 20%）：把最宽容档当默认，可能误判超限。
- 备选 B（恒输出三档不判定）：不满足详细计划「输出单数 single_cap_upper」且弱化结论。

**D5 — 输入校验（推荐：严格校验 + 非零退出）**
- 推荐：`--peg` 必须 >0；`--current-cash`/`--single-stake` 必须在 [0,100]；stage/tier 枚举非法即报错返回 1。防止负 PEG、超 100% 仓位等非法输入产出误导结论。
- 备选（不校验/静默容错）：可能把明显错误输入当有效结论，**不推荐**。

**D6 — validation 结构（推荐：可复现审计字段）**
- 推荐：`validation` 记录 `inputs`（含 stage/tier）、`rate_source`/`econ_source`（来源行号）、`peg_compare`/`cash_compare`/`single_compare`（比较过程字符串）、`stage_source`/`note`，保证任一结论可回溯到框架原文与输入。
- 备选（只回显输入或省略比较过程）：不满足详细计划「输出 validation 字段可审计复现」。

**D7 — 网络边界（推荐：默认纯离线）**
- `calibrate` 是纯查表 + 数值比较，与 `stage` 一样**默认零网络**；只有 `--from-data` 才读本地缓存（不触发 akshare 刷新）。保证校准结论确定性、可复现、无时变依赖。
- 备选（每次自动 `data` 刷新）：引入时变与网络不确定性，**不推荐**。

## 9. 验收标准

逐条对照详细计划 P2-3 验收标准（并补硬约束）：

1. **输出含 `validation` 可审计复现**：`validation` 记录 `inputs`（含 stage/tier）、`rate_source`/`econ_source`（框架行号）、`peg_compare`/`cash_compare`/`single_compare` 比较过程，任一结论可回溯到输入 + 框架原文。
2. **校准结果与三表一致**：`calibrate` 的 PEG 区间、现金下限、单只上限取值与 P2-1 三表 + 框架 680-749 逐格一致；无明显数值偏差。
3. **JSON 可解析且 schema 对齐 4.3**：`calibrate` 输出可被 `json.loads` 解析，字段含 `stage/peg/current_cash/single_stake/calibrated_peg_verdict/cash_floor/cash_ok/single_cap_upper/single_cap_ok/validation`。
4. **精确算术非 LLM 心算**：PEG verdict 归属、现金达标、单只超限均由程序 `float` 精确比较完成，比较过程落盘到 `validation`。
5. **严格输入校验**：非法 stage/tier/PEG/现金/占比输入报错并返回非零退出码，不产出误导结论。
6. **回归无损**：新增 `calibrate` 不破坏既有 `stage`/`data` 子命令、`--help`、P2-1 四函数与三表；既有 44 项测试全量通过 + 新增 `calibrate` 测试通过。
