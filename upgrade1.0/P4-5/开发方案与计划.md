## 1. 目标与范围

### 1.1 目标

把框架**第4步「估值锚定——多工具矩阵」**（行 378~438）与**第五部分·四「宏观环境适配」**（行 681~748）落成一个可独立调用的 GARP 独立档技能，达成三件事：

1. **类型分流定主锚**：按「快速增长型 / 高研发投入型 / 未盈利科技型 / 稳定增长型 / 成熟型企业」五分，为标的选定**唯一主锚工具**与辅助校验工具（框架行 381~387 硬编码）；
2. **算数全部外置**：所有估值数值（调整后 PEG、EV/Sales、Rule of 40、隐含增速、DCF 现值与安全边际、复合增速）**一律由 `financial_rigor.py` 输出**，宏观参数一律由 `macro_calibrator.py` 查表，ESG 折价一律由 `governance_data.py esg` 透传；**技能层零心算、零自造阈值**；
3. **收口为单一估值结论**：把「类型内多工具结论 + 宏观校准 + ESG 折价」三层**收口为一个统一档位**，并映射为可执行的建仓节奏（分批建仓规则，框架行 393~401）。

## 2. 关键量化口径（唯一权威 = 框架第4步行 378~438 + 第五部分·四行 681~748）

> **引用不重复定义原则**：本节只列「本技能必须固定下来、可直接执行」的口径与阈值；定义原文一律指向框架行号，不复制粘贴整段论述。

### 2.1 公司类型五分与主锚表（硬编码，框架行 381~387 逐格落地）

| 公司类型 | 核心工具（主锚） | 辅助工具 | 可接受标准（框架原文阈值） |
| --- | --- | --- | --- |
| **快速增长型（盈利稳定）** | 调整后 PEG | 远期 PE、PEG 分位 | PEG < 1 低估；1~1.2 合理；1.2~1.5 合理偏贵（持有不加仓、机动仓择机减）；> 1.5 高估 |
| **高研发投入型（利润被压低）** | PS / EV/Sales | Rule of 40 | Rule of 40 ≥ 40（收入增速 + 利润率或 FCF 利润率）；EV/Sales **低于同业可比** |
| **未盈利科技型** | PS、EV/Sales | 研发管线 NPV | 需有**清晰的盈利路径和里程碑节点** |
| **稳定增长型** | 远期 PE + 隐含 PEG | 股息率 | 当前 PE ≤ 未来 3 年 EPS 复合增速（百分数值）× 1.2（即**隐含 PEG ≤ 1.2**） |
| **成熟型企业** | DCF | 股息贴现 | 当前市值 ≤ **保守 DCF 估值的 80%** |

**类型判定的兜底规则**（本技能口径化，防「挑选有利类型」）：

1. 类型判定须**先给出数据依据**（营收增速、净利率、研发强度、经营现金流符号、上市年限），再套类型；
2. 满足多个类型特征时，**按「盈利稳定性优先」排序**：盈利为负 → 未盈利科技型；净利率 <5% 或研发强度显著高于同业 → 高研发投入型；增速连续 ≥20% 且盈利稳定 → 快速增长型；增速稳定 10%~20% → 稳定增长型；增速 <10% 且现金流成熟 → 成熟型企业；
3. **类型判定结果须在报告中显式列出依据与被排除的类型**，禁止无声跳档；
4. **不得为「套用更宽松阈值」而挑选类型**（记入 `GV-1`）。

### 2.2 快速增长型：调整后 PEG 四档 + 宏观浮动（框架行 383、行 421、行 699~703）

**口径**：调整后 PEG = **调整后 PE ÷ 未来增速（%）**；调整后 PE = 市值 ÷（**核心经营利润 + 研发费用回加**）——用于消除「研发费用化虚增 PE、虚增 PEG」（框架行 421）。工具：`financial_rigor.py adjusted-peg`（P1-6），**取数值，不取工具内置档位**（`GV-2`）。

**基准档位（中性宏观，框架行 383）**：

| 档位 | 调整后 PEG |
| --- | --- |
| 低估 | < 1.0 |
| 合理 | 1.0 ~ 1.2 |
| 合理偏贵 | 1.2 ~ 1.5 |
| 高估 | > 1.5 |

**宏观浮动后的区间**（框架行 699~703 + 行 737~740，**由 `macro_calibrator.py stage` 给出，不得自行换算**）：

| 宏观 stage | 合理买入区间（工具 `peg_interval`） | 低估（可加仓） | 高估（减机动仓） |
| --- | --- | --- | --- |
| 加息 / 过热 | `[0.8, 1.0]` | < 0.7 | > 1.2（0.7~0.8 为**空档，不主动加仓**） |
| 中性 | `[1.0, 1.2]` | < 1.0 | > 1.5 |
| 降息 | `[1.2, 1.5]` | < 1.2 | 仍 > 1.5 减仓，**> 2 绝对透支清机动仓** |
| 复苏 | `[1.2, 1.5]` | < 1.2 | 同上 |
| 衰退 | `[1.0]`（**仅给上限**） | 见 §9.B | 按（一）表降息档节奏 |
| 滞胀 | `[0.8]`（**仅给上限**；PEG ≥ 0.8 即不新建仓） | 见 §9.B | 同上 |

**红线**：**「PEG > 2 为严重透支」不因降息而取消**（框架行 711），只可放缓减仓节奏。

> **实测确认（2026-09-17）**：`macro_calibrator.py stage` 对衰退/滞胀返回**单值数组** `[1.0]` / `[0.8]`（仅上限），对加息/过热返回 `[0.8, 1.0]`、对中性返回 `[1.0, 1.2]`、对降息/复苏返回 `[1.2, 1.5]`；顶层字段名为 `peg_interval` / `cash_floor` / `single_cap`（**单只上限于 `merrill_stage.single_cap_verified` 与 `econ_stage.single_verified` 亦同步给出**）。单值情形的下限缺失处理见 **§9.B**。

### 2.3 稳定增长型：远期 PE + 隐含 PEG（框架行 386）

**口径**：当前 PE ≤ 未来 3 年 EPS 复合增速（百分数值）× 1.2，即 **隐含 PEG ≤ 1.2**。

- 算术：`financial_rigor.py peg --pe {当前PE} --growth {未来3年EPS复合增速}`（取数值）；
- 复合增速：`financial_rigor.py calc --expr "((第3年EPS/当前EPS)**(1/3)-1)*100"`（**幂运算用 `**`，`^` 被白名单拒绝**）；
- 市值隐含倒推校验：`financial_rigor.py implied-growth`（红/黄/绿三灯）；
- **不得**用第2年一致预期替代第3年口径（口径不一致即为违规）。

### 2.4 高研发投入型：Rule of 40 + EV/Sales（框架行 384、行 389）

- **Rule of 40** = 营收增速（%）+ 利润率（%）**或** FCF 利润率（%）≥ **40** 为通过，< 40 不达标；工具 `financial_rigor.py rule-of-40`（P1-4），`--profit-margin` 与 `--fcf-margin` **二选一**且**须标注选用口径**；
- **EV/Sales** = EV ÷ TTM 营收，EV = 市值 + 有息负债 − 现金；工具 `financial_rigor.py ev-sales`（P1-5）；
- 可接受标准为「**低于同业可比**」——同业倍数须取 **≥2 家可比公司**并显式列出，**不得以行业均值一句话替代**（`GV-3`）。

### 2.5 未盈利科技型：PS / EV/Sales + 研发管线 NPV（框架行 385）

- 主锚为 **PS / EV/Sales**（工具同上）；
- 辅助「研发管线 NPV」缺工具的问题**已确认按 E-2 处置**：新增工具子任务 **P3-8**（`in_research_scan.py` 新增 `pipeline-npv` 子命令）；**P3-8 交付后**本技能直接调用取 NPV 数值，并标注其假设与口径；**P3-8 交付前**按「**定性 + 数据缺口标注**」降级（列出在研项目/里程碑/预计商业化年份，标注「NPV 未量化」），**不得臆造数值**（`GV-10`）；
- 可接受标准为「**需有清晰的盈利路径和里程碑节点**」——须逐条列出「里程碑 → 预计兑现时点 → 证据来源」，缺一即标「**不满足**」。

### 2.6 成熟型企业：DCF（框架行 387）

- 工具 `financial_rigor.py dcf`（P1-7）：输入 `--fcf --g-high --years-high --years-fade --g-terminal --r --shares --market-cap [--currency] [--rf] [--discrete-risks]`；输出 `{pv, per_share, margin_of_safety_pct}`；
- 判定：**当前市值 ≤ 保守 DCF 估值 × 80%** 为低估（等价于安全边际 ≥ 20%）；
- **参数硬约束**继承 `terminal_value.py audit` 三条：① **r − g 宽度**（太窄给 audit 告警）；② **币种一致性**（`--currency`）；③ **离散风险归属**（`--discrete-risks`）；
- **保守口径要求**：`--g-terminal` 不得高于长期名义 GDP 增速量级，`--r` 不得低于同币种无风险利率；越界须显式说明理由并标注「非保守口径」（`GV-4`）。

### 2.7 统一收口五档与类型映射（本技能口径化，**待 §9.A 确认**）

框架第4步只给出**五类各自的可接受标准**，未给出跨类型的统一档位。本技能须把它收口为**一套可被下游消费的档位**（`garp-exit` 的「估值判断」级、`garp-investment-checklist` 的建仓前置），故定义：

| 统一档位 | 操作含义（框架行 383 + 行 703、行 393~401） |
| --- | --- |
| **显著低估** | 绝佳买点；底仓可加；首批可按下限建仓 |
| **低估** | 可建仓（进入合理买入区间之下沿）；先建 1/3 首仓 |
| **合理** | 合理买入区间；先建 1/3 首仓 |
| **合理偏贵** | **持有不加仓**；机动仓逢高择机减；**不新建仓** |
| **高估** | 不加仓；机动仓减持 |
| **严重透支** | PEG > 2 红线；加速清机动仓 |

**类型映射规则（PEG 类主锚，直接由宏观校准后的区间判定）**：

| 档位 | 快速增长型（调整后 PEG） | 稳定增长型（隐含 PEG） |
| --- | --- | --- |
| 显著低估 | PEG < 区间下限 − 0.2（加息/过热档为 < 0.7） | 隐含 PEG < 0.8 |
| 低估 | 区间下限 − 0.2 ≤ PEG < 区间下限 | 0.8 ≤ 隐含 PEG < 1.0 |
| 合理 | 区间下限 ≤ PEG ≤ 区间上限 | 1.0 ≤ 隐含 PEG ≤ 1.2 |
| 合理偏贵 | 区间上限 < PEG ≤ 1.5 | 1.2 < 隐含 PEG ≤ 1.5 |
| 高估 | 1.5 < PEG ≤ 2.0 | 1.5 < 隐含 PEG ≤ 2.0 |
| 严重透支 | PEG > 2.0 | 隐含 PEG > 2.0 |

**类型映射规则（非 PEG 主锚，按「相对基准的偏离」换算，**待 §9.A 确认**）**：

| 类型 | 显著低估 | 低估 | 合理 | 合理偏贵 | 高估 | 严重透支 |
| --- | --- | --- | --- | --- | --- | --- |
| 高研发投入型 | EV/Sales ≤ 同业 0.6× 且 Rule of 40 ≥ 50 | EV/Sales ≤ 同业 0.8× 且 Rule of 40 ≥ 40 | EV/Sales ≈ 同业（0.8~1.2×）且 Rule of 40 ≥ 40 | EV/Sales 1.2~1.5× 或 Rule of 40 35~40 | EV/Sales 1.5~2.0× 或 Rule of 40 30~35 | EV/Sales > 2.0× 或 Rule of 40 < 30 |
| 未盈利科技型 | — | 里程碑全部按期兑现 + 现金跑道 ≥ 36 个月 | 里程碑兑现且盈利路径清晰 | 里程碑延期 ≤ 1 项 | 里程碑延期 ≥ 2 项 | 盈利路径不可信 / 现金跑道 < 12 个月 |
| 成熟型企业 | 安全边际 ≥ 40% | 安全边际 ≥ 20%（即市值 ≤ 保守 DCF 80%） | 0% ≤ 安全边际 < 20% | −20% ≤ 安全边际 < 0% | −50% ≤ 安全边际 < −20% | 安全边际 < −50% |

> 说明：上表「高研发投入型」的倍数带（0.6×/0.8×/1.2×/1.5×/2.0×）与「成熟型企业」的安全边际带为**本技能为实现「统一收口」而设的操作化刻度**，框架未显式给出——**须经 §9.A 门禁确认后方可固化**，未确认前不得使用。

### 2.8 交叉校验与降级（沿用既有骨架规则 3，口径替换为本矩阵）

| 校验项 | 规则 | 冲突处置 |
| --- | --- | --- |
| **PE 历史分位**（`pe-percentile`） | < 40% 低估 / 40%~60% 合理 / > 60% 偏高 | 与主锚冲突时**主锚降一档**，并显式标注冲突原因与数值 |
| **隐含增速**（`implied-growth`） | 红/黄/绿三灯 | **红灯**：主锚降一档；**黄灯**：标注「偏贵预警」；**绿灯**：标注「估值未透支」 |
| **宏观区间**（`macro_calibrator`） | 加息/过热收紧、降息/复苏放宽、滞胀最紧 | 以**宏观校准后的区间**替换基准区间后**再做档位判定**（不是事后调档） |

**单向性约束**：辅助工具**只能降档、不得升档**（不得因辅助指标好看而把主锚结论升级一档）（`GV-5`）。

### 2.9 宏观叠加（框架行 681~748）

**作用点（三层，边界须清晰）**：

| 层 | 作用对象 | 是否由本技能裁量 |
| --- | --- | --- |
| ① PEG 合理区间 | 本技能的档位判定区间 | ✅ **是**（按 `macro_calibrator stage` 的 `peg_interval` 替换） |
| ② 现金下限 / 单只上限 / 行业上限 | 组合层仓位 | ❌ **否**，只**透传**（`cash_floor` / `single_cap` 原样呈现，归 P4-8） |
| ③ 风格倾向（防御/成长/周期/现金） | 报告结论段的方向提示 | 只**引用**矩阵 `style` 字段，不扩展 |

**调用**：`macro_calibrator.py stage --stage {stage}`（取参数表）+ `macro_calibrator.py calibrate --stage {stage} --peg {PEG} --current-cash {x} --single-stake {y}`（取 `calibrated_peg_verdict` / `cash_ok` / `single_cap_ok`）；**stage 判定归 `garp-macro`（P4-2）**，本技能不自行判定 stage，若上游未给则调 `data` 子命令并**标注 `manual_review=true`**（工具原文口径）。

### 2.10 ESG 环境折价叠加（框架行 423~438）

| 情形 | 折价幅度（框架原文） | 工具字段（`governance_data.py esg`） |
| --- | --- | --- |
| 高环境风险行业（**无明确转型路径**） | 合理估值再打 **8~9 折**（折价 10%~20%），合理 PEG 上限下调至约 1.0 | `discount_factor` / `discount_pct` / `discount_range` |
| 有明确碳减排承诺与**可验证**转型路径 | 折价收窄至 **≤5% 或豁免**（须有资本开支计划、减排节点、第三方验证） | 同上（由工具依入参判定） |
| 面临**「搁浅资产」风险** | 折价加大 **且上调贴现率**（DCF 中额外上调 1~2 个百分点） | `stranded_asset_triggered` / `discount_rate_adj_bps` / `discount_rate_adj_range_bps` |
| **ESG 评级处于行业尾部/最低档** | **不再下调估值，而是先降仓位上限** | `esg_tail_triggered` / `position_cap_after` / `position_cap_downgrade` |

**三条硬边界**：

1. **折价是叠加、不是替代**——「在基本面估值之上再打一次折扣」（框架行 436），多工具估值**照算**，折价在其结果之上施加；
2. **折价率只来自工具透传**，技能层**不得自行估算** 10%/15%/20%（`GV-6`）；
3. **仓位量只透传、不裁量**——报告**不得出现「建议单只上限 X%」**（与 P4-4 `MG-8` 同构，本技能记 `GV-7`）。

### 2.11 估值陷阱四项强制核查（框架行 416~421）

| # | 陷阱 | 核查动作 |
| --- | --- | --- |
| 1 | **低 PE 陷阱** | 周期股/景气顶点须结合**行业周期位置**判断，不得仅凭低 PE 判低估 |
| 2 | **高 PE 但增速不可持续** | 剔除**一次性收益**（出售资产、疫情红利等）后重算真实 PEG |
| 3 | **忽略股权稀释** | EPS 增长须同时核对**总利润增速与股本变化**（回购减少股本 ≠ 真实盈利增长） |
| 4 | **研发费用化扭曲** | 高研发科技股**必须**用核心经营利润口径回算调整后 PE（即主锚须用 `adjusted-peg`） |

### 2.12 分批建仓规则（框架行 393~401）

> **归属声明**：本规则在框架中位于**第4步·估值锚定**之下，故归 `garp-valuation`；**仓位上限数值**归 `garp-portfolio-review`（P4-8）。

| 路径 | 适用 | 节奏 |
| --- | --- | --- |
| **默认三分法** | 绝大多数标的 | 1/3 首仓 → 右侧确认后补至 2/3 → 连续 2~3 季兑现后补齐 |
| **左侧布局** | 行业遇短期利空、长期逻辑未破坏 | 首批 ≤ **标的最终仓位的 50%**（**可建上限、非必须建到**），剩余待右侧确认 |
| **右侧一次性 2/3** | 仅在「**渗透率突破 15% 临界点 + 财报连续 2 季超预期 + 行业景气明确上行**」**三信号共振**时启用 | 剩余 1/3 回调至 20 日均线补 |

**硬约束**：建仓初期（持仓 < 最终仓位 50%，**或**持仓 ≥50% 但逻辑未经 2~3 季财报验证）**8%~10% 硬止损优先于「跌破估值下限补仓」**；**不得以「更便宜」为由逆向补仓**。

### 3.3 降级与失败处置

| 情形 | 处置 |
| --- | --- |
| 增速 ≤ 0 或亏损 | 判「**PEG 不适用**」，按 §2.1 重定类型；再三不适用则标「**数据不足，无法估值**」 |

### 3.4 风控硬编码 `GV-*`（全新编号，`GV-1`~`GV-12`）

| **GV-9** | **「不适用」须显式判定** | 增速 ≤0 / 亏损 / 周期顶点等情形须标「不适用」，不得硬套 PEG |
| **GV-10** | **未量化项不得臆造** | 研发管线 NPV、里程碑等无工具支撑者只作定性并标注数据缺口 |
| **GV-11** | **数据截止日期强制标注** | PE / 一致预期 / 研发强度 / 宏观参数均为时变项，结论仅对截止日有效 |

### §9.A 统一收口五档的「非 PEG 类型映射刻度」（本技能口径化）

**问题**：框架第4步只给五类各自的**可接受标准**（如「EV/Sales 低于同业」「市值 ≤ 保守 DCF 80%」），**未给跨类型可比的统一档位**；而下游（`garp-exit` 的估值判断级、`garp-investment-checklist` 的建仓前置）需要一个**单一结论**。

- **推荐 A-1（推荐）**：采用 §2.7 **六档统一口径**（显著低估 / 低估 / 合理 / 合理偏贵 / 高估 / 严重透支），其中 **PEG 类**严格来自框架行 383 + 宏观区间（**无自造刻度**）；**非 PEG 类**（高研发 / 未盈利 / 成熟型）按 §2.7 第二张表**操作化刻度**换算，并在报告中**同时呈现原始标准**（如 EV/Sales 倍数与同业对比、DCF 安全边际%）与换算后档位，**换算刻度须标注「本技能操作化刻度、非框架原文」**。
- 备选 A-2：非 PEG 类型**不映射统一档位**，只输出「满足 / 不满足可接受标准」二态，收口结论按「主锚满足度为唯一口径」，档位仅对 PEG 类给出。
- 备选 A-3：非 PEG 类型统一降级为「**定性结论 + 数据表**」，不参与档位体系。

### §9.B 衰退 / 滞胀档 `peg_interval` 为单值时的下限处理

**问题**：实测 `macro_calibrator stage` 对**衰退**返回 `[1.0]`、对**滞胀**返回 `[0.8]`（**仅上限**，无下限），而 §2.7 的档位判定需要区间下限。

- **推荐 B-1（推荐）**：**下限沿用同向「最紧档」的下限 0.8**——即滞胀/衰退期判定区间取 **`[0.8, 上限]`**（衰退 `[0.8, 1.0]`、滞胀 `[0.8, 0.8]` → 等价于「PEG < 0.8 才可新建仓，PEG ≥ 0.8 一律不新建仓」），与框架行 745「滞胀期合理买入上限取加息档区间下限 0.8」的表述自洽；**框架未显式给出的下限，报告中须标注「下限为沿用加息档口径、框架未显式定义」**。
- 备选 B-2：单值时**只做上限判定**（PEG > 上限 即「不在合理买入区间」），**不下「低估」结论**。
- 备选 B-3：单值时**标「数据不足，区间判定不可用」**，转由辅助工具做定性提示。

### §9.C 宏观与 ESG 的**叠加顺序**与冲突处置

**问题**：ESG 折价「在基本面估值之上再打一次折扣」（框架行 436），而宏观调整的是 **PEG 合理区间**；两者都作用于「档位」，先后顺序会影响结论。

- **推荐 C-1（推荐）**：**先宏观 → 后 ESG**：①用宏观 `peg_interval` 替换判定区间 → 得「宏观校准后档位」；②再施加 ESG 折价（PEG 类等价于**合理上限下调至约 1.0**，见框架行 429；DCF 类等价于 **`--r` 上调 `discount_rate_adj_bps`** 后重算）→ 得**最终档位**；③**两级结论都须在报告中留痕**（校准前 / 校准后 / 折价后）。
- 备选 C-2：ESG 在前（先按行业风险折价估值，再叠加宏观区间）。
- 备选 C-3：二者**分别独立呈现**，不合并为最终档位，由下游自行叠加。

### §9.D `PSG` 的处理（中期链主锚 → GARP 是否保留）

**问题**：既有骨架在爆发期以 **PSG** 为主锚；框架第4步**未列 PSG**，高研发/未盈利型的主锚为 **PS / EV/Sales + Rule of 40**。

- **推荐 D-1（推荐）**：**PSG 不作为本技能主锚，也不引用其档位口径**（列为口径隔离禁用词之一）；仅在报告中作为**说明性参考**时可提及数值，**不参与档位判定**。
- 备选 D-2：**完全禁用 PSG**（含数值引用）。
- 备选 D-3：保留 PSG 为高研发型的**辅助**工具之一。

### §9.E 研发管线 NPV 缺工具的处置

**问题**：框架行 385 将「研发管线 NPV」列为未盈利科技型的辅助工具，**当前无对应工具**。

- **推荐 E-1（推荐）**：**不新增工具**（§7.3 明确「不建独立聚合器」，且 P4-5 不含工具开发任务），按**定性 + 数据缺口标注**处理（列在研项目 / 里程碑 / 预计商业化年份），并作为**待上报事项**归「工具侧补丁 或 P4-23 文档侧」。
- 备选 E-2：在 `in_research_scan.py`（P3-8 邻近）基础上**扩展**一个 NPV 粗算子命令（**超出 P4-5 范围**，须另立任务）。
- 备选 E-3：用 `three-scenario` 的三情景估值**替代**研发管线 NPV。

### §9.F 报告路径与「估值可用方法清单」的出口形态

**问题**：本技能被 P4-3 引用为「可用方法清单（PE/PEG/PS/EV-Sales/DCF/可比公司）」的提供方（P4-3 `SKILL.md` 行 150）。

- **推荐 F-1（推荐）**：报告写入 `reports/{公司名}/{公司名}-garp-valuation-{YYYYMMDD}.md`（与 `garp-management` 同构），**不新建 `reports/valuation/` 目录**（避免与中期链目录混淆）；方法清单以 `SKILL.md` 内**固定小节**形式提供，供 P4-3 直接引用。
- 备选 F-2：沿用既有骨架的 `reports/valuation/` 目录，文件名加 `-garp-` 前缀。
- 备选 F-3：报告直接落在 `reports/{公司名}/` 根下，不加技能名中缀。
