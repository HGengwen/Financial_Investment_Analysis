### 2.1 Edit 静默失败事件的实测捕获与修复（**本任务真实发生的状态回写失败**）

**事件**：阶段四 §4.7「文档同步」时，对 `.trae/skills/tools-scripts/garp-geo-policy-tools.md` 的 `Edit` **返回成功并回显了正确的新内容（含 `1.2.0` / `两种形态现均可用`），但磁盘文件未变**——mtime 停留在 `2026-09-19 14:25:32`、bytes 停留在 `8766`，磁盘内容仍含旧句「`scan` 子命令仅支持 `python -m …`」「工具侧修复转 P5-2，本处只登记规避形态」，版本行仍为 `1.1.0`。

**同时发现的**部分落盘：`garp-governance-tools.md` 的正文（`P5-2 §4.4 已修复`）**已**落盘，但**版本行仍为 `1.1.0`** —— 即同批 4.7 同步中，一份文档「正文落盘、版本行漏改」，另一份「完全未落盘」。

**捕获方式**：`[System.IO.File]::ReadAllText` + `Contains` 字节级断言（**未使用 `Read` 工具视图**，因其与磁盘不一致）→ 断言 `1.2.0` / `两种形态现均可用` 返回 `False`，据此判定未落盘。

**修复**：改用 `[System.IO.File]::WriteAllText`（UTF-8 无 BOM，保持 LF）确定性重写；重写后逐锚点 `Contains` 复核 —— `1.2.0` = True / `两种形态现均可用` = True / `撤销 1.1.0` = True / 旧句残留 = False；治理文档版本行改后 `1.2.0` = True。修复后字节：geo `9102 B @ 17:50:02`、gov `8464 B @ 17:49:16`。

**意义**：这是详细计划 §0.5「状态回写检测」条款的**第二次实战验证**（P5-1 已发生一次）。若仅依赖 `Edit` 的返回结果或 `Read` 视图，将误判为「已交付」，而磁盘实为旧版——**且会造成「文档说已修复、正文却仍写不可用」的自相矛盾交付**。本项目后续交付一律以 `[System.IO.File]::ReadAllText` 的字节级断言为准。
