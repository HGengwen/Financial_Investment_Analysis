## 0. 结论摘要（TL;DR）

## 1. 目标与范围

### 1.1 目标

1. **全链走通**：以 1 只标杆股为标的，依序执行 `garp-investment-checklist` → `garp-valuation` → `garp-exit` 三技能，产出**三份符合各自报告模板的样例报告**，落盘 `reports/{公司名}/`。
2. **契约验证**：验证三技能之间**上游产物 → 下游输入**的转接字段**逐项可得、无断链、无口径冲突**（即 checklist 的「待估值校验」标记能被 valuation 消费，valuation 的「最终估值档位」能被 exit 的五级估值判断消费）。

## 3. 全链契约（三技能如何「咬合」与「转接」）

> **本节是本方案的核心**：证明 `<S1 checklist → S2 valuation → S3 exit>` 是一条**可执行、字段可得、口径自洽**的链，而非三份孤立文档。

### 3.1 链式转接图

```
garp-investment-checklist (S1)
  ├─ 产出：reports/{公司}/{公司}-garp-checklist-{YYYYMMDD}.md
  ├─ 七步「收口输出与下游转接」（SKILL.md L234~243）：
  │    「可建仓」（全部达标）→ 转 garp-valuation
  │    建仓前置约束：引用 garp-macro 现金下限/单只上限；卖出纪律转 garp-exit
  └─ 输出「待估值校验」标记
        │
        ▼
garp-valuation (S2)
  ├─ 产出：reports/{公司}/{公司}-garp-valuation-{YYYYMMDD}.md（九段式，SKILL.md L474~546）
  ├─ 消费 S1：公司类型候选、`garp-investment-checklist` 报告（P4-3）支撑类型判定
  └─ 报告模板「九、下游转接与跟踪清单」（L536~544）：
       「估值档位 → garp-exit（P4-6）」作为「估值判断」级输入
        │
        ▼
garp-exit (S3)
  ├─ 产出：reports/{公司}/{公司}-garp-exit-{YYYYMMDD}.md（八段式，SKILL.md L486~565）
  ├─ 消费 S2：读 reports/{标的}/{标的}-garp-valuation-{YYYYMMDD}.md 取「估值档位」（L587）
  └─ 一级~五级检查；五级估值判断读 S2 档位 + 市场情绪信号
```

### 3.2 三处关键转接字段（必须逐项可得的硬契约）

| 转接点 | 上游产物字段 | 下游消费字段 | 契约强度 |
| --- | --- | --- | --- |
| S1 → S2 | 「三档结论 = 可建仓」 | 「待估值校验」标记 → S2 判断是否进入估值 | ✅ 报告显式字段 |
| S1 → S2 | 财务初筛五门槛 / 五大支柱证据 | S2「公司类型判定」依据（营收增速/净利率/研发强度/现金流/上市年限） | ✅ 字段对齐 |
| S1 → S2 | 建仓前置约束（`garp-macro` cash_floor/single_cap） | S2 报告模板「五、宏观叠加」透传 | ✅ 透传字段 |
| S2 → S3 | **「最终估值档位」（显著低估…严重透支）** | S3 五级估值判断输入（`GX-` 读取 valuation 报告） | ✅ **链路脊梁** |
| S2 → S3 | 主锚工具 + PEG / 一致预期增速 | S3 五级（调整后 PEG > 1.5 / > 2 触发） | ✅ 数值可用 |
| S2 → S3 | `cash_floor` / `single_cap` / `position_cap_after`（透传） | S3 转接至 `garp-portfolio-review` | ✅ 透传（本链不消费仓位数值） |

> **缺口提示**：`garp-exit` 的「第二步 装配输入」还消费 `-garp-thesis.md`（`garp-thesis-tracker` P4-7 产出）。**P4-7 已交付**（Phase 4 完成门禁 L185「✅ 完成门禁已通过」），但其 `-garp-thesis.md` 是否在本任务虚构生成，**列入开工门禁 D 决策**；无论决策如何，`garp-exit` 报告须如实标注论文输入来源状态（真实论文 / 声明式降级）。

## 5. `report_audit.py` 准出工作流（实测口径）

### 5.1 三步工作流（实测接口，2026-09-19）

```bash
# Step 1 — 提取数据点并随机抽样（默认 15%，可指定种子复现）
F:/Anaconda3/envs/Python_3_12_3/python.exe tools/common/report_audit.py extract \
    --report reports/新易盛/新易盛-garp-valuation-{YYYYMMDD}.md \
    --ratio 0.15 --seed 42 --output-json > 抽检清单.json

# Step 2 — 逐点独立取数，回填 fetched_value / fetched_source / fetched_value2 / fetched_source2

# Step 3 — 输入核验结果，输出准出/打回判决
F:/Anaconda3/envs/Python_3_12_3/python.exe tools/common/report_audit.py verdict \
    --results "$(Get-Content 抽检清单.json -Raw)" --report "新易盛-garp-valuation-{YYYYMMDD}"
```

**实测参数表**：

| 子命令 | 参数 | 语义 |
| --- | --- | --- |
| `extract` | `--report` | 报告 Markdown 路径（必填） |
| | `--ratio` | 抽样比例，**默认 0.15** |
| | `--seed` | 随机种子（**用于复现同一批样本**，本任务必填以保证可复现） |
| | `--dry-run` | 只打印不输出 JSON |
| | `--output-json` | 仅输出纯 JSON 到 stdout（供管道解析） |
| `verdict` | `--results` | JSON 数组，含 `fetched_value` 等字段 |
| | `--report` | 报告名称（仅显示用） |
| | `--output-json` | 判决结果以 JSON 输出 |

### 5.2 判定规则（源码实测，`tools/common/report_audit.py`）

- **容差**：`_TOLERANCE = 0.01`（**1%**），偏差 `_pct_diff(reported, fetched) <= 0.01` 判通过。
- **双源规则**：`pass1 = diff1 <= TOL`；`pass2 = (diff2 is None) or (diff2 <= TOL)`；**两者皆过方通过**。
- **未提供核验值**：`fetched_value is None` → 该点**跳过，不计入通过/失败**（故「跳过」不可用作规避手段，须在记录中如实统计跳过数）。
- **判决与退出码**：全通过 → `【准出】` + `verdict='PASS'` + **退出码 0**；存在不通过 → `【打回】` + `verdict='FAIL'` + **退出码 1**。

### 5.3 本任务的审计执行约定

| 项 | 约定 | 理由 |
| --- | --- | --- |
| 审计对象 | **三份报告各审一次**（checklist / valuation / exit） | 上游要求「全链输出符合框架口径」 |
| 抽样比例 | **0.15（默认）** | 与工具默认一致，避免人为调整 |
| 随机种子 | **固定（如 `--seed 42`）** | 可复现；记录中须写明种子 |
| 取数独立性 | `fetched_source` **不得**填报告自身或同源 | 防「自证循环」，这是准出判决有效性的前提 |
| 跳过点统计 | 记录 `跳过数 / 抽检数 / 通过数 / 不通过数` | 透明披露，防止以「跳过」掩盖缺口 |
| 结果留痕 | 抽检清单 JSON + 判决 JSON 一并落 `upgrade1.0/P5-2/` | 交付件 4 证据 |

> **风险 R2 提示**：若某报告抽检命中「无法独立取数」的点（如内部推算值），**处置方式为在报告中标注为「推算值/低置信度」并在 `verdict` 中跳过 + 记录说明**，**不得**填入编造值。
