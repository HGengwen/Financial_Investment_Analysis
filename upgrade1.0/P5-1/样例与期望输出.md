## §4 关键口径样例（防「断言过松」）

以下三例为**刻意对齐实现细节**的边界断言，用于证明测试确实在约束行为而非「只求通过」：

### 4.1 C1 合法 g 组合的口径依据

`CURRENCY_BANDS["CNY"]` 的 `g_max = 0.02`（基准档），乐观档另放宽 1pct 至 `0.03`。故 C1 合法组合为：

```text
G_OK = "0.005,0.020,0.030"    # 基准 0.020 <= 0.02 ✓；max 0.030 <= 0.03 ✓
```

反例：`"0.015,0.030,0.040"`（即 PRESET 的人民币「平移前」原值）**会被 C1 打回**——这正是 `--g-shift -0.01` 存在的意义，测试以 `test_c1_g_above_max_fails` 固化了这一纪律。

### 4.2 `warn_spread` 边界

```python
tv.warn_spread(0.05) == ""     # 0.05 < 0.05 为 False → 不打标
tv.warn_spread(0.049) == "⚠窄"
```

### 4.3 `rescale_irr` 的 `k` 非线性

`k` 在复利项**内**扣除，故不是纯加性项：

```text
IRR_new = (1 + IRR_base - k) x (PE_new/PE_base)^(1/years) - 1 + k
差异（k=0.03 vs k=0） = k x (1 - (PE_new/PE_base)^(1/years))
```

当 `PE_new > PE_base` 时该差异为**负**（k 摊薄 PE 驱动的资本利得），测试以 `test_k_dampens_pe_driven_gain` 断言该精确恒等式。

> **修正记录**：初版该用例误按「纯加性」断言 `with_k - no_k == 0.03`，实测差 `-0.000677`，据此改为精确恒等式——该失败**暴露的是测试假设错误，非被测代码缺陷**（符合 Out of Scope「只登记不修」纪律，无需修改 `tools/`）。
