### 3.5 skipped 62 → 63（+1）的归因与披露（**须提请用户裁定**）

**事实**：`skipped` 由基线 62 变为 63，**超出验收 8.6 的「≤62」绝对值上限 1 项**。

**归因**：该 +1 来自**既有网络依赖用例**，与 P5-1 改动无因果关系。三条证据：

| # | 证据 | 说明 |
| --- | --- | --- |
| **a** | **新增文件零网络依赖** | `test_terminal_value.py` 59 用例全部为纯计算 / 纯判定，**2 次单独复跑均 `59 passed / 0 skipped`**；其设计上不导入 akshare / yfinance / 搜索工具 |
| **b** | **既有用例集合未变** | 收集总数 Δ = **+59** = 新增用例数（见 3.2），既有 38 文件无增删改；`pytest.ini` 未改变收集结果 |
| **c** | **网络依赖用例的状态天然可变** | 实测网络依赖子集中，`tests/us_stock/test_stock_info.py` 有 **5** 个、`test_stock_quote.py` 有 **3** 个用例因「网络不可用」skip；`test_commodity_price_integration.py` 有 **3** 个因「yfinance 不可用」skip。这些用例在网络可达时**通过**、不可达时**skip**，`pass↔skip` 随网络条件翻转 |

**机制**：`tests/conftest.py` monkeypatch `socket.socket.settimeout`（拒绝清零，兜底 20s）→ 受限网络下网络依赖用例抛 `TimeoutError/SSLError` → 由各文件既有的 `except Exception -> skipTest` 捕获并跳过。**skip 是防挂起机制的正常产物，非缺陷**；其**具体条数随网络抖动而变**。

**对验收 8.6 的判定**：

| 维度 | 判定 |
| --- | --- |
| **立法意图**（原文括号说明：「**不得因新增用例引入新的网络依赖 skip**」） | ✅ **达标**——新增 59 用例零网络依赖、0 skip |
| **绝对值**（「skipped ≤ 62」） | ⚠️ **偏差 1**（63 > 62），归因于既有用例的网络抖动 |

**处置**：如实披露，**提请用户在完成门禁裁定**。可选处置：① 判定 8.6 以「意图」为准，通过；② 追加一次全量复跑以观察 skip 是否回落至 62（成本约 17 分钟）；③ 将 8.6 的绝对值上限修正为「≤ 基线 + 环境抖动容差」。
