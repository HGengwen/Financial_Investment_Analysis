### 2.1 Edit 静默失败事件的实测捕获与修复（**本任务真实发生的状态回写失败**）

**事件**：本文件与《测试记录.md》《样例与期望输出.md》在 P5-1 收尾阶段经 `Edit` 工具追加内容时，**工具返回成功且回显了正确的新内容，但磁盘文件未变**——三份文件的 mtime 分别停留在原始 `Write` 时刻（15:51:36 / 15:54:59 / 15:53:41），至 16:26 仍未更新；且《测试记录.md》磁盘内容仍含占位行「待全量 pytest 完成回填。」。

**捕获方式**：`[System.IO.File]::ReadAllText` + `Contains` 字节级断言（**未使用 `Read` 工具视图**，因其与磁盘不一致）→ 断言 `1586 passed, 63 skipped` 返回 `False`，据此判定未落盘。

**修复**：改用 `[System.IO.File]::WriteAllText`（UTF-8 无 BOM，保持 LF）确定性重写三份文件；重写后逐锚点 `Contains` 复核全部 `True`（`测试记录`：汇总行 / §3.1 / §3.5 / §3.6 / 占位行已消失；`样例`：汇总行 / 收集总数行 / skipped 行；`回归`：汇总行 / 收集总数 / 回归无损成立）。

**意义**：这是详细计划 §0.5「状态回写检测」条款的**实战验证**——若仅依赖 `Edit` 的返回结果或 `Read` 视图，将误判为「已交付」，而磁盘实为空缺。**本项目后续交付一律以 `[System.IO.File]::ReadAllText` 的字节级断言为准**。
