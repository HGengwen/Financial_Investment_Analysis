## 0. 结论摘要（TL;DR）

本任务在 P3-1/P3-2 已交付的 `geo_policy_screen.py` 上**新增 `scan` 子命令**，把框架第 0 步 0.1（地缘政治风险）与 0.2（政策与国字号基金）的「检索」环节下沉为可执行命令，禁止 LLM 心算。

- **输入**：`--industry`（地缘风险维度检索对象，行业/领域名）+ `--fund`（政策基金维度检索对象，行业/领域/基金名），二者**至少填一个、可同时填**。
- **输出**：JSON，强制含 `data_as_of`（数据截止日期）、`retrieved_at`（检索执行时间）、`snapshot_example`（来源快照示例）、`degraded`（降级标注），另附 `structured_source`（akshare 结构化源探测结论）与 `disclaimer`/`note`。
- **核心口径（唯一权威）**：框架第 0 步 0.1「评估某行业前须先检索该行业是否已被卷入地缘政治冲突/管制清单」+ 0.2「每次评估更新基金名称/规模/投向实时数据，基金名单仅为格式示例非当前事实」。
- **关键设计原则**：`scan` **只检索、只呈现来源快照，不判定风险等级/基金力度、不输出 `screen` 的档位结论**；「akshare 结构化优先 + 搜索五工具回退」在本版本落地为「探测无结构化接口 → 直接走搜索工具并显式标注 `structured_source`」，不硬编 akshare 假接口；实时检索失败必须降级并标注 `degraded`。
- **复用与回归约束**：复用 P3-1/P3-2 文件骨架（`argparse` 子命令、`json.dumps(ensure_ascii=False, indent=2)`、Google 风格 docstring、模块导入自检）；**不改动** `screen`/`localize`/`examples` 三个既有子命令及任何既有常量、`dataclass`。

## 1. 目标与范围

### 1.1 目标

在 `tools/specialized/geo_policy_screen.py` 上新增：

1. **`scan --industry`（地缘风险检索维度）**：检索目标行业/领域当前是否被卷入「制裁清单 / 出口管制 / 风险行业」，返回来源快照。
2. **`scan --fund`（政策基金检索维度）**：检索目标行业/领域的政策基金「名录 + 注资额度」（基金总规模、单项目投资额、占项目总投资比例），返回来源快照。
3. **强制数据时效字段**：每次输出 `data_as_of` + `retrieved_at` + `snapshot_example`，落实框架「数据截止日期 + 快照示例」强制标注。
4. **失败降级标注**：实时检索失败时回退旧缓存或标空，并在 `degraded`/`degraded_reason` 中显式标注。

### 1.2 包含范围

- `scan` 子命令与核心函数 `scan()`（含检索编排、字段归一化、快照抽取）。
- 输入校验（`--industry`/`--fund` 至少填一个；非空校验；非法即 fail-fast 返回非零）。
- akshare 结构化源**探测**（`_probe_structured_sources()`），并输出 `structured_source` 探测结论。
- 搜索工具链封装（`anysearch` + `doubao_search` 为核心，`exa_search` 为可选第三级回退）。
- 检索结果字段归一化（不同工具返回结构统一为固定 source 结构）。
- 缓存兜底（`data/geo_policy/`，仅失败降级时读，默认实时检索）。
- 单元测试（mock 搜索依赖，覆盖成功/降级/失败/空结果/非法输入/JSON 可解析 + P3-1/P3-2 回归不破坏）。

### 1.3 不包含范围（明确排除，防范围蔓延）

- **不含**任何「风险等级判定 / 基金力度判定」——`scan` 不下结论，不下沉 `screen` 的三维档位判定。
- **不含**对搜索结果真伪的自动研判、事实核查或去重聚类（仅归一化 + 快照呈现）。
- **不含** `tavily_search` / `web_search` 两个 async MCP 客户端的接入（见 §4，本版本排除，留后续）。
- **不含**「美股深度研究」的完整工具链路由（`exa_search` 仅作第三级可选回退，不新增 `--market` 参数、不做多市场自动路由）。
- **不含**把框架 0.1 历史风险行业表、0.2 示例基金名单当作 `scan` 的输出或结论（仅可在检索关键词启发上参考，正文标注为示例）。
- **不改动** P3-1/P3-2 已交付的 `screen`/`localize`/`examples` 子命令、`GeoPolicyResult`/`LocalizationResult`/`CohortExample` 及所有既有常量与自检函数。
- **不改动** `.trae/skills/` 下既有技能与既有其它工具签名。

## 2. 关键量化口径（唯一权威 = 框架第 0 步）

> 以下取自《中长期价值成长（GARP）投资框架》第 0 步（行 86~162），是唯一权威。任何实现与本文档/总计划/详细计划不一致时，**以框架正文为准**。

### 2.1 地缘政治风险检索（框架 0.1）

> **关键操作纪律**：评估某个行业前，须先检索"该行业当前是否已被卷入地缘政治冲突/管制清单"，而非默认"上表之外的行业就无风险"。逆全球化是扩散性的长期变量，风险行业边界会持续外扩。

- 检索对象 = **行业/领域当前是否命中制裁清单、出口管制、风险行业**，不是复述历史风险行业表。
- 框架 0.1 给出的五类「已明显暴露地缘政治风险的行业」（半导体与高端制造、生物制药与创新药、矿产资源、稀土、能源与航运）标注为「示例，会随时间变化」，`scan` **不将其固化为结论**。
- 0.1 四类逆全球化信号（贸易壁垒常态化 / 产业链区域化 / 技术脱钩 / 资本与数据流动收紧）与三类风险形态（技术大国竞争 / 国家经济民族主义 / 地区冲突战争）作为检索关键词的启发参考，不作为输出断言。

### 2.2 政策基金检索（框架 0.2）

> 评估的核心不是"记住某一期基金名单"，而是掌握判断"政策资本力度"的方法。……每次评估时更新"基金名称、规模、投向"的实时数据，剔除已到期、已转向或规模缩水的基金，补充新设立的基金。

- 检索对象 = **基金名称 + 规模 + 投向 的实时数据**，重点关注「基金总规模、单项目投资额、占项目总投资比例」三个额度口径。
- 框架 0.2 末尾的基金名单（国家人工智能产业投资基金 / 大基金三期 / 国家制造业转型升级基金 / 工业母机产业投资基金）已明确标注「示例（仅作格式示范，非当前事实）」，`scan` **不将其作为当前事实输出**。

### 2.3 数据时效与「不写硬结论」纪律（本任务的强制契约）

> 总计划 P3-2 验收标准：输出带"数据截止日期 + 快照示例"标注，强制最终以实时检索为准。

- **强制字段**：每次输出 `data_as_of`（数据截止日期）+ `retrieved_at`（检索执行时间）+ `snapshot_example`（来源快照示例）。
- **不写硬结论**：`scan` 只输出「检索到的来源 + 来源片段」，**不输出**「该行业属于高风险/低风险」「该基金力度强/弱」等判定；这类判定交由 `screen`（P3-1）与后续人工研判。
- **失败必降级**：首选实时检索失败 → 回退工具或旧缓存，且在 `degraded` + `degraded_reason` 标注原因；全部失败 → `retrieval_status="failed"` + 空来源 + 明确 `degraded=true`。

### 2.4 与 P3-1/P3-2 的分工边界（口径隔离）

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 三维交叉矩阵六行判定 / 赛道两分法 | P3-1 `screen` | 输入档位 → 输出结论 |
| 国产化率四档分层 / 半导体示例 | P3-2 `localize` / `examples` | 输入数值 → 输出档位 |
| 制裁清单/出口管制/风险行业/政策基金**检索** | **P3-3 `scan`（本任务）** | 输入行业/基金 → 输出来源快照，**不判档** |
| 维度叠用与最终研判 | Phase 4 `garp-geo-policy` 技能 | 编排 `scan` 取数 + `screen` 定档，本工具不越权 |

## 3. 输入/输出签名

### 3.1 CLI 子命令

```text
# 仅检索地缘风险（制裁清单/出口管制/风险行业）
python tools/specialized/geo_policy_screen.py scan --industry 半导体

# 仅检索政策基金（基金名录 + 注资额度）
python tools/specialized/geo_policy_screen.py scan --fund 半导体设备

# 同时检索两个维度
python tools/specialized/geo_policy_screen.py scan --industry 半导体 --fund 半导体设备
```

- 子命令 `scan`：与 P3-1 `screen`、P3-2 `localize`/`examples` 命名不冲突。
- `--industry`：可选；非空自由文本（行业/领域名），触发「地缘风险」维度检索。
- `--fund`：可选；非空自由文本（行业/领域/基金名），触发「政策基金」维度检索。
- **约束**：`--industry` 与 `--fund` 至少填其一；两者可同时填（一次输出两个维度，维度顺序固定为 industry 在前、fund 在后）。
- 无 `--as-of`/`--basis`：本命令的数据截止日期由检索执行时间自动生成（`data_as_of`/`retrieved_at`），不接受外部传入以免伪造。

### 3.2 输入校验（fail-fast 护栏）

| 校验项 | 规则 | 行为 |
| --- | --- | --- |
| `--industry` | 若提供，`strip()` 后须非空 | 空 → 报错返回非零 |
| `--fund` | 若提供，`strip()` 后须非空 | 空 → 报错返回非零 |
| 互斥约束 | `--industry` 与 `--fund` 至少填一个 | 二者皆缺 → 报错返回非零 |
| 非法值 | 任一非字符串 / 纯空白 | 报错返回非零，拒绝执行 |

> 与 P3-1/P3-2 一致：非法输入拒绝（fail-fast），不降级、不猜。

| 字段 | 类型 | 说明 |

## 5. 实现设计（五步，与详细计划对齐）

### 5.1 可结构化接口确认（实现步骤①）

- 新增 `_probe_structured_sources() -> Dict[str, Any]`，返回 `{"probed": True, "available": False, "note": "……"}`。
- **当前实现结论**：经仓库盘点，akshare 现有接口中**未发现**针对「制裁清单 / 出口管制 / 风险行业 / 政策基金注资额度」的直接结构化接口。
- **落地方式**：不硬编 akshare 假接口；`_probe_structured_sources()` 探测返回 `available=false`，`scan` 据此直接走搜索工具，并在输出 `structured_source.note` 中如实标注「未发现稳定结构化接口，已用搜索工具实时检索」。未来若 akshare 新增对应接口，仅需在探测函数中扩展，不破坏既有逻辑。

### 5.2 检索编排（实现步骤②）

- 新增 `_run_search(query_terms, dimension, search_inject)` 编排函数，prepared 关键词、按工具链顺序调用并归一化。
- 工具链（固定，默认 A股/国内口径）：
  1. `anysearch`（首选，A股投研首选）——每维度对每个 `query_terms` 逐条检索；
  2. `doubao_search`（回退，实时资讯/权威首选）——首选失败/空时回退；
  3. `exa_search`（第三级可选回退，仅地缘风险维度尝试，需 `EXA_API_KEY`）——无 key 或失败则跳过并记录。
- 关键词模板（框架启发，非结论）：
  - 地缘风险：`"{industry} 实体清单 出口管制"`、`"{industry} 制裁 管制清单"`、`"{industry} 风险行业 逆全球化"`；
  - 政策基金：`"{industry_or_fund} 国家产业基金 注资 规模"`、`"{industry_or_fund} 大基金 专项子基金 投资额"`。
- **依赖注入**：编排函数接受可注入的 `search_inject`（默认映射到真实工具），便于单元测试 mock，避免测试触发真网络。

### 5.3 快照/截止日期强制字段（实现步骤③）

- 新增 `scan(industry, fund, search_inject=None, now=None)` 核心函数，返回 dict（异构动态结构，故不用 `dataclass`，直接返回 dict；序列化由 CLI 统一 `json.dumps`）。
- `data_as_of` = `now.date().isoformat()`；`retrieved_at` = `now.isoformat(timespec="seconds")`（`now` 可注入，测试可控）。
- 字段归一化：把 anysearch（title/url/snippet/content）、doubao（title/url/summary/snippet/publish_time/site_name）、exa（title/url/published_date/content）统一映射为 §3.4 六字段 source。
- `snapshot_example`：从各维度 `sources` 每维度取至多 2 条作为示例快照（含维度标识），全失败为空数组。
- `degraded` 判定规则（精确）：
  | 情形 | `degraded` | `degraded_reason` | 维度 `retrieval_status` |
  | --- | --- | --- | --- |
  | 首选 `anysearch` 成功且非空 | `false` | `null` | `ok` |
  | 首选失败/空 → `doubao`/`exa` 成功且非空 | `true` | 记录「首选工具失败/空，已回退 {工具}」 | `ok` 或 `partial` |
  | 实时工具全失败/空 → 命中缓存 | `true` | 记录「实时检索失败，回退旧缓存（cache_as_of=…）」 | `ok`（来源标记 `source_tool=cache`） |
  | 全失败且无缓存 | `true` | 记录「实时检索与缓存均不可用」 | `failed`（`sources=[]`） |
- 缓存兜底（复用 P2-2 模式）：
  - 目录 `data/geo_policy/`；文件命名 `scan_{dimension}_{安全hash}.json`；
  - **默认实时检索不读缓存**；仅在实时工具全失败时读旧缓存兜底，且标注 `source_tool=cache` + 缓存时间；
  - TTL 短窗（默认 24h，超出视为无缓存）。不新增全局配置项，硬编码常量 `SCAN_CACHE_TTL_HOURS = 24`。

### 5.4 样例（实现步骤④）

- 新增 `cmd_scan(args)`，打印 §3.3 顶层 JSON。
- 样例与期望输出落 `upgrade1.0/P3-3/样例与期望输出.md`，覆盖：
  1. `scan --industry 半导体`（success 场景，mock 示例来源）；

## 7. 风险与依赖

| 类型 | 内容 | 应对 |

| 依赖风险 | `anysearch`/`doubao_search` 需网络 + `.env` 凭证；`exa_search` 需 `EXA_API_KEY` | 依赖注入 mock 使单测离线可跑；运行时 `exa_search` 无 key 捕获 `ValueError` 跳过 |

| 并发/异步风险 | `tavily`/`web` 为 async MCP | 本版本明确不接入（§1.3），避免跨异步边界；仅用同步 `anysearch`/`doubao_search` 与可选 `exa_search` |
| 范围蔓延 | 误把多市场路由、事实核查、结论研判塞入 | §1.3 明确排除，门禁核对 |
| 回归风险 | 扩展文件破坏 P3-1/P3-2 | 只新增常量/函数/子命令，不改既有符号；测试追加而非替换 |
