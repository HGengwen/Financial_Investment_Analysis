## 3. 关键测试设计

### 3.1 依赖注入（离线可测）

`scan(industry, fund, search_inject=None, now=None)` 接受可注入的
`search_inject`（工具名到可调用对象的映射）与 `now`，
测试中注入 `lambda`/空函数，**完全离线、确定性**，不触发真实网络。

### 3.2 缓存目录隔离（模块级）

为避免 `scan` 用例污染真实 `data/geo_policy/` 目录并保证用例互不串扰，
测试文件使用 **模块级 setUpModule/tearDownModule** 将模块常量
`SCAN_CACHE_DIR` 整体重定向到 `tempfile.TemporaryDirectory()`：

```python
_CACHE_TMP = None
_PATCHER = None

def setUpModule():
    global _CACHE_TMP, _PATCHER
    _CACHE_TMP = tempfile.TemporaryDirectory()
    _PATCHER = mock.patch(
        "tools.specialized.geo_policy_screen.SCAN_CACHE_DIR",
        Path(_CACHE_TMP.name))
    _PATCHER.start()

def tearDownModule():
    global _CACHE_TMP, _PATCHER
    if _PATCHER is not None:
        _PATCHER.stop()
        _PATCHER = None
    if _CACHE_TMP is not None:
        _CACHE_TMP.cleanup()
        _CACHE_TMP = None
```

同时在 `TestScanSearchBranches.setUp` 中对每个用例再做一次独立的临时目录隔离
并 `addCleanup`，确保「全失败空缓存」与「全失败命中缓存」两条路径互不串扰。

## 4. 曾出现的测试问题与修复

### 4.1 缓存污染导致「全失败空缓存」误判

- **现象**：`test_all_failed_empty_cache` 期望 `retrieval_status=failed`，实际得到 `ok`。
- **根因**：`scan` 的首选成功分支会把结果写入 `data/geo_policy/` 真实缓存；
  后续「全失败」用例读到前序写下的旧缓存，落到「命中缓存」分支而非「空来源」。
- **修复**：
  1. 先在 `TestScanSearchBranches.setUp` 内临时重定向 `SCAN_CACHE_DIR`；
  2. 随后提升为**模块级 setUpModule/tearDownModule 统一隔离**，
     使整个测试模块的 `scan` 缓存均写入临时目录，测试结束自动清理。
- **验证**：复跑后 59 passed，且 `data/geo_policy/` 真实目录保持为空（无污染）。

### 4.2 CLI 用例避免网络依赖

- **调整**：P3-3 不带真实网络依赖的 `scan` 成功路径 CLI 用例，
  只保留「`scan` 双缺参数 → 退出码 1」的离线用例；JSON 可解析改由
  `TestScanJSONSerialization` 用 mock 注入覆盖，避免单测受凭证/网络/限流影响。
