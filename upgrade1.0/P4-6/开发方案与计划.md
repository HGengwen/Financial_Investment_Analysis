## 1. 目标与范围

### 1.1 目标

把框架**第三部分「持仓管理与操作纪律」的卖出三节**（行 474~538）落成一个可独立调用的 GARP 独立档技能，达成三件事：

1. **优先级固化**：把「诚信否决 > 硬止损 > 逻辑止损 > 产业景气判断 > 估值判断」固化为**逐级检查、命中即停、禁止跳过一级**的硬编码顺序（框架行 475 声明与金字塔、备忘卡「完全一一对应」）；
2. **算数全部外置**：ATR 止损价一律由 `momentum.stop_price()`（内部调用 `atr()`）输出，估值档位一律取 `garp-valuation`（P4-5）与 `financial_rigor.py` 的结果，**技能层零心算、零自造阈值**；
3. **补齐两类框架特有结构**：把「暂时性困难 vs 永久性衰退」六维清单（行 508~520）与「补充机制（不占优先级）」（行 502~505）做成**可留痕的检查步骤**，使「加仓 / 持有 / 清仓」的深跌处置有据可依。

## 2. 关键量化口径（唯一权威 = 框架第三部分行 443~538 + 第五部分·二行 651~665 + 第六部分行 751~822）

> **引用不重复定义原则**：本节只列「本技能必须固定下来、可直接执行」的口径与阈值；定义原文一律指向框架行号，不复制粘贴整段论述。

### 2.1 五级卖出优先级映射表（硬编码，框架行 474~500 逐格落地）

| 级别 | 触发条件（框架原文阈值） | 决策 | 思想来源 |
| --- | --- | --- | --- |
| **一级 诚信否决** | 管理层诚信问题暴露、财务造假实锤、监管立案 | **立即清仓**，不看估值与趋势，不找任何理由 | 费雪 |
| **二级 硬止损** | 单笔亏损达 **8%~10%** 且无明确基本面反转信号 | **止损离场** | 欧奈尔 |
| **三级 逻辑止损** | ① 连续 **2 个季度**业绩低于预期**且**产业景气未改善；② 财务出现不可逆恶化（应收账款暴增 / 存货高企 / 现金流持续为负）；③ 龙头地位被颠覆、科研转化大幅低于预期；④ 管理层或科研转化评分**跌破 10 分**（非诚信事项） | ①②③ **减仓或清仓**；④ **降观察仓 / 减仓** | 林奇 + 郑希 |
| **四级 产业景气判断** | ① 渗透率 / ROE 出现拐点，但**景气尚可、仅节奏放缓**（如进入 40%~60% 逐步兑现期）→ 减机动仓、降仓位；② **增速归零 / 转负**（增长见顶）→ **升级为逻辑恶化、清仓**（独立触发，与渗透率位置无关） | ① 减机动仓；② **清仓** | 李进 + 郑希 |
| **五级 估值判断** | ① 调整后 PEG **> 1.5** → 减机动仓；**> 2** 为严重透支 → 加速清机动仓；② 市场情绪极度狂热（两融余额骤增 / 换手率持续高位 / 成交额创新高 / 新开户激增等**多信号共振**）→ 减机动仓，多项共振时加速清机动仓 | **底仓不动，机动仓调整** | 林奇 |

**硬编码执行规则**：

1. 检查顺序**固定**为 一级 → 二级 → 三级 → 四级 → 五级；
2. **命中即停**：输出命中的**最高**级别及对应动作，**不得**继续检查更低级别，**不得**被低优先级覆盖；
3. **禁止跳过一级**：任何输入都必须先过诚信否决检查；
4. **一票否决的语境边界**（框架行 663）：本技能的一级仅针对**持仓后**的清仓信号；买入前闸门（0.3 三维矩阵回避 / 能力圈自检 / ROIC<5% 扩产）**不进入本表**，命中即在建仓前放弃；
5. **降档不得升档**：低优先级结论不得覆盖高优先级结论；高优先级未触发时才允许向下一级推进。

### 2.2 补充机制（**不占优先级**，框架行 502~505 + 行 798~801）

> 框架在**三处独立位置**明确「补充机制**不占优先级**」：行 502、行 798，以及行 475 的「一一对应」结构声明（备忘卡将补充机制单列于卖出段之外）。故本技能**不**将其并入任一级别。

| 机制 | 触发条件 | 动作 | 频次约束 |
| --- | --- | --- | --- |
| **时间止损** | 持有满 **4 个季度（1 年）**，买入逻辑**仍未兑现** | 减仓至**观察仓**或替换 | — |
| **性价比替换（末位优化）** | 发现其他标的**估值显著更低且产业趋势更强** | 逐步切换（先建新标的底仓、再清旧标的机动仓） | **每季度最多 1 次** |

**适用范围限定（框架行 504、行 800）**：

1. 时间止损**仅针对「逻辑未兑现」的仓位**，与「1~5 年长期持有、逻辑**已兑现**的杰出企业」**不冲突**——前者是**证伪退出**，后者是**价值兑现的耐心等待**；报告中必须区分措辞，不得把杰出企业的时间持有误判为「逻辑未兑现」；
2. 补充机制的执行**不得覆盖**五级中任一已命中级别；
3. 补充机制判定须给出**买入日期**（时间止损）与**候选替换标的的估值与趋势对比证据**（性价比替换），缺证据即标「未判定」。

### 2.3 暂时性困难 vs 永久性衰退六维清单（框架行 508~520 逐格落地）

| 判断维度 | 暂时性困难（**可加仓**） | 永久性衰退（**需清仓**） |
| --- | --- | --- |
| **行业需求** | 需求延迟，但长期趋势未变 | 需求被替代品**永久性**替代 |
| **竞争格局** | 份额短期波动，但优势仍在 | 份额**持续流失**，护城河消失 |
| **财务** | 现金流短期承压，但资产负债表健康 | 现金流**持续为负**，债务恶化 |
| **管理层** | 承认问题，有清晰应对方案 | 推卸责任，频繁更换高管 |
| **研发** | 研发投入维持或增加 | 研发投入**持续削减** |
| **客户** | 客户流失是暂时性的，可挽回 | 核心客户**永久性**转向竞争对手 |

**使用规则（框架行 520）**：

1. 「**暂时性困难**」**且**产业逻辑、科研转化（科技股）、管理层、财务等维度**均未恶化** → 可在**合理估值下限附近加仓**；
2. 「**永久性衰退**」→ **无论盈亏立即清仓**（与一级同为准出动作，不得以「估值便宜」为由延后）；
3. 六维度须**逐条给出证据与数据来源**，**禁止**一句话概括或只挑有利维度；未取证维度标「**未判定**」并计入不确定性；
4. 本清单为**强制触发步骤**的情形：① 自买入价下跌 **> 20%**（框架行 535）；② 已达到最终仓位 50% 以上且逻辑已验证（即已脱离「建仓初期」）而出现深跌。其余情形按需展开。

### 2.4 硬止损与仓位状态分水岭（框架行 528~538）

**「建仓初期」完整定义**（框架行 530，**逐字固化**）：

> 指①持仓 **< 最终仓位的 50%**；**或** ②持仓 **≥ 50%** 但逻辑尚未经 **2~3 个季度财报持续兑现验证**（如右侧一次性建 2/3 后、财报尚未兑现期间）。**两者任一成立**即适用 8%~10% 硬止损，而非仅看「<50%」这一个数字。

| 仓位状态 | 决策规则（框架行 534~536） |
| --- | --- |
| **建仓初期**（持仓 < 最终仓位 50%，**或** ≥50% 但逻辑未验证） | 若下跌超过 **8%~10%**，按欧奈尔规则**止损离场**，保护本金 |
| **底仓已建立且逻辑已验证** | 自买入价下跌 **≤ 20%** 且产业逻辑、科研转化（科技股）、管理层、财务等维度**均未恶化** → 可在**合理估值下限附近加仓**；下跌 **> 20%** → **不自动加仓**，转入 §2.3 六维清单复核，据结果决定加仓 / 持有 / 清仓 |
| **无论何种状态，逻辑被证伪** | **立即清仓**，不存在「越跌越买」 |

**止损分水岭（框架行 538，逐字固化）**：须**同时满足**『① 达到最终仓位的 50%』与『② 逻辑经 2~3 季财报兑现验证』**两个条件**，缺一仍按建仓初期 8%~10% 执行。

> **与组合层「底仓 60%~80%」的区分**（框架行 528 括注）：此处「底仓已建立」指**单只标的**达到最终仓位的 50% 且逻辑已验证，**非**组合层面的 60%~80% 底仓。报告中须显式声明该区分，禁止混用两个「底仓」语义。

### 2.5 ATR 动态止损口径（框架行 469~471、行 536）

| 项 | 口径 |
| --- | --- |
| **计算公式** | 止损价 = **买入价 −（2~3）× ATR(14)** |
| **ATR(14)** | 最近 14 个交易日的平均真实波幅 |
| **TR 定义** | `max(当日最高−当日最低, |当日最高−昨收|, |当日最低−昨收|)` |
| **适用对象** | **中波动 / 高波动**标的（**低波动股不使用 ATR**，一律 8%~10% 硬止损；框架行 472）；三档按**波动刻度 `k`** 判定，见本节「波动分档」 |
| **适用阶段** | **仅**在「底仓已建立**且**逻辑已验证」后使用（框架行 469、行 471） |
| **禁止情形** | 建仓初期（持仓 < 最终仓位 50% **或** 逻辑未验证）**一律**按 8%~10% 硬止损、**不用 ATR** |
| **封顶约束** | ATR 止损价对应的亏损幅度**由 20% 底仓容忍度封顶**——ATR **只能精化跟踪节奏，不能突破 20% 底仓容忍度**（框架行 471）；**封顶后有效止损价 = 买入价 × (1 − 20%)**，报告须与原始 `stop_price`（**未封顶参考值**）**并列呈现** |
| **调用工具** | `tools.common.momentum.stop_price(highs, lows, closes, entry_price, multiplier)`（P1-8）；返回 `{'atr14', 'stop_price', 'stop_pct'}` |
| **低波动豁免** | 波动刻度 `k` **< 8%** → **一律 8%~10% 硬止损**、**不得使用 ATR**（含底仓已建立且逻辑已验证的情形）；依据框架行 472，阈值为**本技能操作化刻度**（`GX-15`） |
| **封顶后动作顺序** | 高波动档 `k` > 20% → 封顶**必然生效** → 触及有效止损价**等于**达到 20% 门槛 → **先跑 §2.3 清单复核，再按清单结论定动作**；**不得**仅凭跌幅直接下卖出结论 |

**波动分档与 `multiplier` 选取（框架行 472 明示规则 + 本技能操作化刻度）**：

| 档位 | 判定（按波动刻度 `k`） | 是否使用 ATR | `multiplier` | 有效止损幅度 | 依据 |
| --- | --- | --- | --- | --- | --- |
| **低波动** | `k` **< 8%** | **否** | — | **8%~10% 硬止损**（底仓路径下亦然） | 框架行 472 明示 |
| **中波动** | **8% ≤ `k` ≤ 20%** | 是 | **2.0** | `k`（封顶未生效） | 框架行 470 区间取下限 |
| **高波动** | `k` **> 20%** | 是 | **2.0~3.0**（波动越高越靠上限，须说明理由） | **20%**（封顶生效） | 框架行 470~472 |

**波动刻度 `k` 取数口径（唯一权威，禁止反推）**：

```python
k = momentum.stop_price(highs, lows, closes, entry_price=买入价, multiplier=2.0)["stop_pct"]
```

- **禁止**用 `round(atr14, 2) × 2 ÷ 买入价` 反推 `k`——实测反推得 **5.54**，工具给 **5.53**（分位差，见「调用形态约束与已知事实」第 4 / 7 条）；
- `k` 为 `None`（数据不足 / 护栏静默降级）→ 按 §3.3 回退 8%~10% 硬止损口径并标注。

**两个 20% 的角色区分（防混用）**：

| 20% 的角色 | 含义 | 适用对象 |
| --- | --- | --- |
| ATR 幅度封顶上限 | ATR 跟踪止损价最多离买入价 20% | 中波动 / 高波动（低波动档不涉及） |
| 底仓容忍度门槛 | 自买入价下跌 >20% → 不自动加仓 + 转 §2.3 清单复核 | **全部档位**（含低波动） |
**调用形态约束与已知事实（2026-09-17 实测核对）**：

1. `momentum.py` **无 CLI / 无 argparse / 无 `__main__`** → 须以**内联 Python 模块调用**方式使用，**不得**在技能层用公式心算；
2. `stop_price()` **仅输出原始止损幅度**，其 docstring 明确「不做 20% 底仓容忍度封顶，也不做 8%~10% 硬止损与仓位状态分档——该类判断由上层编排（**P4-6**）完成」→ **封顶与分档由本技能负责**；
3. `stop_price()` 默认 `multiplier=2.0`（框架取 2~3），`period=14`、`method='wilder'`；报告中须标注实际取用的倍数并说明理由；
4. `atr()` 返回 **2 位小数**；`stop_price()` **用全精度 ATR 计算止损价、最后才 round**（避免中间舍入误差）→ 交叉校验时**不得**用「先 round 的 atr14 × 倍数」反推止损价；
5. **交叉校验源**：三市场 `stock_quote.py --momentum` 输出 `atr14` 字段（P1-9 已交付），可用于**独立复核** `stop_price()` 返回的 `atr14`；两者一致性容差与不一致处置见 §3.3；
6. **数据不足**（有效 TR 样本 < 14+1 根 K 线）→ `atr14` / `stop_price` / `stop_pct` 均为 `None` → 按 §3.3 降级为「ATR 未取得，回退 8%~10% 硬止损口径」并标注。
7. **反推误差实测（2026-09-17）**：以 T1 夹具序列（`atr14` = 2.77、买入价 100.00）为例，`round(atr14, 2) × 2 ÷ 买入价` 反推得 **5.54%**，工具 `stop_price(..., multiplier=2.0)["stop_pct"]` 给 **5.53%**（对应止损价 94.47）→ **波动刻度 `k` 一律直接读工具 `stop_pct`，禁止反推**。

### 3.3 降级与失败处置

| 情形 | 处置 |
| --- | --- |
| **无买入价** | **跳过二级**（硬止损与 ATR 均不可算），标记「数据不足」；其余四级与补充机制照常 |
| **无买入日期** | **跳过时间止损**子项，标记「数据不足」；其余照常 |
| **无 `--final-position`** | **无法判「建仓初期」** → 按最保守口径（**视为建仓初期**）执行 8%~10% 硬止损，并在报告中显式标注「最终仓位缺失，已按最保守口径假定建仓初期」 |
| **无买入日期且无最终仓位** | 二级与时间止损跳过；报告须在结论摘要中标注**两级不可判** |
| **无论文（`-garp-thesis.md`）** | 仅执行 一级 / 四级 / 五级；二级 / 三级 / 补充机制跳过并标「数据不足」（沿用骨架构型，但**四级/五级仍需输入**） |
| **ATR 数据不足**（有效 TR < 14+1 根） | `stop_price()` 返回 `None` → **回退 8%~10% 硬止损口径**并标注「ATR 未取得」；**不得**用其他窗口近似 |
| **`stop_price()` 的 `atr14` 与 `stock_quote --momentum` 的 `atr14` 不一致** | 以 **`stop_price()` 为准**（本技能核心工具，且其为全精度计算链）；差异须在报告中**并列留痕**并标注「交叉校验不一致，误差 X%」；**不得**静默取其一 |
| **`adjusted-peg` / 估值档位未取得** | 五级**降级为「仅市场情绪信号判定」**并标注「估值档位未取得」；**不得**用历史增速替代后充当已校准档位（与 P4-5 `GV-2` 同源原则） |
| **治理检索无结果** | 标「**未发现证据**」而**非**「无风险」；一级结论须写「基于现有检索未触发」 |
| **工具报错 / 超时** | 记录失败命令与错误原文，**不得以估算值代替**，降级为「该工具未取得」并标注 |
| **候选替换标的证据不足**（性价比替换） | 判「**未判定**」，**不执行**替换 |

### 3.4 风控硬编码 `GX-*`（全新编号，`GX-1`~`GX-15`；`GX-15` 为**交付期口径补丁**新增，见 §9.0.1）

| **GX-5** | **ATR 止损价必须调工具** | 一律调 `momentum.stop_price()`，**禁止心算**；报告须贴原始输出 |
| **GX-6** | **补充机制不得升格为优先级** | 时间止损 / 性价比替换与五级**并列**，不得覆盖已命中级别 |
| **GX-7** | **六维清单须逐维度留痕** | 6 维度逐条给证据与来源；未取证标「未判定」；禁止一句话概括 |
| **GX-8** | **永久性衰退立即清仓** | 不受盈亏、估值、趋势约束；与一级同为准出动作 |
| **GX-9** | **估值数值只引用不重算** | 档位取 P4-5 结论；本技能不重算 PEG / EV-Sales / DCF |
| **GX-10** | **只出动作方向与级别，不出仓位数值** | 报告**不得出现**「目标仓位 X%」「减至 X%」（观察仓口径除外，见 §9.G） |
| **GX-11** | **技术面不单独成层** | 技术面仅作四级辅助确认；纯技术体检归 `trend-momentum-scan` |
| **GX-12** | **两个「底仓」语义不得混用** | 单只标的最终仓位 50% ≠ 组合股票仓位 60%~80%；报告须显式声明 |
| **GX-13** | **检查日期与数据截止日强制标注** | 持仓、价格、财报、情绪均为时变项，结论仅对截止日有效 |
| **GX-14** | **不做买入决策、不做组合裁决** | 边界声明；越界即违规 |
| **GX-15** | **低波动股不得使用 ATR** | 波动刻度 `k` < 8% → 一律 **8%~10% 硬止损**（底仓路径下亦然）；阈值为**本技能操作化刻度**（框架行 472 明示规则的操作化落地，见 §2.5 / §9.0.1） |

## 9. 开工门禁待确认点（A~G）

> 以下 **7 项**为**开工前必须确认**的关键设计决策；**未确认前不进入开发**。每项给出推荐项与理由。确认后在本节 §9.0 回填「确认结论表」。

### §9.A `exit-signal` / `valuation-thermometer` 的处理（**口径隔离张力**）

**问题**：详细计划 §7.1 第 4 条明确「技能内引用其他技能时，**只指向 `garp-*` 与复用 2 技能**（`qoq-accelerator`、`trend-momentum-scan`），**不引用 1~3 年 / 10 年链技能**」；但 §7.3 P4-6 定义（行 488）与总计划行 146/172 却写「引用 `exit-signal`（P0~P5 数值映射为五级）、`valuation-thermometer`（数值）」——**二者均为中期链技能**，构成**计划内部张力**。

- **推荐 A-1（推荐）**：**`exit-signal` 与 `valuation-thermometer` 仅作开发期骨架对照，运行时零引用**：
  1. `exit-signal` 的 P0~P5 → 五级的映射关系只在**开发期对照表**（§4.4）中呈现，**`SKILL.md` / `README.md` 正文不出现** `exit-signal` 字样与 `P0`/`P5` 编号；
  2. 五级的**估值输入改引 `garp-valuation`（P4-5，已交付）+ `financial_rigor.py` 直算**（调整后 PEG），替代原计划的 `valuation-thermometer`；
  3. 总计划行 172「exit-signal 数值引用」解释为「**数值映射关系对照**」而非运行时调用；该解释须在《口径隔离声明》中显式留痕。
- 备选 A-2：**保留运行时引用**（在 `SKILL.md` 中显式列出 `exit-signal` 作为「P0~P5 → 五级映射来源」）——**违反 §7.1 第 4 条**，须同步修订 §7.1 或 §7.3。
- 备选 A-3：**折中**——`SKILL.md` 仅保留一句「本技能五级与中期链六级存在映射关系（不引用其口径）」，不列具体编号。

### §9.B 「时间止损」与「性价比替换」的层级归属

**问题**：中期链 `exit-signal` 把「时间止损」**并入 P2**（逻辑止损子项 B），把「性价比替换」设为 **P5 独立层级**；而框架行 502 与行 798 **两处**均写明二者属「**补充机制（不占优先级，兜底/优化动作）**」。

- **推荐 B-1（推荐）**：**严格按框架**——五级之后设**独立「补充机制」段**，两项与五级**并列检查**（仅在五级**全不触发**时执行），**不并入**三级、**不设为**第六级；`SKILL.md` 须显式写明「与中期链把时间止损并入 P2 的做法**结构性不同**」的**理由**（框架行 502 的三处独立声明）。
- 备选 B-2：沿用中期链做法——时间止损并入三级、性价比替换设为第六级（**直接违反框架行 502，不推荐**）。
- 备选 B-3：五级 + 补充机制并列呈现，但补充机制**永不参与**结论收口（仅作提示）——与框架行 504「减仓至观察仓或替换」的动作性表述不符。

### §9.C ATR 止损价的调用形态（`momentum.py` 无 CLI）

**问题**：`momentum.py` 经 Grep 核实**无 CLI / 无 argparse / 无 `__main__`**（P1-8 交付物为纯计算模块），而技能层需要「可被 LLM 稳定调用且禁止心算」的形态。

- **推荐 C-1（推荐）**：**技能层内联 Python 模块调用** `tools.common.momentum.stop_price(...)`，并把**原始输出三字段**（`atr14` / `stop_price` / `stop_pct`）在报告中**逐字贴出**；同时用三市场 `stock_quote.py --momentum` 的 `atr14` 做**独立交叉校验**（不一致时以 `stop_price()` 为准并并列留痕，见 §3.3）。
- 备选 C-2：为 `momentum.py` **新增 CLI 包装**（如 `--stop-price`）——**超出 P4-6 范围**，须另立工具子任务，**违反 §7.3「不建独立聚合器」精神**。
- 备选 C-3：仅在技能中给出**公式与人工取数步骤**（不调工具）——**违反验收要点「调用 `momentum.stop_price` 而非心算」**。

### §9.D ATR 与 8%~10% 硬止损的适用边界固化

**问题**：框架对 ATR 的适用条件有三处限定（行 469「仅在底仓已建立且逻辑已验证后使用」、行 471「建仓初期一律按 8%~10%、不用 ATR」、行 471/536「ATR 幅度由 20% 底仓容忍度封顶」），需固化为**可机械执行的条件树**。

- **推荐 D-1（推荐）**：**严格按框架三处限定固化**为条件树：① 建仓初期（持仓 <最终仓位 50% **或** ≥50% 但逻辑未验证）→ **一律 8%~10% 硬止损，禁用 ATR**；② 底仓已建立且逻辑已验证 → 用 2~3×ATR 动态跟踪；③ 止损幅度 **>20% 时取 20%**（封顶）；④ 逻辑被证伪 → 立即清仓（**不适用**任何止损档）。报告中须留痕「所处分支 + 封顶是否生效」。
- 备选 D-2：**所有阶段**都用 ATR，仅在建仓初期额外叠加 8%~10% 双保险——**违反行 471「一律按 8%~10%、不用 ATR」**。
- 备选 D-3：ATR **不封顶**，允许幅度 >20%（理由是「高波动股需要更宽空间」）——**违反行 471/536**。

### §9.E 与 `garp-portfolio-review`（P4-8）的仓位量切割

**问题**：框架第三部分·二（行 456~471）含完整仓位管理规则（单只 10/15/20%、行业 40%、相关性 <0.5、流动性 >1 亿、再平衡 ±5%），而详细计划 §7.3 P4-8 明确把这些数值归 `garp-portfolio-review`；本技能若输出仓位数值将造成**双源冲突**。

- **推荐 E-1（推荐）**：本技能**只输出「动作方向与级别」**（清仓 / 止损离场 / 减仓 / 降观察仓 / 调仓 / 持有 / 加仓），**不输出**「目标仓位 X%」「减至 X%」；底仓 / 机动仓的**数量区间仅作语义引用**（§2.7 注）；所有仓位裁决**转接** P4-8（`GX-10`）。
- 备选 E-2：本技能输出**建议仓位数值**并与 P4-8 对齐——**双源维护成本高且易冲突**，且违反 §7.3 分工。
- 备选 E-3：本技能**完全不提**底仓 / 机动仓，只出「全仓级别动作」——**与框架行 494/499「减机动仓」「底仓不动」的动作粒度不符**。

### §9.F 诚信否决的触发口径来源

**问题**：一级「诚信否决」的事实来源有三个可能通道：① `garp-management`（P4-4）的 `integrity_veto` 闸门；② `garp-geo-policy`（P4-1）的「回避」前置结论；③ 本技能**新增**的外部事实检索（新发生的立案 / 造假实锤 / 失信暴露）。若三者关系不清，会出现**重复判定**或**语境混用**（框架行 663 已明确两类「否决」语境不同）。

- **推荐 F-1（推荐）**：**以转接为主、净新增判定为辅**：
  1. `garp-management` 的 `integrity_veto=true`（且其 A-1 口径覆盖后仍成立）→ **直接转接**为一级触发；
  2. `garp-geo-policy` 的「回避」属**买入前**闸门 → **不进入**五级表（框架行 663），仅在报告中作为**语境提示**出现；
  3. 本技能**净新增**判定**仅限持仓后新发生**的外部事实（立案 / 造假实锤 / 失信暴露），须附**可核查证据链**（来源 + 日期 + 原文要点）。
- 备选 F-2：**全部自判**（不转接，重新执行治理检索）——**重复取证、且与 P4-4 结论可能冲突**。
- 备选 F-3：**只转接、不做净新增**——持仓后新发生的立案将无法触发一级，**存在重大漏判风险**。

### §9.G 「观察仓」的数值口径（框架未定义）

**问题**：框架行 504 / 行 800 只写「**减仓至观察仓**」，**未给数值定义**；而本技能 §2.2 的时间止损与三级第④条（评分 <10）都要输出「降观察仓」动作，需要一个可执行口径。

- **推荐 G-1（推荐）**：沿用参考文献骨架口径「**原仓位的 30%~50%**」，并在报告中**显式标注**「该数值为文献骨架口径、**框架未显式定义**」；同时明确该数值**不是目标仓位上限**（不越界至 P4-8：报告只写「减至原仓位的 30%~50%」，不写「占组合 X%」）。
- 备选 G-2：**只给动作不给数值**（「降为观察仓，具体幅度由 P4-8 裁决」）——最保守、零越界，但**可执行性弱**。
- 备选 G-3：定义为「**单只占组合 ≤5%**」——**越界至 P4-8 的仓位裁决**，且框架未支持该数值。

**已可直接采用的默认项（无需门禁）**：

1. **报告路径**：`reports/{标的}/{标的}-garp-exit-{YYYYMMDD}.md`（与 P4-4 / P4-5 同构；不新建 `reports/exit-signals/`）；
2. **风控前缀**：`GX-*`（`GX-1`~`GX-15`；已核全技能目录零占用；`GX-15` 为**交付期新增**，见 §9.0.1）；
3. **论文文件**：`reports/{标的}/{标的}-garp-thesis.md`（P4-7 声明式）；
4. **检查频率**：`daily` / `quarterly` 双模式（框架行 806「每季度复盘」）；
5. **命令名**：`/garp-exit {标的}`（技能名 `garp-exit`）。
